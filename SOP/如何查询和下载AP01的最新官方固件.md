# 如何查询和下载 AP01 的最新官方固件


## 1. 进入项目

执行前提：执行任务的 AI 已处于本项目仓库根目录。

确认命令：

```bash
pwd
```

成功条件：输出的是本项目仓库根目录。不要把该输出复制进本文。

失败处理：如果不在本项目仓库根目录，停止。

准备项目内运行环境：

```bash
test -d .venv || python3 -m venv .venv
.venv/bin/python -m pip install -r features/official_firmware_source/requirements.txt
```

成功条件：安装命令正常结束。所有后续 Python 命令都必须使用 `.venv/bin/python`。

失败处理：报告创建或安装失败的原始错误，不得改用项目目录外的证书文件。

下一步：进入第 2 步。

## 2. 准备登录态

执行目标：由 AI 自动复用已有登录态；没有可用登录态时，自动生成并展示二维码。

命令：

```bash
.venv/bin/python app/ap01_official_firmware.py login \
  --env-file env/mi-cloud.env \
  --qr-output artifacts/official-firmware/xiaomi-login-qr.png
```

命令返回“已有米家登录态可用”时，直接进入第 3 步。

命令输出以下内容时，AI 必须继续执行，不得停止并要求用户填写字段：

```text
二维码已生成：artifacts/official-firmware/xiaomi-login-qr.png
```

AI 接下来的动作：

1. 立即打开、向用户展示，并将 `artifacts/official-firmware/xiaomi-login-qr.png` 作为一条单独的聊天正文图片直接发送；不得只输出可折叠的工具记录。
2. 保持登录命令继续运行，等待用户用拥有目标 AP01 的米家账号扫码并在手机上确认。
3. 用户确认后继续等待命令结束，不要求用户回复“已填写”，不要求用户手工提供任何登录字段。
4. 命令确认账号内存在 AP01 后，会自动创建或更新 `env/mi-cloud.env`。

成功输出必须是以下两种之一：

- `已有米家登录态可用`；
- `扫码登录完成`。

失败处理：

- 二维码超时：重新执行本步骤，展示新二维码。
- 扫码账号内没有 AP01：停止，并要求用户改用拥有目标 AP01 的米家账号重新扫码。
- 网络、证书或小米登录接口失败：停止并报告原始错误。
- 不得读取、复制或引用项目目录外的凭据文件。

下一步：进入第 3 步。

## 3. 查询当前官方固件

输入：`env/mi-cloud.env`。

命令：

```bash
.venv/bin/python app/ap01_official_firmware.py info --env-file env/mi-cloud.env
```

成功输出应包含：

```text
"result": "小米云官方固件信息查询完成"
```

同时记录以下字段：

- `model`：设备型号，必须是 `njcuk.enstor.ap01`。
- `version`：本次云端返回的最新固件版本，不与历史版本比较。
- `md5`：本次云端返回的文件核对值，供下载后比较。
- `upload_time`：小米云返回的上传时间。
- `timeout`：小米云返回的下载超时时间。

失败处理：

- 提示没有米家登录态：回到第 2 步。
- 出现 `CERTIFICATE_VERIFY_FAILED`：表示 Python 没能确认网站证书可信；停止，不得改用目录外证书文件绕过。
- `model` 不是 `njcuk.enstor.ap01`：停止。
- `version` 为空或不能安全用于文件名：停止。
- `md5` 不是 32 位十六进制值：停止。

下一步：

- 只查询最新版本：进入第 6 步记录结果后结束。
- 需要下载官方固件：进入第 4 步。

## 4. 下载官方固件

输入：第 3 步查询成功的小米云结果。

正式下载命令：

```bash
.venv/bin/python app/ap01_official_firmware.py download --env-file env/mi-cloud.env
```

命令会重新查询云端当前版本，并自动生成输出文件：

```text
artifacts/firmware/original/ap01-<云端返回的 version>.bin
```

成功输出应包含：

```text
"result": "官方原版固件已固定"
```

失败处理：

- 云端型号不是 AP01：停止。
- 云端版本不能安全生成文件名：停止。
- 云端 MD5 格式错误：停止。
- 云端下载地址不是 HTTPS：停止。
- 下载文件 MD5 不一致：停止。
- 目标文件已存在但仍可写：停止。

下一步：进入第 5 步。

## 5. 核对下载结果

输入：第 3 步记录的查询结果和第 4 步命令输出。

必须同时满足：

- `cloud.model` 是 `njcuk.enstor.ap01`。
- `cloud.version` 是下载命令重新查询到的版本。
- `path` 是 `artifacts/firmware/original/ap01-<cloud.version>.bin`。
- 实际 `md5` 等于同一次下载输出中的 `cloud.md5`。
- `size` 大于 0。
- `sha256` 是 64 位十六进制值。
- `read_only` 是 `true`。

失败处理：任一项不满足就停止，不得继续制作或刷入。

完成限制：即使全部满足，也只说明最新官方固件已下载且与云端 MD5 一致。若该版本尚未进入项目固定基线，不得用它制作或刷入。

下一步：进入第 6 步。

## 6. 记录结果

只查询时，记录：

```text
查询时间：
model：
version：
md5：
upload_time：
timeout：
结论：
```

下载后，记录：

```text
下载时间：
输出文件：
权限：
文件大小：
MD5：
SHA-256：
结论：
```

结论只能写以下三种之一：

- `查询成功，未下载。`
- `查询和下载成功，文件与本次云端 MD5 一致并已只读保存；未作为制作基线。`
- `已停止，原因：<填写第几步失败和失败原因>。`

## 停止条件清单

遇到以下任一情况必须停止：

- 文档、命令或记录里需要写入以 `/` 开头的绝对路径；
- 流程需要读取本项目目录以外的文件；
- 第 2 步无法生成二维码、扫码超时或账号内没有 AP01；
- 小米云查询失败；
- 出现证书错误；
- 云端型号不是 `njcuk.enstor.ap01`；
- 云端版本为空或不能安全生成文件名；
- 云端 MD5 格式错误；
- 云端下载地址不是 HTTPS；
- 下载文件为空或实际 MD5 与本次云端 MD5 不匹配；
- 保存后重新读取的大小、MD5、SHA-256 或只读权限不匹配；
- 目标文件已存在但仍可写。
