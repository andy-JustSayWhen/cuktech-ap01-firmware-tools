# 如何部署服务端

本文只说明 AP01 AGENTS 看板服务怎样部署到**当前这台电脑**。它与刷机解耦：刷机时只部署执行刷机的当前电脑；固件地址表中的其他电脑可在需要提供备用服务时，分别在那些电脑上执行本章对应的一键程序。其他电脑是否部署，不影响已完成的刷机验收。

部署目录是仓库外的独立文件夹，里面保存服务程序、字体、缓存和输出文件。删除项目仓库后，已部署的服务仍能运行；用户的 Codex 登录状态保留在用户目录，不被复制。

技术实现见 [`看板服务一键部署`](../reference/DESIGN/看板服务一键部署.md)。

## 1. 前提

- 当前电脑已经安装 Python 3.12 或更高版本，并已安装 Pillow（Python 的图像处理库）。
- 当前电脑已经登录 Codex，且固件地址表中已包含这台电脑的局域网地址。
- 从项目仓库根目录执行对应命令；脚本不会上传固件或修改设备。

## 2. Windows 一键部署

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\deploy-agents-dashboard.ps1 -Start
```

默认部署到当前用户的应用数据目录。需要指定目录、端口或刷新周期时：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\deploy-agents-dashboard.ps1 `
  -TargetDir "<部署路径>" -Port 18765 -IntervalSeconds 300 -Start
```

脚本复制服务文件，创建隐藏启动脚本，登记当前用户登录后自动启动，并立即检查本机服务状态。

## 3. macOS 一键部署

```bash
chmod +x tools/deploy-agents-dashboard.sh
tools/deploy-agents-dashboard.sh --start
```

默认部署到当前用户的应用支持目录。需要指定目录、端口或刷新周期时：

```bash
tools/deploy-agents-dashboard.sh \
  --target-dir "<部署路径>" --port 18765 --interval-seconds 300 --start
```

脚本复制服务文件，生成并检查登录自启动文件，登记服务，并立即检查本机服务状态。

## 4. 怎样算完成

满足以下全部条件才算当前电脑部署完成：

1. 一键程序显示本机健康检查通过；
2. 部署目录包含 `features/agents_dashboard`、`fonts`、`service-output` 和 `service-cache`；
3. 登录自启动已登记，重启电脑并登录后本机服务仍可访问；
4. 看板设备能在下一次取包周期获得完整四页数据。

目标目录已有服务或端口已被其他程序占用时，脚本会停止，不覆盖现有服务。先确认旧服务用途，再选择其他目录或停止旧服务后重试。
