# AP01 官方固件分析

## 1. 文档目的

本组文档记录从酷态科 AP01 官方固件中直接取得的硬件和软件证据，为需求、技术设计、
固件制作、刷机保护和验收提供统一基线。

当前基线为 `1.0.2_0031`。2026-07-28 已再次向小米云确认最新版本与固定原厂文件校验值
一致；原厂文件仍使用仓库外只读副本。

## 2. 结论总览

| 范畴 | 固件直接证明的事实 |
| --- | --- |
| 设备身份 | 型号字符串为 `njcuk.enstor.ap01`，固件版本为 `1.0.2_0031` |
| 处理器程序 | 主程序为 32 位 RISC-V（芯片执行指令的一套规则）指令，工程名含 `AP01_BL618`，驱动路径含 `bl616` |
| 系统软件 | 使用 NuttX（设备里的小型实时操作系统）、LVGL（绘制小屏界面的图形程序库）、libuv（处理异步任务的程序库）和 mbedTLS（实现加密通信的程序库） |
| 屏幕 | 画布和主要页面资源为 320×240，使用 `jd9853` 屏幕控制器和帧缓冲设备 `/dev/fb0` |
| 输入 | 唯一事实原文见 [`原厂各页面物理旋钮交互实现`](原厂各页面物理旋钮交互实现.md) |
| 联网 | 包含 Wi-Fi（无线局域网）、BLE（低功耗蓝牙）、米家配网、米家设备通信、天气服务和在线更新 |
| 底座通信 | 通过触点侧的串口、模数转换采样和协议管理读取端口、功率、温度、电池与充电协议数据 |
| 存储 | 包含闪存分区、只读文件系统、LittleFS（面向小型设备闪存的文件系统）、配置文件和资源分区 |
| 更新恢复 | 包含两个固件槽、当前槽与更新槽属性、在线更新、恢复记录和恢复校验代码 |
| 图形资源 | 固件内找到 199 张可解码 PNG（静态图片格式）和 10 个可解码 GIF（动图格式） |
| 原厂一级页 | 时钟、功率、天气、日历、设置、虚拟形象 |

## 3. 必须区分的边界

- 固件证明主程序工程使用 `BL618` 标识并调用 `BL616` 系列驱动；固件本身不能证明实体芯片
  表面的完整丝印。
- 固件证明包含双槽和恢复代码；本项目尚未在指定设备上完成官方固件回退实测，因此不能写
  “一键回退已经可靠”。
- 固件证明支持 PNG 和 GIF 解码；参考项目的实时画面加载功能目前只完成 GIF89a、
  320×240、至少两帧的真机验证。
- 原厂内置 GIF 最大达到 569,645 字节，因此 256KB 不是设备的全局文件上限。
  256KB 是参考项目当前实时画面传输与内存槽实现的限制。
- 固件包含 BLE 配网和通信代码；未在本次固件中发现通过蓝牙传输第三方固件或实时画面的
  实现。
- 固件包含底座触点通信和 `UsbIface` 模块；该名称表示底座向屏幕报告充电接口数据，
  不能据此认定 AP01 屏幕具有可用于刷机的外露 USB 接口。
- 原厂设置持久化字段中没有一级页面显隐配置。页面默认值、允许关闭的页面、全部关闭行为、
  恢复行为属于新产品规则，必须在需求文档中由用户确认。

## 5. 维护规则

1. 每次制作前重新查询小米云最新版本。
2. 版本、字节数或官方文件指纹任一变化，停止复用本文地址和结论。
3. 新结论必须同时写明证据位置、复查方法和能力边界。
4. 原厂固件和提取资源不得提交到代码仓库。
5. 真机验证结果写入新的案例文档，并从本页链接。
6. 设计引用原厂入口前，必须从实际注册回调或实际调用者逐分支追踪；读写不同字段的相似入口
   在证明等价前按不同接口处理。
7. 原厂字段被初始化为零不等于该字段或其中部分位可复用；只有完整读写引用和位级语义都已
   证明时才能写入，否则使用独立状态。
8. 自动测试只能证明实现符合当前设计。新的原厂直接证据与设计冲突时，相关设计、测试和冻结
   成品同时失效，修订完成前不得安装。
