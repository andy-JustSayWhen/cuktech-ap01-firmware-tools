# 2026-07-27 AP01 系统设置菜单首尾循环静态定位

返回主文档：[`AP01 官方固件分析`](../AP01-官方固件分析.md)

## 1. 范围与能力边界

本记录只分析官方 `1.0.2_0031` 固件中的系统设置列表、左右旋转处理和最小等长修改位置。
原厂基线身份见 [`固件制作规范`](../../../reference/固件制作规范.md) 第 4 节。

本次取得的是静态证据，不是真机运行结果。没有生成优化固件，没有上传文件，也没有向设备
发送仅下载或安装命令。

## 2. 复查方法

1. 校验原厂文件的字节数、两个完整文件指纹和文件尾恢复校验，固定值只见
   [`固件制作规范`](../../../reference/固件制作规范.md) 第 4 节；
2. 从文件偏移 `0x1000` 起按主程序指令反汇编；
3. 对设置列表创建、项目数量读取、项目查找、左右事件和选中切换的调用关系交叉复查；
4. 用 [`requirements.md`](../../../reference/requirements.md) 中固定版本的汇编与链接工具生成
   替换字节；
5. 把生成结果再次反汇编，核对每个跳转目标、调用目标、区间长度和原字节断言；
6. 核对新增执行区前后函数边界、完整零填充范围、全固件直接跳转目标和地址指针。

运行地址等于文件偏移加 `0x9ffff000`。该关系只适用于本记录的官方版本。

## 3. 原厂调用关系

| 事实 | 文件位置或运行位置 | 直接证据 |
| --- | --- | --- |
| 设置列表创建 | 运行地址 `0xa01988d4` | 创建循环固定处理 7 个原厂设置项目 |
| 左右事件处理函数 | 文件 `0x0f9096`，运行地址 `0xa00f8096` | 事件类型为 `17` 时读取按键；右为 `19`，左为 `20` |
| 系统设置列表类型 | 左右处理函数内 | 对象类型字节等于 `26` 时进入系统设置列表分支 |
| 当次项目数量 | 运行地址 `0xa00c5fe4` | 左右分支均在处理选择前调用并保存返回值 |
| 按序号取得列表对象 | 运行地址 `0xa00c5d84` | 循环查找类型为 `26` 的列表对象 |
| 选择切换 | 运行地址 `0xa00f3d5a` | 原厂相邻项目切换均传入列表对象、原序号和新序号 |
| 当前项目状态 | 列表对象数据偏移 `+1` | 值 `48` 至 `54` 分别对应序号 `0` 至 `6` |

右旋原厂逻辑依次处理 `0→1` 至 `5→6`，当前序号为 `6` 时返回。左旋原厂逻辑依次处理
`6→5` 至 `1→0`，当前序号为 `0` 时返回。部分内部相邻切换还会调用运行地址
`0xa00c6dfe` 调整原厂列表位置，因此修改方案保留全部内部相邻切换，只接管当次有效首尾。

## 4. 新执行区证据

文件 `0x01c008..0x01c100`、运行地址 `0xa001b008..0xa001b100` 是连续 248 字节零填充区：

- 前一条指令位于运行地址 `0xa001b006`，是函数返回；
- 后一函数从运行地址 `0xa001b100` 开始；
- 对完整原厂文件反汇编后，没有任何直接跳转目标落入该零填充区；
- 对完整原厂文件逐字节检查四字节地址值后，没有指向该区偶数地址的指针；
- 参考项目已经把文件 `0x01c008..0x01c010` 作为近距离跳转区，并在写入前断言 8 字节全零；
- 左右两个状态读取位置与该区互相跳转均处于处理器单条跳转允许范围内。

本功能只使用文件 `0x01c008..0x01c07e` 的前 118 字节。文件
`0x01c07e..0x01c100` 的后 130 字节保持全零。原厂版本、完整文件指纹、前后边界或零填充
任一不匹配时，清单生成必须停止。

## 6. 新控制流

右旋每次从原厂列表取得实际项目数：

1. 项目数小于 2 时直接返回；
2. 当前序号越过当次项目数时直接返回；
3. 当前序号是当次最后一项时，把状态切换到 `48`，调用原厂选择切换执行
   `项目数减一→0`；
4. 其余有效序号回到原厂分支，保留原厂相邻切换和列表位置调整。

左旋每次执行对称检查：

1. 项目数小于 2 时直接返回；
2. 当前序号越过当次项目数时直接返回；
3. 当前序号为 `0` 时，把状态切换到 `项目数加 47`，调用原厂选择切换执行
   `0→项目数减一`；
4. 其余有效序号回到原厂分支。

官方创建循环最多产生 7 项，因此本版本的有效项目数范围为 `0..7`。方案不把最后一项写死
为序号 `6`，每次事件都使用原厂数量读取结果。

## 7. 原厂日志保持

下列原厂日志代码区全部位于修改清单之外，并要求候选固件与原厂逐字节一致：

- 右旋通用日志：`0x0f912c..0x0f914e`；
- 右旋系统设置日志：`0x0f9172..0x0f918c`；
- 左旋通用日志：`0x0f96f8..0x0f971a`；
- 左旋系统设置日志：`0x0f973e..0x0f9758`。

其中通用日志正文
`ui setting dtl custom handler, key right`（系统设置详情处理函数收到右旋）和
`ui setting dtl custom handler, key left`（系统设置详情处理函数收到左旋）保持原厂字节。
设置功能所需的项目数量读取、对象查找、内部相邻切换和列表位置调整也全部保留。

## 8. 修改边界

- 只修改上述 3 个主程序区间；
- 新增 118 字节版本限定处理程序，不修改图形资源、持久化文件或运行时内存分配；
- 不修改文件头、文件尾恢复记录、启动、分区、槽、联网、米家通信和官方更新路径；
- 固件总长度保持不变，构建时仍需重算文件尾恢复校验；
- 原厂左右旋转日志、其他对象类型的寄存器初始化和类型专用处理保持原厂字节；
- 静态检查不能证明界面动画、声音、焦点和长时间运行结果，真机安装仍受恢复门禁阻塞。

## 9. 实现与静态验证

实现位于 `features/settings_menu_wrap/`：

- 汇编源文件和链接边界断言固定新增处理程序、两个挂接点、目标地址和区间长度；
- 清单生成器要求真实原厂文件只读、完整零填充区、前后边界、全部旧字节、工具版本和汇编
  结果逐项一致；
- 测试必须把 4 个日志代码区与候选字节逐字节比较；
- 清单状态固定为等待用户批准，没有把批准状态暴露为命令参数；
- 离线制作门禁必须确认待批准清单不能生成优化固件。

实现提交、测试数量、清单结果和门禁结果在代码完成后写入本节。

## 10. 当前结论

这 3 个区间已具备版本、位置、旧字节、替换来源、调用目标、日志保持和失败返回路径，可以
进入实现与修改清单评审。只有用户明确批准这 3 个区间后，清单状态才能改为允许离线构建；
批准前制作工具必须
拒绝生成 `ap01-1.0.2_0031-opt.bin`。
