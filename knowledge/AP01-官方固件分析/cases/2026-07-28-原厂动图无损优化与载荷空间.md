# 2026-07-28 AP01 原厂动图无损优化与载荷空间

返回主文档：[`AP01 官方固件分析`](../AP01-官方固件分析.md)

## 1. 对象与目标

本次针对原厂固件中数据起点为 `0x57e830` 的第 9 个 GIF 动图执行无损结构优化。该动图为
`320×240`、20 帧，原始数据长度为 502,081 字节。

目标不是删除或替换原厂画面，而是在设备继续解码相同画面的前提下，移除动图编码中的冗余，
把原资源槽尾部变成后续设备端载荷候选空间。

## 2. 固定工具与结果

| 项目 | 固定值 |
| --- | --- |
| 工具 | Gifsicle 1.96 |
| 参数 | `-O3` |
| 原数据起点 | `0x57e830` |
| 原数据长度 | 502,081 |
| 原数据 SHA-256 | `053b16cc10cff7a52544ab0c495f561b10727f718d0ce6a3efa2f034cda3a9e2` |
| 优化后长度 | 491,894 |
| 优化后 SHA-256 | `6f09647a3d97baeb10b78f9f08d30cd03e77b437dfe14a17a42489952e2e8b99` |
| 减少字节数 | 10,187 |
| 16 字节对齐载荷起点 | `0x5f69b0` |
| 下一资源描述起点 | `0x5f9174` |
| 连续候选容量 | 10,180 |

优化时只把当前动图描述中的数据长度改为 491,894，数据指针保持不变，固件总长度不变。

## 3. 无损等价检查

原动图和优化后动图必须分别完整解码，并逐项满足：

1. 画面尺寸均为 `320×240`；
2. 帧数均为 20；
3. 循环参数一致；
4. 每帧时长一致；
5. 每帧清除方式一致；
6. 每帧合成后的全部 RGBA 像素逐字节一致。

当前固定结果已通过上述六项检查。其他原厂动图即使视觉抽查相同，也不得共享本结论；只有
同样通过全部字段和逐帧像素检查的资源才能形成新的候选空间。

## 4. 边界

本记录证明 `0x5f69b0` 至 `0x5f9174` 可以从该动图的数据范围中释放出来，不证明放入其中的
任意程序都能正确执行。完整载荷仍必须完成：

- 链接后总量不超过 10,180 字节；
- 所有符号和只读数据位于该区间；
- 没有未处理的重定位；
- 从一级页面挂接点可到达；
- 原动图在固件中的描述、指针、帧等价和下一资源描述均保持有效；
- 真机安装前继续受恢复门禁约束。
