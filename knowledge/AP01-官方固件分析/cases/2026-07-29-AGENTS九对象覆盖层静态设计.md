# 2026-07-29 AGENTS 九对象覆盖层静态设计

## 1. 目的

为 AGENTS 看板保留独立一级导航位置，同时不改变原厂一级窗口容器的九个直接子对象。

## 2. 直接证据

1. 原厂萌宠根对象位于一级窗口序号 7，原厂米家详情位于序号 8；
2. 参考项目已经通过序号 7 取得萌宠根对象，并沿对象关系取得其图片控件；
3. 两份增加第十个一级直接子对象的观察成品均出现原厂确认操作回归；
4. 回刷 `opt-setting.bin` 后，用户确认原厂交互恢复正常。

## 3. 静态方案

AGENTS 根对象改为萌宠根对象的 320×240 子覆盖层。覆盖层初始横向坐标为 320，进入
AGENTS 虚拟导航状态时移到 0，离开时移回 320。萌宠原有对象、图片和状态不修改。

导航包装仅在覆盖层固定标记有效且虚拟显示状态开启时处理 AGENTS 事件；其他事件原样交回
原厂。功率页左旋和萌宠页右旋进入虚拟状态，虚拟状态左旋回到萌宠，右旋进入功率。

## 4. 失败关闭边界

- 找不到萌宠根对象时不创建覆盖层；
- 创建、状态申请或图片创建失败时清理已创建对象；
- 找不到覆盖层或状态标记不符时不接管任何原厂事件；
- 不读取或改写一级窗口容器偏移 52；
- 不在载荷中保存可写全局状态。

## 7. 自动安装结果

1. 设备接受更新，下载进度达到 100，并报告安装完成；
2. 运行计时由 2203 秒归零到 8 秒；
3. 设备重新上线，型号和版本保持原值；
4. 本机数据服务保持健康，无刷新错误；
5. 设备重启后主动请求新结果包，服务请求数由 3 增至 4。

用户已确认 AGENTS 看板画面显示；随后原厂“返回”确认失败，结果见第 8 节。

## 8. 物理失败与回刷

用户在系统设置菜单确认“返回”时，设备直接重启。该回归发生在一级窗口仍保持九个直接
子对象的情况下，说明萌宠根对象内部新增覆盖层仍会影响原厂确认路径。

本成品禁止再次安装。设备随后回刷 SHA-256 为
`348d0843ac3f3f380eb155170c4104fd8467a018ddfd13670d67be998f269dc1` 的
`opt-setting.bin`；下载进度达到 100，设备报告安装完成，运行计时归零到 10 秒并重新上线。

后续实现不得新增任何界面对象，只能复用原厂已有对象和状态。
