# 2026-07-29 功率页确认键重启回归定位

返回主文档：[`AP01 官方固件分析`](../AP01-官方固件分析.md)

技术修复只见
[`AP01 1.0.2_0031 优化固件 DESIGN`](../../../reference/DESIGN/AP01-1.0.2_0031-opt.bin.md)
第 6.1、10.12 节。

## 1. 真机现象与日志边界

原厂精确调用链观察成品安装后，其他已操作页面正常；在原厂功率一级页按下并松开旋钮后，
画面停止响应。小米云仍能联系设备，但运行计时已经重新从 55 秒开始并连续增长到 58 秒，
证明本次现象包含一次整机重启，不是 AGENTS 画面单独停止刷新。

本机数据服务在故障前后持续收到设备的 `/a` 请求，健康状态错误为空。当前没有已经验证的
串口或设备崩溃记录读取通道，因此没有程序异常地址、调用栈或复位原因原文；不得据此编造
具体异常指令。

## 2. 静态差异边界

原厂功率页确认分支位于原厂键值回调 `0xa00bbfee` 内。观察成品把一级窗口注册的回调地址
改为 AGENTS 包装入口。该入口对功率页确认键执行以下额外路径后才进入原厂回调：

1. 建立 64 字节栈；
2. 读取键值；
3. 读取原厂交互分派序号；
4. 恢复包装栈并跳入原厂回调。

原厂回调随后为功率详情路径建立 384 字节栈。反汇编证明功率页确认在包装中不读取萌宠状态
或 AGENTS 独立尾部，也不执行 AGENTS 数据源切换；因此当前直接证据把故障收敛到非萌宠
确认键仍经过包装入口这一差异，不能把故障归因于数据服务或 AGENTS 页面文件。

## 3. 修复约束

修正版在包装栈之前增加无栈入口。非序号 `7` 的确认键必须不修改栈、不调用函数、不写内存，
直接进入原厂回调；序号 `1`、`2`、`8` 的三种键值同样直接进入原厂回调。完整实现与构建
门禁只见 DESIGN 第 6.1、10.12 节。

## 4. 回刷结果

设备已回刷 SHA-256 为
`348d0843ac3f3f380eb155170c4104fd8467a018ddfd13670d67be998f269dc1` 的
`opt-setting.bin`。上传对象完整回读与本地文件逐字节一致；设备接受更新、完成安装，运行
计时由 262 秒归零到 9 秒并重新上线，更新状态回到空闲。

原厂精确调用链观察成品禁止再次安装。
