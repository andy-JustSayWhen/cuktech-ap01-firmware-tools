# 2026-07-29 新增对象与原厂确认回归

返回主文档：[`AP01 官方固件分析`](../AP01-官方固件分析.md)

## 1. 真机现象

- 一级页面和菜单左右旋转正常；
- 任意普通页面按下并松开旋钮都会进入时间设定；
- 在菜单中选择并确认“返回”会直接重启设备。

## 2. 直接证据

原厂一级回调 `0xa00bbfee` 在左旋、右旋和确认分支分别调用 `0xa00be388`。后者从传入
窗口容器偏移 `52` 读取原厂交互分派序号并返回，原厂回调据此选择页面专用交互或内部详情
交互。

新增一级对象和萌宠子对象的两份成品都会破坏原厂确认路径，因此这些对象修改继续禁止。
但零新增对象成品仍复现日历详情无法返回，证明“新增对象把最后有效序号改成 9”不是完整
根因，偏移 `52` 也不是最后有效序号。

当前能够直接确认的共同边界是一级键值回调被替换，以及包装入口错误使用偏移 `56` 的窗口
切换状态判断确认分支。日历回归根因只见
[`日历详情返回回归定位`](2026-07-29-日历详情返回回归定位.md)。

## 3. 修复约束

1. 不新增一级对象或萌宠子对象；
2. 通过 `0xa00be388` 读取原厂交互分派序号；
3. 交互分派序号不是 `7` 的确认键直接进入原厂回调；
4. 不改写偏移 `52`，不以偏移 `56` 代替确认分派；
5. 原厂内部详情的左右和确认全部由原厂回调处理。

## 4. 验收

- 功率、时间、日历、天气、设置和萌宠确认操作与原厂一致；
- 日历等原厂详情进入和返回正常；
- 菜单“返回”不触发重启；
- 一级页面和菜单左右旋转保持正常；
- AGENTS 概览、详情循环和详情返回正常；
- 设备完成安装、重启、重新上线和主动取包。

产品表现原文见 [`SPEC`](../../../reference/SPEC.md)，实现约束原文见
[`DESIGN`](../../../reference/DESIGN/AP01-1.0.2_0031-opt.bin.md) 第 6.1 节。
