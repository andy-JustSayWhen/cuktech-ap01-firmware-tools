# 2026-07-29 日历详情返回回归定位

## 1. 现象

AGENTS 四页、一级左右切换和 AGENTS 详情返回均可用，但原厂日历进入详情后，按下并松开
旋钮无法返回一级页面。

## 2. 差异边界

当时设备中的设置列表空挂接观察成品，相对已验收的 AGENTS 四页同步实验成品只修改：

- 文件偏移 `0x1999dc` 的四字节分支；
- 载荷末尾新增的 28 字节原厂等价分支；
- 文件尾恢复校验值。

这 36 个差异字节不覆盖一级键值包装、日历详情回调或页面注册载荷，因此空挂接不是直接
覆盖日历返回逻辑的修改。

## 3. 根因

原厂一级窗口依次创建功率主页、C1 条件页、C2 条件页、时间、日期、天气、设置、萌宠和
米家详情，米家详情固定为序号 8。原页面注册载荷先创建 AGENTS，再复现米家详情创建，导致
AGENTS 占用序号 8、米家详情移动到序号 9。

日历详情仍使用原厂内部对象序号。详情打开后，一级键值包装取得序号 8 的对象时读到了
AGENTS 状态标记，于是把确认键当作 AGENTS 详情操作消费，原厂日历返回回调没有收到该事件。

## 4. 修复约束

页面注册载荷必须：

1. 先复现原厂米家详情对象创建，使其保持序号 8；
2. 保存原厂米家详情对象；
3. 再创建 AGENTS，使其占用新增序号 9；
4. 最后仍把原厂米家详情对象作为原初始化调用的返回值；
5. 一级循环使用 `0、3、4、5、6、7、9`，跳过 C1、C2 和米家详情对象；
6. AGENTS 创建失败时仍返回已经创建的原厂米家详情对象。

## 5. 验收

- 日历进入详情后，按下并松开旋钮可返回日历一级页面；
- 原厂其他详情页保持原交互；
- 一级左右按功率、时间、日期、天气、设置、萌宠、AGENTS 的顺序首尾循环；
- AGENTS 概览、三个详情和详情返回均保持可用；
- 设备完成安装、启动、重新上线并继续主动获取四页数据。
