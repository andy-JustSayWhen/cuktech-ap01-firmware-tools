# 2026-07-29 日历详情返回回归定位

## 1. 现象

AGENTS 四页、一级左右切换和 AGENTS 详情返回均可用，但原厂日历进入详情后，按下并松开
旋钮无法返回一级页面。

## 2. 差异边界

原厂萌宠控件复用观察成品没有新增、删除或重排任何界面对象，页面注册点与
`opt-setting.bin` 相同，但仍复现了同一故障。共同修改边界收敛到一级键值回调地址：
原厂 `0xa00bbfee` 被替换为 AGENTS 包装入口。

## 3. 根因

原厂回调 `0xa00bbfee` 在左旋、右旋和确认三条分支分别调用 `0xa00be388`，以容器偏移
`52` 的交互分派序号选择一级页面或内部详情逻辑。AGENTS 包装改用 `0xa00b0290` 读取偏移
`56` 的窗口切换状态，并把它当作确认分派依据。

日历进入详情后，窗口切换状态仍可指向日历一级页，而原厂交互分派已经进入内部详情状态。
包装依据偏移 `56` 判断确认键，导致原厂日历返回分支没有收到完整事件。此前把故障归因于
新增对象改变序号，已经被零新增对象成品的同症状否定。

## 4. 修复约束

1. 页面注册点和原厂对象树保持 `opt-setting.bin` 原字节；
2. 包装入口必须用 `0xa00be388` 的结果判断原厂交互分支；
3. 交互分派序号不是 `7` 的确认键，在读取萌宠状态前直接进入原厂回调；
4. 交互分派序号为原厂内部详情时，左右和确认均直接进入原厂回调；
5. 不得用 `0xa00b0290` 的偏移 `56` 结果代替原厂确认分派序号。

## 5. 验收

- 日历进入详情后，按下并松开旋钮可返回日历一级页面；
- 原厂其他详情页保持原交互；
- 一级左右按功率、时间、日期、天气、设置、萌宠、AGENTS 的顺序首尾循环；
- AGENTS 概览、三个详情和详情返回均保持可用；
- 设备完成安装、启动、重新上线并继续主动获取四页数据。
