# 2026-08-01 FW-AGENTS-008 功率页未找到

返回主文档：[`AP01 官方固件分析`](../AP01-官方固件分析.md)

## 1. 真机事实

`FW-AGENTS-008` 安装并重新上线后，用户确认设备能够进入一级页面，默认显示时钟页。随后按
既定顺序准备测试功率确认时，用户报告旋转过程中没有找到原厂功率页，并提出“旋转过快导致
跳过”或“页面被隐藏”两种可能。

同一时间窗内只读云端状态仍为在线、更新空闲，运行时间连续增长；没有本次操作触发整机重启
的证据。当前成品没有导出逐格键值、实际分派序号或目标分支，因此真机事实只能确认“用户无法
找到功率页”，不能直接指定跳页根因。

## 2. 已排除误隐藏

对原厂包、已验收设置阶段输入和 `FW-AGENTS-008` 成品逐字节复核后确认：

1. 显示初始化与九个原厂直接子对象创建区间保持一致；
2. 功率对象创建位置 `0xa00b2602` 的字节保持一致；
3. 功率确认区间 `0xa00bc8c6..0xa00bc960` 与设置阶段输入一致；
4. 当前成品没有接入一级页面过滤挂接；
5. 构建清单同样记录页面注册字节未变、功率确认路径未变。

因此，当前没有代码证据支持“功率页被显隐配置关闭”。原厂功率对象仍会创建；本次现象应按
“没有稳定停留或没有被用户看到”继续定位，而不是按页面不存在处理。

## 3. 当前成品仍会从上游影响功率页

当前成品虽然没有修改功率页创建和确认代码，但修改了功率页上游的共享输入与相邻导航：

1. 设置阶段输入把底层旋钮方向变化位置 `0xa0107e20` 的原字节 `a14d` 改为 `71bd`；该修改
   位于所有页面共用的旋钮解码路径，不只作用于系统设置页；
2. 当前成品在萌宠左旋、右旋和确认三个原厂局部分支挂接自定义入口；
3. 产品导航把 AGENTS 概览作为萌宠与功率之间的逻辑一级页；
4. 从 AGENTS 概览向功率方向离开时，代码先恢复萌宠，再返回原厂萌宠右旋继续地址
   `0xa00bc716`。

因此，“功率页本身字节未改”只能证明功率页面代码未被直接覆盖，不能证明到达功率页之前的
输入事件数、当前分派序号和页面切换生命周期未受影响。

## 4. 尚未区分的两条路径

当前证据同时容许：

1. 一个用户认为的旋转动作产生多个完整同向事件，依次经过 AGENTS 概览、功率并继续落到
   下一页；
2. AGENTS 概览恢复萌宠并交还原厂右旋继续地址时，原厂内部状态与显示状态没有保持一致，
   导致功率页没有稳定显示。

底层方向过滤只丢弃同一格中途出现的相反方向边沿，设计上不增加同向步数；但它作用于全部
页面，且只在系统设置列表范围完成过真机验收，不能据此宣称一级页面步进没有问题。没有逐格
事件记录前，不把任一路径写成根因。

## 5. 当前结论与停止条件

`FW-AGENTS-008` 的启动画面通过，但一级物理导航失败，方案已否定并禁止再次安装。当前停止
功率确认和其他页面操作。下一版代码前，DESIGN 必须先规定一个不改变原厂导航结果的观察
方案，至少取得原始键值、当前交互分派序号、AGENTS 独立状态和实际目标分支；取得真机记录
后才能在“多事件”和“状态错位”之间纠偏。
