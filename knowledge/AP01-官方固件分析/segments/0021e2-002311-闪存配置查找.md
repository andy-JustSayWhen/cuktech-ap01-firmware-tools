# `0x0021e2..0x002311` 闪存配置查找

返回总账：[`AP01 原厂固件逐字节与逐指令通读总账`](../原厂固件逐字节与逐指令通读总账.md)

## 1. 覆盖结论

本段连续覆盖 304 字节、1 个完整函数、113 条指令，没有数据或填充。
端点 `0xa0001312` 是下一函数的栈帧建立指令，不属于本段。

该函数是 `bflb_sf_cfg_get_flash_cfg_need_lock_ext`（按编号取得闪存配置的原厂扩展函数）的
这份固件实现：

| 输入情况 | 实际路径 | 成功条件 |
| --- | --- | --- |
| 闪存编号为 0 | 临时把镜像偏移设为 0，从 `0xa0000008` 读 92 字节，随后恢复原偏移 | 头 4 字节等于 `FCFG`（闪存配置块标记），且后续 84 字节的校验值一致 |
| 闪存编号非 0 | 先调用芯片只读函数表中的标准查找；失败后遍历本地 41 项补充表 | 标准查找返回 0，或本地表的编号字段命中 |

成功时复制 84 字节配置并返回 0；所有路径都失败时返回 -1。

## 2. 原厂源码对应和版本边界

已直接核对官方仓库中以下原文：

- `drivers/lhal/src/flash/bflb_sf_cfg.c` 的基础查找函数，对应“编号为 0 时读头部并校验”和
  “按编号查表”两条主路径；
- `drivers/lhal/src/flash/bflb_xip_sflash.c` 的缓存读取函数，对应保存偏移、清零偏移、复制数据和
  恢复偏移的嵌入指令；
- `drivers/soc/bl616/std/include/bl616_romdriver_e907.h` 的只读函数表，证明
  `0x90015d00`、`0x90015d24`、`0x90015db4` 分别是标准配置查找、取得镜像偏移、设置镜像偏移。

官方仓库 `V2.0.0` 和当前 `f7b74e7` 版本中，扩展函数本身只转发到基础函数；
没有找到这份二进制里“标准查找失败后再查 41 项补充表”的同版本源码。该差异不影响
指令结论：`0xa00012d6..0xa000130e` 直接证明了补充路径；本文不把新版源码的简单转发
冒充为原厂固件的完整实现。

## 4. 能力边界

本函数只保证把命中的 84 字节配置复制到调用者给定的地址；它不验证输出地址容量，
也不会在本地表失败后自动探测闪存。对编号为 0 的路径，标记或校验任一失败就返回 -1。
