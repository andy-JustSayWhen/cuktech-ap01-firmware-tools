# `0x002772..0x002821` 双闪存擦除分流

返回总账：[`AP01 原厂固件逐字节与逐指令通读总账`](../原厂固件逐字节与逐指令通读总账.md)

## 1. 覆盖结论

本段连续覆盖 176 字节、1 个完整函数、62 条指令，没有数据或填充。

函数是 `bflb_flash_erase`（在两颗闪存之间分流擦除请求）：`a0` 是绝对起始地址，`a1` 是擦除长度。

| 条件 | 路径 |
| --- | --- |
| `起始 + 长度 > 第一颗容量 + 第二颗容量` | 直接返回 -12 |
| `起始 + 长度 <= 第一颗容量` | 关闭中断，擦除第一颗，恢复原中断状态 |
| `起始 >= 第一颗容量` | 将系统总线切换到第二颗，擦除完整区间，然后撤销切换 |
| 区间跨越两颗 | 关中断擦除第一颗尾部；成功后切换总线，再擦除第二颗头部 |

跨颗路径的第一段返回非零时立即结束，不进入第二颗。

## 2. 原厂源码与版本边界

官方仓库 `V2.0.0` 的 `drivers/lhal/src/bflb_flash.c` 中，`bflb_flash_erase`
的容量检查、三种分流、中断保护、第二总线切换和跨颗中途失败返回与本段一致。
当前官方源码将中断保护封装进了新的进入/退出函数；本二进制明确直接读写 `mstatus`
（处理器全局状态寄存器），因此以 `V2.0.0` 路径为同版本证据。

芯片只读函数表的 `0x90015d98` 和 `0x90015d9c` 分别是第二总线替换与撤销替换。

## 4. 能力边界

函数使用 32 位加法计算“起始 + 长度”，没有单独检查该加法是否回绕。第二颗路径传给底层的仍是绝对地址，
底层配置和总线切换必须与这一地址约定一致。本函数不会在实际擦除后读回数据验证是否全部变为擦除值。
