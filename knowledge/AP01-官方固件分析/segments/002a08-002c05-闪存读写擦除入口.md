# `0x002a08..0x002c05` 闪存读写擦除入口

返回总账：[`AP01 原厂固件逐字节与逐指令通读总账`](../原厂固件逐字节与逐指令通读总账.md)

## 1. 覆盖结论

本段连续覆盖 510 字节、190 条指令，包含三个函数：

| 文件偏移 | 函数 | 指令数 | 结论 |
| --- | --- | ---: | --- |
| `0x002a08..0x002ab5` | `bflb_xip_sflash_read_need_lock` 的本机专用入口 | 64 | 用全局闪存配置执行映射外读取，处理进入、状态保存、失败恢复、成功读出、状态恢复和退出 |
| `0x002ab6..0x002b63` | `bflb_xip_sflash_write_need_lock` 的本机专用入口 | 65 | 用全局闪存配置执行页编程，控制路径与读取入口成对 |
| `0x002b64..0x002c05` | `bflb_xip_sflash_erase_need_lock` 的本机专用入口 | 61 | 把长度换算成包含式结束地址后调用前文已经通读的区间擦除函数 |

三个入口都固定使用 `gp+56` 指向的全局闪存配置、处理器组 0、闪存分区 0。调用者只传
地址、缓冲区和长度；擦除入口只传起始地址和长度。

## 2. 原厂源码和只读函数表证据

官方仓库 `V2.0.0` 的 `drivers/lhal/src/flash/bflb_xip_sflash.c` 给出了三条完整控制流，
`drivers/soc/bl616/std/include/bl616_romdriver_e907.h` 则证明本段只读函数表目标：

| 函数表地址 | 原厂函数 | 本段用途 |
| --- | --- | --- |
| `0x90015f04` | `RomDriver_XIP_SFlash_Opt_Enter` | 保存并暂时调整加密映射状态 |
| `0x90015f08` | `RomDriver_XIP_SFlash_Opt_Exit` | 恢复进入前的加密映射状态 |
| `0x90015e0c` | `RomDriver_SFlash_Set_IDbus_Cfg` | 状态保存失败时重新建立映射读取配置 |
| `0x90015dec` | `RomDriver_SFlash_Read` | 从闪存读到调用者缓冲区 |
| `0x90015dd8` | `RomDriver_SFlash_Program` | 把调用者缓冲区写入闪存 |
| `0x90015ef8` | `RomDriver_XIP_SFlash_State_Restore` | 恢复镜像偏移和映射读取状态 |

二进制把公开源码中的全局配置、处理器组 0 和闪存分区 0 固化进了三个专用入口；这不是
对函数名的推测，因为参数寄存器布局、成功/失败分支和六个函数表目标均逐项吻合。

| `0xa0001bf8` | `mv s2,a0` | 保存实际擦除函数返回值 |
| `0xa0001bfa` | `li a3,0` | 将闪存分区号设为 0 |
| `0xa0001bfc` | `li a2,0` | 将处理器组号设为 0 |
| `0xa0001bfe` | `addi a0,gp,56` | 传入全局闪存配置地址 |
| `0xa0001c02` | `jalr a5` | 恢复镜像偏移和映射读取状态 |
| `0xa0001c04` | `j 0xa0001bbe` | 汇合到退出保护状态和返回路径 |

## 4. 能力边界

1. 三个入口本身不做地址上限、缓冲区有效性或长度为 0 的检查。
2. 三个入口的名字明确要求调用者已经完成互斥保护；本段没有保存或关闭中断的指令。
3. 状态保存失败时不会读、写或擦除，只重建映射读取配置并返回原错误码。
4. 状态保存成功后，无论实际操作成功还是失败，都会恢复镜像偏移并退出映射保护状态。
5. 本段只操作全局配置对应的第一颗闪存；双闪存跨界分流不在这三个入口内。
