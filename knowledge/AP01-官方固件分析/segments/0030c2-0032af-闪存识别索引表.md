# `0x0030c2..0x0032af` 闪存识别索引表

返回总账：[`AP01 原厂固件逐字节与逐指令通读总账`](../原厂固件逐字节与逐指令通读总账.md)

## 1. 覆盖结论

本段连续覆盖 494 字节，不是可执行指令：

| 文件偏移 | 内容 | 长度 |
| --- | --- | ---: |
| `0x0030c2..0x0030c3` | 四字节对齐填充，两个字节均为 `00` | 2 |
| `0x0030c4..0x0032af` | 41 条 `flash_info_t`（闪存识别索引记录），每条 12 字节 | 492 |

每条记录的三个 32 位字段依次是：

1. 三字节闪存芯片编号；
2. 名称地址，本产品 41 条全部为 0；
3. 84 字节闪存配置地址，共引用后续 7 份不同配置。

## 2. 原厂源码和前后调用证据

官方仓库 `V2.0.0` 的 `drivers/lhal/src/flash/bflb_sf_cfg.c` 明确定义：

```c
typedef struct
{
    uint32_t jedec_id;
    char *name;
    const spi_flash_cfg_type *cfg;
} flash_info_t;
```

同文件的 `flash_infos` 数组和查找循环证明记录布局。前文
[`0021e2-002311 闪存配置查找`](0021e2-002311-闪存配置查找.md) 与
[`002e16-003013 第二颗闪存初始化与零填充`](002e16-003013-第二颗闪存初始化与零填充.md)
都实际按“索引乘 12、比较首字、读取偏移 8 配置地址”的方式使用这 41 条记录。

## 5. 能力边界

这个索引只把已知芯片编号映射到配置地址，不提供模糊匹配、容量推断或厂商回退。名称字段
全部为空，因此产品运行时不能从该表取得人类可读型号名。
