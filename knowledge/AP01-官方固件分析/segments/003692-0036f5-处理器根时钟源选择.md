# `0x003692..0x0036f5` 处理器根时钟源选择

返回总账：[`AP01 原厂固件逐字节与逐指令通读总账`](../原厂固件逐字节与逐指令通读总账.md)

## 1. 覆盖结论

本段连续覆盖 100 字节、38 条指令。官方源码把这条控制流写成多个短函数，编译后合并为一个
实际入口：

- 输入 0 选择基础时钟，再读取 `0x2000f030` 的位 0；位 0 为 0 时返回固定的 32000000
  赫兹，为 1 时调用前一段晶振频率查询；
- 输入 1 选择高速时钟，再读取 `0x2000e114` 的位 4～5；选择值 0、1、2、3 分别返回音频
  锁相环二分频、音频锁相环原频、240000000 赫兹和 320000000 赫兹；
- 输入不是 0 或 1 时返回 0。

## 2. 原厂源码对应关系

官方仓库 `V2.0.0` 的 `drivers/soc/bl616/std/src/bl616_clock.c` 中：

- `Clock_MCU_Root_Clk_Mux_Output`（取得处理器根时钟源频率）负责输入 0、1 和非法值的总分支；
- `Clock_Get_MCU_XClk_Sel_Val`（取得基础时钟选择）读取休眠控制寄存器低两位中的位 0；
- `Clock_XClk_Mux_Output`（取得基础时钟频率）在内部 32 兆赫和晶振之间选择；
- `Clock_MCU_Clk_Mux_Output`（取得处理器高速时钟频率）解释高速时钟选择值；
- 高速时钟选择字段的直接寄存器定义证明它位于 `0x2000e114` 的位 4～5。

二进制把公开源码中无线锁相环的 240 和 320 兆赫查询直接折叠成常量，未保留函数调用；这只
证明本入口的返回逻辑，不代表无线锁相环硬件已经启动或锁定。

## 4. 能力边界

该入口依据两个配置字段推导处理器根时钟源的名义频率，不检查所选振荡源是否上电、是否锁定，
也不应用处理器总线分频。后续函数还会在这个名义根频率上继续除以总线分频值。
