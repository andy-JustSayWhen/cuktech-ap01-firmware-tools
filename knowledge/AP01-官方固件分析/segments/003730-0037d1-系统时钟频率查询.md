# `0x003730..0x0037d1` 系统时钟频率查询

返回总账：[`AP01 原厂固件逐字节与逐指令通读总账`](../原厂固件逐字节与逐指令通读总账.md)

## 1. 覆盖结论

本段连续覆盖 162 字节、58 条指令，是系统时钟频率查询入口。实际二进制接受的类型值和路径
如下：

| 类型值 | 本机二进制行为 |
| --- | --- |
| 1 | 先取得处理器根时钟，再除以总线主分频加 1 |
| 3 | 递归查询类型 1，再除以外设总线分频加 1 |
| 4 | 查询 32 千赫时钟；低速来源返回 32000，数字分频来源返回晶振频率除以分频值加 1 |
| 5 | 查询基础时钟；在内部 32000000 赫兹和晶振频率之间选择 |
| 其他 | 返回 0 |

## 2. 原厂源码和二进制边界

官方仓库 `V2.0.0` 的 `drivers/soc/bl616/std/src/bl616_clock.c` 中
`Clock_System_Clock_Get`（取得系统时钟频率），与本机保留的类型 1、3、4、5 四条路径逐项
一致：

- `0x2000f030` 的位 1 是处理器根时钟选择，位 0 是基础时钟选择，位 3～4 是 32 千赫来源；
- `0x20000090` 的位 8～15 是总线主分频，位 16～23 是外设总线分频；
- `0x20000250` 的低 11 位是晶振生成 32 千赫时钟时使用的分频值。

公开源码还列出类型 0 的处理器根时钟和类型 6 的晶振频率；本机这个实际入口没有这两条分支，
传入它们会走默认返回 0。相应计算函数在前文作为独立内部入口存在，但不能据此把缺失分支算作
本入口能力。类型 2 在公开源码和本机二进制中都没有处理分支。

公开源码对 32 千赫来源值 0、1 都返回 32000，对 2、3 都使用晶振分频；编译结果因此只检查
来源字段的高位，也就是寄存器位 4，省略了不影响结果的位 3。

## 4. 能力边界

该入口只按寄存器字段计算名义频率，不检查时钟源工作状态。所有分频都使用无符号整数除法，
余数被舍去。实际入口缺少的类型 0、2、6 必须视为返回 0，不能依据公开源码或相邻内部函数
补成二进制中不存在的分支。
