# `0x00408c..0x0040a3` 三类消息空闲链表头

返回总账：[`AP01 原厂固件逐字节与逐指令通读总账`](../原厂固件逐字节与逐指令通读总账.md)

## 1. 覆盖结论

本段连续覆盖 24 字节，是三组双向循环链表头的静态初值：普通消息块空闲池、
中断处理专用消息块空闲池，以及 `System V`（一种老式进程间通信规则）消息块空闲池。
每组链表头都由前向、后向两个 32 位地址组成；两个地址均指回链表头自身，表示原厂消息
系统初始化函数运行前，链表中还没有消息块。

| 项目 | 值 |
| --- | --- |
| 文件范围 | `0x00408c..0x0040a3` |
| 复制后的运行内存范围 | `0x62fc3578..0x62fc358f` |
| 原厂对象 | `g_msgfree`、`g_msgfreeirq`、`g_msgfreelist` |
| 未解释字节 | 0 |

本文是上述三组全局空闲链表头、两类消息块结构及预分配数量的唯一事实原文；后续文档只引用
本路径，不重复定义。

## 3. 原厂消息初始化调用逐项闭合

原厂初始化路径在 `0xa002934e..0xa0029390` 连续处理三组链表：

1. `0xa002934e..0xa0029354` 把 `0x62fc3578` 作为链表头，传入数量 `4`、分配类别 `0`；
2. `0xa0029358..0xa0029360` 把 `0x62fc3580` 作为链表头，传入数量 `8`、分配类别 `2`；
3. `0xa0029364..0xa0029390` 分配 `1344` 字节，从 `0x62fc3588` 开始按 `336` 字节步长
   接入四个消息块，最后把链表闭合回头部。

前两组调用的共同辅助函数位于 `0xa0025166..0xa00251b2`。该函数逐条执行：

- 计算 `332 × 数量` 并申请一整块内存；
- 在每个消息块的 `+0x08` 写入分配类别；
- 把每个消息块的前两个 32 位字段接入对应双向链表；
- 每次把地址前移 `332` 字节，直到达到调用方给出的数量。

这与 `NuttX`（原厂固件使用的实时操作系统）的消息队列实现逐项一致：

- `g_msgfree` 保存普通预分配消息块；
- `g_msgfreeirq` 专门保留给中断处理路径；
- 分配类别 `0` 表示普通预分配，`1` 表示临时动态申请，`2` 表示中断保留预分配；
- `g_msgfreelist` 保存 `System V` 消息块。

官方源文件可直接核对：

- [`mq_initialize.c`](https://github.com/apache/nuttx/blob/c4f641991ae5a3edda9ddbfa5a7d3e76e8ae87e5/sched/mqueue/mq_initialize.c)
- [`mqueue.h`](https://github.com/apache/nuttx/blob/c4f641991ae5a3edda9ddbfa5a7d3e76e8ae87e5/sched/mqueue/mqueue.h)
- [`msg.h`](https://github.com/apache/nuttx/blob/c4f641991ae5a3edda9ddbfa5a7d3e76e8ae87e5/sched/mqueue/msg.h)
- [`mq_msgfree.c`](https://github.com/apache/nuttx/blob/c4f641991ae5a3edda9ddbfa5a7d3e76e8ae87e5/sched/mqueue/mq_msgfree.c)

公开源码当前把三类消息块放进静态池，原厂二进制则在初始化时申请整块内存；两者的链表名称、
结构字段、分配类别和三类用途一致。本文以原厂二进制的实际分配时机和数量为准，不把公开源码
的存储时机反套到该固件。

## 4. 两种消息块尺寸与配置反推

普通和中断保留消息块每个正好 332 字节：

| 字段 | 长度 |
| --- | ---: |
| 双向链表节点 | 8 |
| 分配类别 | 1 |
| 消息优先级 | 1 |
| 消息长度 | 2 |
| 消息正文 | 320 |
| 合计 | 332 |

因此原厂的单条消息正文上限为 320 字节；普通预分配数量为 4，中断保留数量为 8。

`System V` 消息块每个正好 336 字节：

| 字段 | 长度 |
| --- | ---: |
| 双向链表节点 | 8 |
| 消息长度 | 2 |
| 对齐空位 | 2 |
| 消息类型 | 4 |
| 消息正文 | 320 |
| 合计 | 336 |

`1344 ÷ 336 = 4`，所以这类消息块也预分配 4 个。两种结构的 320 字节正文上限相同。

## 5. 分配和归还路径验证

后方 `0xa012e2f2..0xa012e32e` 的消息块取得函数先从 `g_msgfree` 取一个普通块：

- 普通池为空且当前不在中断处理环境时，动态申请 332 字节并把类别写成 `1`；
- 普通池为空且当前在中断处理环境时，改从 `g_msgfreeirq` 取保留块；
- 两条路径都失败时返回空地址。

`0xa012e578..0xa012e5d4` 的归还函数读取消息块 `+0x08` 的类别：类别 `0` 回普通池，
类别 `2` 回中断池，类别 `1` 释放动态内存，其余值进入原厂断言失败路径。由此可确认，前两组
链表不是一般用途的匿名链表，而是消息块分配器实际使用的两个空闲池。

这些后方地址只用于确认本段数据的名称、结构和能力边界；因文件顺序尚未读到这些代码，本文
不把后方函数本身提前标为已逐指令通读。

## 6. 能力边界

本段只保存三组空闲链表头的开机初值，不包含任何预分配消息正文。普通 4 块、中断保留 8 块
和 `System V` 4 块都是初始化函数运行后从内存中建立；链表在运行中会随消息发送、接收和释放
不断变化，因此不能用本段静态自指状态推断运行时一直没有消息。
