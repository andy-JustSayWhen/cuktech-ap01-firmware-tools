# `0x0040a4..0x0040b3` 文件区间锁保护互斥量

返回总账：[`AP01 原厂固件逐字节与逐指令通读总账`](../原厂固件逐字节与逐指令通读总账.md)

## 1. 覆盖结论

本段连续覆盖 16 字节，是原厂文件区间锁表的全局保护互斥量 `g_protect_lock` 初值。文件关闭
路径在查找、删除当前文件关联的区间锁记录前取得它，完成链表和查找表修改后再释放它，防止
多个任务同时破坏同一份锁记录。

| 项目 | 值 |
| --- | --- |
| 文件范围 | `0x0040a4..0x0040b3` |
| 复制后的运行内存范围 | `0x62fc3590..0x62fc359f` |
| 原厂对象 | `g_protect_lock` |
| 原厂结构 | 16 字节互斥量 |
| 未解释字节 | 0 |

## 2. 十六字节逐字段读取

| 文件偏移 | 运行地址 | 长度 | 原始内容 | 初始状态 |

| `0x0040a4..0x0040b3` | `0x62fc3590..0x62fc359f` | 16 | `01 00 05 00 00 00 00 00 00 00 00 00 ff ff ff ff` | 未占用、没有持有任务的互斥量 |

互斥量内部字段和该 16 字节初始器的唯一原文见
[`闪存容量、同步量与驱动配置`](003f84-00405f-闪存容量同步与驱动锁配置.md)第 3 节；
本文只确定本对象的业务归属，不重复定义结构。

## 3. 原厂调用链闭合

原厂 `0xa0027ba4` 开始的文件关闭路径执行以下顺序：

1. 取得当前文件及其文件节点；
2. 确认该文件需要清理区间锁记录；
3. 取得当前任务，查找当前文件对应的锁记录；
4. 在 `0xa0027bf6` 把 `gp+208`，即 `0x62fc3590`，传给互斥量取得函数；
5. 删除当前文件持有的锁记录并回收对应节点；
6. 在 `0xa0027c08` 把同一地址传给互斥量释放函数；
7. 随后才调用文件节点的关闭入口并释放文件节点引用。

`NuttX`（原厂固件使用的实时操作系统）当前的
[`fs_lock.c`](https://github.com/apache/nuttx/blob/c4f641991ae5a3edda9ddbfa5a7d3e76e8ae87e5/fs/vfs/fs_lock.c)
同样把 `g_protect_lock` 声明为全局保护互斥量，并在查找、修改、关闭清理文件区间锁记录时
成对取得和释放。原厂二进制的实际地址、初值和关闭清理顺序与该职责一致。

这些后方地址用于确认本段对象名称和用途；因文件顺序尚未读到对应函数，本文不把后方函数
提前标为已逐指令通读。

## 4. 能力边界

本段只保护文件区间锁管理数据，不是文件节点树的全局读写同步量；后者唯一原文见
[`文件节点树读写同步量`](004060-00408b-文件节点树读写同步量.md)。本段也不保存任何具体
文件锁记录，实际记录在运行时按文件操作动态建立和删除。
