# `0x0040b4..0x0040d3` 套接字伪文件节点

返回总账：[`AP01 原厂固件逐字节与逐指令通读总账`](../原厂固件逐字节与逐指令通读总账.md)

## 1. 覆盖结论

本段连续覆盖 32 字节，是原厂套接字专用伪文件节点 `g_sock_inode` 的完整静态初值。套接字
创建成功后，原厂把新建的套接字对象作为文件私有数据，并把本节点作为文件节点，一起交给
文件描述符分配器；因此套接字可以复用统一的文件描述符读、写、关闭和控制路径。

| 项目 | 值 |
| --- | --- |
| 文件范围 | `0x0040b4..0x0040d3` |
| 复制后的运行内存范围 | `0x62fc35a0..0x62fc35bf` |
| 原厂对象 | `g_sock_inode` |
| 原厂结构 | `struct inode`，32 字节配置形态 |
| 未解释字节 | 0 |

本文是该套接字伪文件节点结构、字段和值的唯一事实原文；后续文档只引用本路径。

运行地址 `0x62fc35c0` 开始，原厂代码单独以 `gp+256` 引用它，也从二进制侧封闭了本结构
的末端。

## 3. 操作表逐项核准

本段的 `u.i_ops` 指向运行地址 `0xa01b89c8`。该表前九项依次为：

| 表内偏移 | 原始值 | 原厂职责 |
| ---: | --- | --- |
| `+0x00` | `0xa00254a2` | 打开 |
| `+0x04` | `0xa0025526` | 关闭 |
| `+0x08` | `0xa002554e` | 读取 |
| `+0x0c` | `0xa002556a` | 写入 |
| `+0x10` | `0x00000000` | 不提供定位 |
| `+0x14` | `0xa00255b4` | 设备控制 |
| `+0x18` | `0x00000000` | 不提供内存映射 |
| `+0x1c` | `0xa0024a04` | 截断入口 |
| `+0x20` | `0xa0024b5e` | 轮询入口 |

公开的原厂系统同类实现见
[`socket.c`](https://github.com/apache/nuttx/blob/c4f641991ae5a3edda9ddbfa5a7d3e76e8ae87e5/fs/socket/socket.c)：
其 `g_sock_inode` 同样以三个空树链接、引用计数 1、套接字类型 9 和套接字文件操作表初始化。
本固件操作表中的非空入口数量、顺序和职责与之逐项一致。

操作表位于镜像后方，本文只读取本段保存的指针，并用表项和值确认归属；后方各入口尚未按
文件顺序读到，不能提前标为已逐指令通读。

## 4. 文件描述符分配调用闭合

原厂套接字创建路径在底层套接字对象创建成功后申请 12 字节套接字容器，然后执行：

- 取当前任务所属的文件描述符表；
- 把 `gp+224`，即本段起点 `0x62fc35a0`，作为文件节点参数；
- 把套接字容器作为文件私有数据参数；
- 调用文件描述符分配器，把两者绑定到一个新文件描述符。

`0xa0026828` 和 `0xa019f4c0` 两个实际调用点都传入同一节点地址；前者用于单个套接字，
后者用于成对套接字中的文件描述符分配。由此可排除把本段前三个全零字误判为独立信号量。

## 5. 能力边界

本段是所有套接字文件描述符共享的常驻伪文件节点，不保存某个连接的远端地址、协议状态或
收发缓存；这些运行数据放在每个文件描述符自己的私有套接字对象中。三个空树链接也表示该
节点不挂入普通路径文件树，不代表设备没有网络能力。
