# `0x0040e0..0x0040ef` 系统内存日志设备

返回总账：[`AP01 原厂固件逐字节与逐指令通读总账`](../原厂固件逐字节与逐指令通读总账.md)

## 1. 覆盖结论

本段连续覆盖 16 字节，是原厂系统内存日志设备对象 `g_sysdev` 的完整静态初值。该对象把
一块 1024 字节内存解释成“8 字节管理头加 1016 字节循环日志区”，并维护当前打开该设备的
读者链表。系统启动时，它作为私有对象注册到 `/dev/ramlog`。

| 项目 | 值 |
| --- | --- |
| 文件范围 | `0x0040e0..0x0040ef` |
| 复制后的运行内存范围 | `0x62fc35cc..0x62fc35db` |
| 原厂对象 | `g_sysdev` |
| 原厂结构 | `struct ramlog_dev_s`（保存内存日志缓冲区和读者链表的结构），共 16 字节 |
| 未解释字节 | 0 |

本文是该设备对象初值、字段和注册用途的唯一事实原文；后续文档只引用本路径。

## 2. 十六字节逐字段读取

原始字节为：

```text
d8 57 fc 62  f8 03 00 00  d4 35 fc 62  d4 35 fc 62
```

| 文件偏移 | 结构内偏移 | 长度 | 小端值 | 字段与初始状态 |
| --- | ---: | ---: | --- | --- |
| `0x0040e0..0x0040e3` | `+0x00` | 4 | `0x62fc57d8` | `rl_header`：日志缓冲管理头地址 |
| `0x0040e4..0x0040e7` | `+0x04` | 4 | `0x000003f8` | `rl_bufsize = 1016`：循环日志区可用字节数 |
| `0x0040e8..0x0040eb` | `+0x08` | 4 | `0x62fc35d4` | `rl_list.next`：指向链表头自身 |
| `0x0040ec..0x0040ef` | `+0x0c` | 4 | `0x62fc35d4` | `rl_list.prev`：指向链表头自身 |

链表头运行地址正是本对象起点加 8，即 `0x62fc35d4`；两个方向都指回自身，表示启动时没有
任何读者。公开系统 12.12.0 版本中的同类结构、对象和初值与这四项逐项一致，见
[`ramlog.c`](https://github.com/apache/nuttx/blob/nuttx-12.12.0/drivers/syslog/ramlog.c)。

## 3. 缓冲管理头和容量闭合

写入函数 `0xa002bdba..0xa002beb4` 从本对象 `+0x00` 取得管理头，再按以下布局访问目标内存：

| 管理头内偏移 | 长度 | 用途 |
| ---: | ---: | --- |
| `+0x00` | 4 | 初始化标记，正确值为 `0x12345678` |
| `+0x04` | 4 | 单调递增的写入位置 |
| `+0x08` | 1016 | 实际循环日志字节 |

若初始化标记不正确且当前设备正是本对象，原厂先把从 `0x62fc57d8` 开始的 1024 字节清零，
再写入标记。`8 + 1016 = 1024`，与代码清零长度完全闭合。本段只确认本段保存的目标地址、
容量和后方代码的访问方式；目标缓冲区在镜像后方，尚未按文件顺序读到，不能提前计入连续
完成范围。

写入长度超过 1016 字节时，原厂只保留输入末尾 1016 字节。正常写入时用“写入位置除以
1016 的余数”确定循环区位置，跨尾端时分两次复制，最后把原请求长度累加到写入位置。

## 4. 读者链表调用闭合

设备打开入口 `0xa003169c..0xa0031704` 为新读者申请 20 字节私有对象，然后在关闭中断的
临界区内把该对象插入本段 `+0x08` 的双向链表。它根据当前写入位置和 1016 字节容量，为
读者设置最早仍未被覆盖的读取位置。

设备关闭入口 `0xa002e3b2..0xa002e3e4` 在关闭中断的临界区内从同一链表摘除读者对象，再
释放该对象。写入后的读者唤醒和读取事件通知也遍历本链表，因此这里保存的是读者集合，
不是日志字节链表。

## 5. 设备注册与操作表

启动代码 `0xa00295e0..0xa00295f8` 把以下三项交给设备注册入口 `0xa01b2052`：

- 路径字符串 `0xa01b82a4`，内容为 `/dev/ramlog`；
- 文件操作表 `0xa01b8938`；
- 私有对象 `gp`（保存全局数据起点的寄存器）加 268，即本段起点 `0x62fc35cc`。

操作表前九项依次是：

| 表内偏移 | 原始值 | 原厂职责 |
| ---: | --- | --- |
| `+0x00` | `0xa003169c` | 打开并建立读者对象 |
| `+0x04` | `0xa002e3b2` | 关闭并移除读者对象 |
| `+0x08` | `0xa002b2ca` | 读取循环日志 |
| `+0x0c` | `0xa002beea` | 写入循环日志 |
| `+0x10` | `0x00000000` | 不提供定位 |
| `+0x14` | `0xa002acde` | 设备控制 |
| `+0x18` | `0x00000000` | 不提供内存映射 |
| `+0x1c` | `0x00000000` | 不提供截断 |
| `+0x20` | `0xa002bf44` | 等待读写事件 |

该顺序也与上述公开原厂文件的 `g_ramlogfops` 一致。操作表和各函数位于镜像后方，本文用
它们确认本段对象用途，不把那些后方指令提前计入连续通读范围。

## 6. 能力边界

本段只保存日志缓冲头地址、容量和读者链表头，不直接保存日志内容。日志写满后覆盖最旧
数据；每个读者单独保存读取位置，所以不同读者可以按各自进度读取。该对象也不负责把日志
持久化到闪存或通过蓝牙发送，相关功能若存在，属于调用本设备的后续链路。
