# `0x00462c..0x00467b` 加密设备、块代理锁与目录节点

返回总账：[`AP01 原厂固件逐字节与逐指令通读总账`](../原厂固件逐字节与逐指令通读总账.md)

互斥量字段定义原文：
[`0x0040a4..0x0040b3` 文件区间锁保护互斥量](0040a4-0040b3-文件区间锁保护互斥量.md)

## 1. 覆盖结论

本段连续覆盖 80 字节，依次是加密设备共用的常驻文件节点、块设备代理临时编号保护锁，
以及目录文件共用的常驻文件节点。两个节点都采用前文已经逐字段确认的 32 字节文件节点
配置形态；中间 16 字节为一个独立互斥量。

| 项目 | 值 |
| --- | --- |
| 文件范围 | `0x00462c..0x00467b` |
| 复制后的运行内存范围 | `0x62fc3b18..0x62fc3b67` |
| 加密设备节点 | `g_cryptoinode`（加密设备共用的常驻文件节点），32 字节 |
| 块设备代理保护锁 | `g_devno_lock`（保护临时设备编号生成的锁），16 字节 |
| 目录节点 | `g_dir_inode`（目录文件共用的常驻文件节点），32 字节 |
| 未解释字节 | 0 |

## 3. 加密设备节点归属

`0xa01bacf8` 指向的九项文件操作如下：

| 表内偏移 | 原始值 | 行为 |
| ---: | --- | --- |
| `+0x00` | `0x00000000` | 不提供再次打开入口 |
| `+0x04` | `0xa003abf2` | 逐个移除并释放加密会话，最后释放文件私有对象 |
| `+0x08` | `0xa003a448` | 固定返回 `-5`，即输入输出错误 |
| `+0x0c` | `0xa003a456` | 固定返回 `-5`，即输入输出错误 |
| `+0x10` | `0x00000000` | 不提供位置移动入口 |
| `+0x14` | `0xa003ac36` | 处理 101 至 105 五个加密控制命令 |
| `+0x18` | `0x00000000` | 不提供内存映射入口 |
| `+0x1c` | `0x00000000` | 不提供截断入口 |
| `+0x20` | `0xa003a464` | 轮询入口固定返回成功 |

这九项与上游提交
[`9eadf61e90c2dc655106e930459c4780e6335060` 中的 `g_cryptofops`](https://github.com/apache/nuttx/blob/9eadf61e90c2dc655106e930459c4780e6335060/crypto/cryptodev.c)
逐项一致。其控制命令数值也与同一提交的
[`cryptodev.h`](https://github.com/apache/nuttx/blob/9eadf61e90c2dc655106e930459c4780e6335060/include/crypto/cryptodev.h)
一致：取得会话为 101、关闭会话为 102、执行加密为 103、非对称密钥操作为 104、查询
非对称能力为 105。

后续上游提交
[`ee6fdb2c856e`](https://github.com/apache/nuttx/commit/ee6fdb2c856e)
才把第一项由空地址改为加密会话复制入口；本固件表内第一项仍为零，并且没有该新增函数，
因此这里采用的是该项变更前的实际边界，不能按后续源码补出原厂并不存在的能力。

`0xa003b448..0xa003b4b6` 进一步闭合节点用途：只接受数值 100 的“取得加密文件描述符”
命令，申请 12 字节会话表头，把 `gp+1624`，即本段起点 `0x62fc3b18`，作为文件节点
交给文件描述符分配器；成功后把新文件描述符写回调用方，失败时释放刚申请的表头。这与
同一份上游源码中 `cryptoioctl`（加密主设备的控制入口）使用 `g_cryptoinode` 的路径一致。

## 4. 块设备代理临时编号保护锁

`0xa003e83e..0xa003e89a` 先取得 `gp+1656`，即 `0x62fc3b38` 互斥量，再递增全局临时
设备编号，随后释放该互斥量；锁外把编号格式化为 `/dev/tmpc%06lx`，并反复检查同名路径
是否已存在。该顺序与原厂采用版本
[`fs_blockproxy.c`](https://github.com/apache/nuttx/blob/271f76590f22/fs/driver/fs_blockproxy.c)
中的临时字符设备命名函数逐步一致，因此本互斥量可定名为 `g_devno_lock`。

它只保护编号的读取和递增，不覆盖路径格式化、路径存在性检查、字符串复制或后续设备
注册；这些步骤在释放锁之后进行。

## 5. 目录节点归属

`0xa01bad20` 指向的目录文件操作表为：打开 `0xa003b834`、关闭 `0xa003b4e4`、读取
`0xa003b54a`、写入为空、位置移动 `0xa003b678`、设备控制 `0xa003a7bc`，其余三项
为空。非空项的顺序与原厂采用版本
[`fs_dir.c`](https://github.com/apache/nuttx/blob/271f76590f22/fs/vfs/fs_dir.c)
中的 `g_dir_fileops`（目录文件共用的操作表）逐项一致；同一源码也以三个空树链接、常驻
引用 1 和该操作表地址初始化 `g_dir_inode`。

目录打开路径会把本节点写入目录文件对象，但具体目录遍历位置、当前子节点和挂载点状态
仍保存在每次打开产生的独立私有对象中；本段节点不保存某一次目录遍历的运行状态。

## 6. 能力边界

本段证明两个常驻文件节点和一个保护锁的镜像初值、操作表归属与直接调用路径。操作表本身
位于镜像后方；本文用表项地址和已定位函数确认本段指针的身份，不把后方尚未顺序读到的
代码区提前登记为已逐指令完成。
