# `0x00467c..0x00476b` 网络递归锁与随机数状态

返回总账：[`AP01 原厂固件逐字节与逐指令通读总账`](../原厂固件逐字节与逐指令通读总账.md)

普通互斥量字段定义原文：
[`0x0040a4..0x0040b3` 文件区间锁保护互斥量](0040a4-0040b3-文件区间锁保护互斥量.md)

## 1. 覆盖结论

本段连续覆盖 240 字节，依次为 20 字节网络递归锁 `g_netlock`，以及 220 字节随机数
生成状态 `g_rng`。`rmutex_t`（允许同一任务重复取得、用计数记录取得层数的互斥量）的
结构和初值以本文为唯一事实原文；后续文档只引用本路径。

| 项目 | 值 |
| --- | --- |
| 文件范围 | `0x00467c..0x00476b` |
| 复制后的运行内存范围 | `0x62fc3b68..0x62fc3c57` |
| 网络递归锁 | `0x00467c..0x00468f`，20 字节 |
| 随机数生成状态 | `0x004690..0x00476b`，220 字节 |
| 未解释字节 | 0 |

## 2. 网络递归锁的二十字节

| 文件偏移 | 结构内偏移 | 长度 | 原始值 | 初始状态 |
| --- | ---: | ---: | --- | --- |
| `0x00467c..0x00468b` | `+0x00` | 16 | `01 00 05 00 00 00 00 00 00 00 00 00 ff ff ff ff` | 内层普通互斥量处于可取得、无持有者状态 |
| `0x00468c..0x00468f` | `+0x10` | 4 | `0x00000000` | 同一任务当前重复取得层数为 0 |

原厂采用版本的
[`mutex.h`](https://github.com/apache/nuttx/blob/271f76590f22/include/nuttx/mutex.h)
规定递归锁就是一个 16 字节普通互斥量加一个无符号计数，并以普通互斥量初值加零计数
初始化；本段 20 字节与其逐字段一致。

`0xa003ba8c..0xa003baa2` 直接把 `gp+1704`，即本段起点，交给递归锁释放入口。
`0xa003bf8a..0xa003bfde` 核对当前任务确实是持有者后，保存 `+0x10` 的重复取得层数，
把层数清零并释放内层互斥量；释放失败时恢复原层数。`0xa01b0f18..0xa01b0f68`
执行相反路径：重新取得同一个锁并恢复保存的层数，或正常释放它。

该控制流与同版本
[`net_lock.c`](https://github.com/apache/nuttx/blob/271f76590f22/net/utils/net_lock.c)
中的网络锁取得、释放、临时打断和按原层数恢复路径逐项一致，因而本对象可定名为
`g_netlock`（所有网络协议处理共用的递归锁）。它不是某一个连接的私有锁。

## 3. 随机数状态的二百二十字节

本段的 `g_rng`（系统随机数生成状态）只有开头普通互斥量带非零静态初值，其余 204 字节
全部为零。逐字段布局如下：

| 文件偏移 | 结构内偏移 | 长度 | 原始值 | 字段与初始状态 |
| --- | ---: | ---: | --- | --- |
| `0x004690..0x00469f` | `+0x00` | 16 | 普通互斥量初值 | 随机数状态尚未被任务持有 |
| `0x0046a0..0x0046a3` | `+0x10` | 4 | `0x00000000` | 熵池下一次搅拌位置为 0 |
| `0x0046a4..0x0046a7` | `+0x14` | 4 | `0x00000000` | 自上次重新播种后新增熵记录数为 0 |
| `0x0046a8` | `+0x18` | 1 | `00` | 下一输入字的循环移位量为 0 |
| `0x0046a9` | `+0x19` | 1 | `00` | 上次计时取样的压缩值为 0 |
| `0x0046aa..0x0046ab` | `+0x1a` | 2 | `0x0000` | 上次中断编号取样为 0 |
| `0x0046ac` | `+0x1c` | 1 | `00` | 对外随机输出状态尚未初始化 |
| `0x0046ad..0x0046af` | `+0x1d` | 3 | `00 00 00` | 32 位对齐填充 |
| `0x0046b0..0x0046b3` | `+0x20` | 4 | `0x00000000` | 扩展输出节点偏移为 0 |
| `0x0046b4..0x0046d3` | `+0x24` | 32 | 全零 | 扩展输出参数块尚未建立 |
| `0x0046d4..0x00474b` | `+0x44` | 120 | 全零 | 摘要计算上下文尚未建立 |
| `0x00474c..0x00476b` | `+0xbc` | 32 | 全零 | 根输出暂存区尚无内容 |

以上长度合计 `16 + 4 + 4 + 1 + 1 + 2 + 1 + 3 + 4 + 32 + 120 + 32 = 220`
字节。参数块、摘要上下文和根输出暂存区共同构成 `BLAKE2Xs`（把熵池内容变成可持续
取出随机字节的一套算法）的运行状态；它们的 32、120 和 32 字节大小分别由同版本
[`blake2s.h`](https://github.com/apache/nuttx/blob/271f76590f22/include/nuttx/crypto/blake2s.h)
中的参数结构、上下文结构和固定输出长度直接给出。

## 4. 随机数调用路径闭合

原厂采用版本
[`random_pool.c`](https://github.com/apache/nuttx/blob/271f76590f22/crypto/random_pool.c)
以普通互斥量初值初始化 `g_rng`，其余字段由静态零初始化产生；结构成员顺序和本段完全
一致。固件中的实际访问进一步闭合了该归属：

- `0xa003e11e..0xa003e1f0` 从 `gp+1724` 取得搅拌位置、新增熵记录数和移位量；
- 同一函数按 `104、76、51、25、1` 五个回看位置读取 `0x62fc89a8` 的 128 项熵池，
  再用镜像只读区的八项扭转常量写回当前池项；
- `0xa001ac8a..0xa001ad32` 读取并更新 `+0x19` 的上次计时值和 `+0x1a` 的上次中断
  编号，然后把新的取样交给上述熵混合函数；
- 搅拌位置每次减一并限制在 `0..127`，新增熵标志为真时才递增 `+0x14` 计数，这与
  上游 `addentropy`（把新取样混入熵池的内部入口）的控制流逐项一致。

熵池的 128 个 32 位池项位于运行期零初始化区 `0x62fc89a8`，不在本段镜像字节内；本段
保存的是控制和输出状态。两者不能合并成同一个静态对象，也不能把本段的大段零值解释为
已经生成好的随机数据。

## 5. 能力边界

本段只证明网络递归锁和随机数生成状态的静态初值、结构边界与实际访问路径。随机数状态在
启动后会随着计时、中断和其他熵来源持续变化；镜像中的全零初值不代表运行时随机输出为零。
