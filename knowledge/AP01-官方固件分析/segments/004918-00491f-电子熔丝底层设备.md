# `0x004918..0x00491f` 电子熔丝底层设备

返回总账：[`AP01 原厂固件逐字节与逐指令通读总账`](../原厂固件逐字节与逐指令通读总账.md)

互斥量字段定义原文见
[`0x0040a4..0x0040b3` 文件区间锁保护互斥量](0040a4-0040b3-文件区间锁保护互斥量.md)。

## 1. 覆盖结论

本段连续覆盖 8 字节，是电子熔丝底层设备对象。第一项指向三入口底层操作表，第二项是
注册后保存上层设备对象的地址，静态初值为空。

| 项目 | 值 |
| --- | --- |
| 文件范围 | `0x004918..0x00491f` |
| 复制后的运行内存范围 | `0x62fc3e04..0x62fc3e0b` |
| 原始字节 | `00 d2 1b a0 00 00 00 00` |
| 注册路径 | `/dev/efuse` |
| 未解释字节 | 0 |

## 2. 两个地址字段

| 结构内偏移 | 长度 | 静态值 | 已证实职责 |
| ---: | ---: | --- | --- |
| `+0x00` | 4 | `0xa01bd200` | 三入口底层操作表地址 |
| `+0x04` | 4 | 空 | 注册成功后保存上层设备对象地址；分配失败时保持为空 |

原厂采用版本的
[`efuse.h`](https://github.com/apache/nuttx/blob/271f76590f22/include/nuttx/efuse/efuse.h)
公开了 `struct efuse_lowerhalf_s`（电子熔丝底层设备对象）的首个操作表字段。原厂二进制在
这个公开前缀之后保留了第二个地址字段；该扩展不是依据相邻零值推测，而是由注册路径对
`+0x04` 的实际写入确认。

## 3. 三入口操作表

操作表位于运行地址 `0xa01bd200`，三项原始地址依次为
`0xa01345aa`、`0xa0131c30`、`0xa0131c4a`：

| 表内偏移 | 入口 | 指令证据和作用 |
| ---: | --- | --- |
| `+0x00` | `0xa01345aa` | 检查三个输入地址，按字段起点和位长分段读取电子熔丝值 |
| `+0x04` | `0xa0131c30` | 直接返回错误值 `-38`，明确不提供写入能力 |
| `+0x08` | `0xa0131c4a` | 直接返回错误值 `-25`，明确不接受未实现的设备控制请求 |

`0xa01bd20c` 已属于下一份只读数据，因而本操作表边界严格为三项。操作表和三个入口位于
镜像后方；本文只用它们确认当前 8 字节对象的身份与能力，不把后方代码提前登记为已经
顺序通读。

## 4. 注册路径闭合

`0xa00558c6..0xa00559a4` 的控制流与原厂采用版本
[`efuse.c`](https://github.com/apache/nuttx/blob/271f76590f22/drivers/efuse/efuse.c)
中的注册过程逐项闭合：

1. 申请 24 字节上层设备对象；
2. 初始化其中的保护互斥量；
3. 把本段底层对象地址写入上层对象 `+0x14`；
4. 复制 `/dev/efuse` 路径并保存到上层对象 `+0x10`；
5. 用上层文件操作表注册设备；
6. 注册成功后，把上层对象地址写回本段 `+0x04`；注册失败则释放路径和对象。

申请失败分支 `0xa00558e4` 明确把本段 `+0x04` 写回空值，成功分支 `0xa00559a0` 则写入
新对象地址。因此第二个地址的职责、写入时机和失败状态均已由实际指令确认。

## 5. 能力边界

本段只保存电子熔丝底层操作入口与注册句柄。它证明原厂开放字段读取，并明确拒绝底层写入；
具体字段描述、上层请求参数和后方读取函数的全部指令，必须等顺序覆盖到各自文件偏移时再
登记，本文不提前宣称已经通读。
