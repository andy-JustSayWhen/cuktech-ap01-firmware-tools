# `0x004920..0x004947` 外部闪存设备对象

返回总账：[`AP01 原厂固件逐字节与逐指令通读总账`](../原厂固件逐字节与逐指令通读总账.md)

`LittleFS` 的定义原文见
[`AP01 官方固件分析`](../AP01-官方固件分析.md#2-已确认的原厂能力边界)。

## 1. 覆盖结论

本段连续覆盖 40 字节，是 BL616 外部闪存的 `MTD`（把存储芯片包装成统一擦、读、写接口
的设备层）对象。前 36 字节与原厂采用版本的通用结构逐字段一致，最后 4 字节是芯片驱动
扩展的容量状态地址。

| 项目 | 值 |
| --- | --- |
| 文件范围 | `0x004920..0x004947` |
| 复制后的运行内存范围 | `0x62fc3e0c..0x62fc3e33` |
| 设备名称 | `bl616_media` |
| 驱动源码路径原文 | `chip/bl616_spiflash_mtd.c` |
| 启动时写入的总容量 | `0x01000000` 字节，即 16 兆字节 |
| 未解释字节 | 0 |

## 2. 四十字节逐字段解释

原厂采用版本
[`mtd.h`](https://github.com/apache/nuttx/blob/271f76590f22/include/nuttx/mtd/mtd.h)
中的 `struct mtd_dev_s`（通用存储设备对象）在启用逐字节写入后依次包含六个操作入口、
两个坏块入口和一个名称地址，共 36 字节。原厂芯片驱动在其后追加一个私有地址：

| 结构内偏移 | 长度 | 原始值 | 已证实职责 |
| ---: | ---: | --- | --- |
| `+0x00` | 4 | `0xa0057462` | 按 4096 字节擦除块擦除 |
| `+0x04` | 4 | `0xa0057f7a` | 按 256 字节读写块读取 |
| `+0x08` | 4 | `0xa00574a8` | 按 256 字节读写块写入 |
| `+0x0c` | 4 | `0xa0057fba` | 按任意字节偏移读取 |
| `+0x10` | 4 | `0xa00574ec` | 按任意字节偏移写入，并检查总容量边界 |
| `+0x14` | 4 | `0xa0057540` | 查询存储几何参数和分区参数 |
| `+0x18` | 4 | 空 | 不提供坏块检查入口 |
| `+0x1c` | 4 | 空 | 不提供坏块标记入口 |
| `+0x20` | 4 | `0xa01bd118` | 设备名字符串 `bl616_media` |
| `+0x24` | 4 | `0x62fc8cd0` | 指向运行期总容量值 |

十项长度合计 40 字节，与下一对象起点 `0x004948` 严格闭合。

## 3. 六个操作入口的直接证据

当前对象只登记入口地址和由实际参数换算、返回路径证实的能力；入口函数本体位于镜像后方，
到达其顺序区间时仍须逐条指令登记。

| 入口 | 当前已核准的数据流 |
| --- | --- |
| `0xa0057462` | 把起始块和块数各左移 12 位，转换为 4096 字节单位后调用底层擦除；成功返回已擦块数，失败返回 `-5` |
| `0xa0057f7a` | 把起始块和块数各左移 8 位，转换为 256 字节单位后调用共用读取函数；成功返回已读块数，失败返回 `-5` |
| `0xa00574a8` | 采用同样的 256 字节换算调用底层写入；成功返回已写块数，失败返回 `-5` |
| `0xa0057fba` | 不换算起始偏移和长度，直接调用共用读取函数；成功返回已读字节数，失败返回 `-5` |
| `0xa00574ec` | 从本对象 `+0x24` 取得总容量，拒绝起点或终点越界的写入；合法时调用底层写入 |
| `0xa0057540` | 请求值 `0x601` 时填写 256 字节读写块、4096 字节擦除块和总擦除块数；请求值 `0x50e` 时填写总块数、块大小和空分区名 |

驱动内的源文件断言地址统一指向字符串 `chip/bl616_spiflash_mtd.c`，把这六个入口和本对象
绑定到同一芯片驱动；这不是仅凭函数地址相邻作出的归类。

## 4. 容量与实际分区调用闭合

启动路径 `0xa00558f0..0xa0055a16` 对本对象执行以下操作：

1. 通过 `+0x24` 取得容量状态地址 `0x62fc8cd0`，写入 `0x01000000`；
2. 以本对象、起始块 `0x7100`、块数 `0x100` 创建子分区；
3. 根据本对象返回的 256 字节块大小，子分区起点是 `0x00710000`，长度是 `0x00010000`；
4. 把子分区注册为 `/dev/data`；
5. 初始化分区并把 `littlefs` 文件系统挂载到 `/data`。

因此 `+0x24` 不是任意私有地址：逐字节写入函数用它判定边界，参数查询用它计算块数，
启动路径则为它提供 16 兆字节实际容量，三条数据流互相闭合。

## 5. 能力边界

本段完整说明静态设备对象及其启动用途，不提前把六个后方函数标为已经逐指令通读。两项
坏块入口为空，表示这份闪存驱动不通过通用对象提供坏块检查和标记；它不影响已存在的擦除、
整块读写、逐字节读写和参数查询能力。
