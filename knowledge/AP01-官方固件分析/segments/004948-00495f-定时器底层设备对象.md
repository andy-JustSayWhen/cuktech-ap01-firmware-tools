# `0x004948..0x00495f` 定时器底层设备对象

返回总账：[`AP01 原厂固件逐字节与逐指令通读总账`](../原厂固件逐字节与逐指令通读总账.md)

## 1. 覆盖结论

本段连续覆盖 24 字节，是 BL616 的 0 号定时器底层设备对象。首项指向七入口操作表，其余
五项开机初值均为空；启动时再取得芯片定时器实例并注册为 `/dev/timer0`。

| 项目 | 值 |
| --- | --- |
| 文件范围 | `0x004948..0x00495f` |
| 复制后的运行内存范围 | `0x62fc3e34..0x62fc3e4b` |
| 原始字节 | `4c d2 1b a0`，后接 20 字节零 |
| 驱动源码路径原文 | `chip/bl616_tim_lowerhalf.c` |
| 注册路径 | `/dev/timer0` |
| 未解释字节 | 0 |

## 2. 二十四字节逐字段解释

原厂采用版本
[`timer.h`](https://github.com/apache/nuttx/blob/271f76590f22/include/nuttx/timers/timer.h)
规定 `struct timer_lowerhalf_s`（定时器底层设备对象）的公开前缀是操作表地址。原厂芯片
驱动在这个前缀后保存硬件实例、上层回调和运行状态：

| 结构内偏移 | 长度 | 静态值 | 已证实职责 |
| ---: | ---: | --- | --- |
| `+0x00` | 4 | `0xa01bd24c` | 七入口定时器操作表地址 |
| `+0x04` | 4 | 空 | 0 号芯片定时器实例地址 |
| `+0x08` | 4 | 空 | 到期时由底层调用的上层回调地址 |
| `+0x0c` | 4 | 空 | 传给回调的参数地址 |
| `+0x10` | 1 | 0 | 尚未启动标志 |
| `+0x11..+0x13` | 3 | 0 | 32 位对齐填充 |
| `+0x14` | 4 | 空 | `/dev/timer0` 注册成功后保存的上层设备对象地址 |

字段长度合计 24 字节；下一份只读地址从 `0x004960` 开始，因此本对象没有与下一对象重叠。

## 3. 七入口操作表

操作表 `0xa01bd24c` 的七项与通用定时器结构顺序完全一致：

| 表内偏移 | 原始值 | 已证实职责 |
| ---: | --- | --- |
| `+0x00` | `0xa012c040` | 启动定时器；已经启动时返回 `-16` |
| `+0x04` | `0xa012c0ce` | 停止定时器；未启动时返回 `-19` |
| `+0x08` | `0xa012c18e` | 读取运行标志、设定时长和剩余时长 |
| `+0x0c` | `0xa012c208` | 把新的到期时长交给芯片定时器 |
| `+0x10` | `0xa012c262` | 在关中断保护下更新 `+0x08` 回调和 `+0x0c` 参数 |
| `+0x14` | 空 | 不提供额外设备控制入口 |
| `+0x18` | `0xa012c23a` | 报告最大时长为 `0xffffffff` 微秒 |

驱动函数对 `+0x04`、`+0x08`、`+0x0c`、`+0x10` 的实际加载和写入分别确认了五个私有
字段；源文件断言地址统一指向 `chip/bl616_tim_lowerhalf.c`。这些后方入口在到达自身顺序
区间时仍须逐条指令登记，本文不把入口识别替代为后方代码通读。

## 4. 初始化和注册路径

`0xa0055cce..0xa0055dbc` 对本对象执行以下操作：

1. 把启动标志和回调地址写为空；
2. 以编号 0 取得芯片定时器实例并写入 `+0x04`；
3. 申请 84 字节上层设备对象，把本段地址写入上层对象 `+0x50`；
4. 初始化上层互斥量，复制 `/dev/timer0` 路径并注册设备；
5. 注册失败时释放路径和上层对象，并把本段 `+0x14` 写为空；
6. 注册成功时把上层对象地址写入本段 `+0x14`。

因此最后一个空地址不是未定填充：成功、失败两条控制流都直接写入它，职责已由真实指令
闭合。

## 5. 能力边界

本对象提供启动、停止、状态读取、时长设置、回调设置和最大时长查询；额外设备控制入口
为空。静态零值只表示设备注册前尚未绑定硬件实例、回调和上层对象，不表示这些能力缺失。
