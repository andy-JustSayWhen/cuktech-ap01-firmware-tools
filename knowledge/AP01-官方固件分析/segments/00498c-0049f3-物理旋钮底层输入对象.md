# `0x00498c..0x0049f3` 物理旋钮底层输入对象

返回总账：[`AP01 原厂固件逐字节与逐指令通读总账`](../原厂固件逐字节与逐指令通读总账.md)

页面级旋转、按下、进入和返回事实只引用唯一原文
[`原厂各页面物理旋钮交互实现`](../原厂各页面物理旋钮交互实现.md)，本文不重新定义。

## 1. 覆盖结论

本段连续覆盖 104 字节，是原厂物理旋钮的底层输入对象。它把 A 相、B 相和按键三个引脚
配置为输入，分别登记旋转和按键中断，把事件送入通用输入设备，并以 `/dev/input0` 注册。

| 项目 | 值 |
| --- | --- |
| 文件范围 | `0x00498c..0x0049f3` |
| 复制后的运行内存范围 | `0x62fc3e78..0x62fc3edf` |
| A 相引脚 | 16 |
| B 相引脚 | 17 |
| 按键引脚 | 24 |
| 注册路径 | `/dev/input0` |
| 初始旋转位置 | 0 |
| 初始按键电平 | 1，即未按下 |
| 连续覆盖字节 | 104 |

`0x0049f4` 复制到 `0x62fc3ee0`；启动代码 `0xa0056066` 直接把该地址当作显示设备对象
起点。因此本段既不吞入下一个对象的函数地址，也不存在未覆盖的尾部字节。

| `+0x38..+0x4f` | `0x0049c4..0x0049db` | 24 | 全零 | 按键释放复查使用的延时任务结构 |

各行长度合计 104 字节。`+0x0c` 和 `+0x24..+0x2f` 已按真实读写边界分类，但在没有
原厂私有头文件或有效指令访问前不猜造字段名；这与漏读字节不同。

延时任务结构的 24 字节布局由原厂采用版本
[`wqueue.h`](https://github.com/apache/nuttx/blob/271f76590f22/include/nuttx/wqueue.h#L244-L257)
核准：前 16 字节是队列或计时器共用区，后 8 字节依次为执行入口和参数。固件在
`0xa01080d6` 读取对象 `+0x48`，即该结构内 `+0x10` 的执行入口，判断任务是否已经排队。

## 3. 启动配置与注册路径

`0xa00567ec..0xa0056c34` 对本段执行的顺序是：

1. 清零对象 `+0x00..+0x0f`，并单独清零 `+0x24`；
2. 读取 `+0x10` 的引脚 16，把 A 相设为输入，配置边沿中断并登记
   `0xa0107bca`；
3. 对 `+0x14` 的引脚 17 执行相同配置，并登记同一个旋转中断入口；
4. 读取 `+0x18` 的引脚 24，把按键设为输入，配置边沿中断并登记
   `0xa0108026`；
5. 读取 A、B 两路当前电平，组合后写入 `+0x1c`；读取按键当前电平写入 `+0x1d`；
6. 生成 `/dev/input0`，复制到 `+0x51` 的 16 字节缓冲；
7. 申请 32 字节通用输入上层对象，把本段地址写入上层对象 `+0x18`，再把上层对象地址
   回写本段 `+0x00`；
8. 以操作表 `0xa01bd318` 注册设备，失败时释放上层对象并返回错误。

三路引脚的方向设置、边沿设置和中断登记均有独立失败日志，说明原厂不会把三路初始化
结果合并成一个未经检查的成功标志。

## 4. 旋转中断入口

两路旋转信号共用 `0xa0107bca`。该入口每次都重新读取引脚 16 和 17，把两位电平组合成
当前状态，再与 `+0x1c` 的上一次状态和旋转步骤状态比较。只有完成有效方向步骤时才修改
`+0x20` 累计位置，并通过 `+0x00` 的上层对象上报：

| 已证实方向 | 累计位置变化 | 上报编号 | 上报值 |
| --- | ---: | ---: | ---: |
| 顺时针 | `+1` | 106 | 1 |
| 逆时针 | `-1` | 105 | 1 |

无效跳变只记录日志并更新必要状态，不直接伪造一步。旋转入口末尾把本次两位电平写回
`+0x1c`。编号如何在各页面被转换为界面动作，只引用本文开头的页面交互唯一原文。

## 5. 按键中断与延时释放

按键中断入口是 `0xa0108026`，延时复查入口是 `0xa0107fb8`：

- 电平从 1 变为 0 且与上次被接受的按下边沿相隔超过 4,999 微秒时，上报编号 28、值 0，
  并把当前时间写入 `+0x30..+0x37`；
- 若 `+0x50` 表示已有延时任务，先取消并清零标志；
- 当前任务结构没有执行入口时，以 500 个系统节拍登记释放复查，成功后把 `+0x50` 置一；
- 电平从 0 变为 1 时，上报编号 28、值 1，取消未执行任务并清零标志；
- 延时入口再次读取引脚 24；仍为按下时继续排队，已经释放时上报值 1 并清零标志。

因此按键释放既可由新的边沿直接识别，也可由延时任务补识别；两条路径共用同一上层对象
和同一已排队标志。
