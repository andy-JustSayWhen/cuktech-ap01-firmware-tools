# `0x004ab4..0x004ab7` 系统内存日志输出通道

返回总账：[`AP01 原厂固件逐字节与逐指令通读总账`](../原厂固件逐字节与逐指令通读总账.md)

默认系统日志通道的操作表定义原文：
[`0x004960..0x004963` 默认系统日志通道`](004960-004963-默认系统日志通道.md)

本通道连接的内存日志设备定义原文：
[`0x0040e0..0x0040ef` 系统内存日志设备`](0040e0-0040ef-系统内存日志设备.md)

## 1. 覆盖结论

本段连续覆盖 4 字节，是 `g_ramlog_channel`（把系统日志写入内存循环区的通道）对象。
对象只保存一个六入口操作表地址 `0xa01bd424`。

| 项目 | 值 |
| --- | --- |
| 文件范围 | `0x004ab4..0x004ab7` |
| 复制后的运行内存范围 | `0x62fc3fa0..0x62fc3fa3` |
| 原始值 | `0xa01bd424` |
| 连续覆盖字节 | 4 |

`0x004ab8..0x004abb` 的值是另一张操作表地址 `0xa01bd518`，后方初始化函数把
`0x004ab8` 复制后的地址作为看门狗底层对象起点。因此它不属于本段。

## 2. 六入口操作表

| 表内偏移 | 原始值 | 已证实职责 |
| ---: | --- | --- |
| `+0x00` | `0xa002bf02` | 普通单字节写入内存日志 |
| `+0x04` | `0xa002bf02` | 强制单字节写入，复用同一入口 |
| `+0x08` | 空 | 不提供刷新入口 |
| `+0x0c` | `0xa002bf2c` | 批量写入内存日志 |
| `+0x10` | 空 | 不提供强制批量写入 |
| `+0x14` | 空 | 不提供通道关闭入口 |

`0xa002bf02..0xa002bf2a` 把单个输入字节放入栈上，再以长度 1 调用内存日志写入函数；
`0xa002bf2c..0xa002bf42` 保留原输入缓冲地址和长度，直接调用同一写入函数。两个入口都把
`gp+268`，即 `0x62fc35cc` 的内存日志设备作为目标。

操作顺序、两项写入入口和静态通道初值与原厂采用版本
[`syslog_channel.c`](https://github.com/apache/nuttx/blob/271f76590f22/drivers/syslog/syslog_channel.c)
中的 `g_ramlog_channel_ops` 和 `g_ramlog_channel` 逐项一致。

## 3. 两个系统日志通道的关系

镜像 `0x001be498..0x001be49f` 保存两个通道对象地址：

1. `0x62fc3e4c`，指向已在前文定义的默认系统日志通道；
2. `0x62fc3fa0`，指向本段内存日志通道。

`0xa0051ae6..0xa0051b8c` 和 `0xa012ea18..0xa012eaae` 都从这份两项地址表中取通道，
分别调用它们的操作入口。`0xa01b178e..0xa01b17c0` 依次查看两个通道的刷新入口；
两张表的该项都为空，所以不会额外调用函数。

## 4. 注册边界

`0xa00295e0..0xa00295f8` 把 `/dev/ramlog`、内存日志文件操作表和
`0x62fc35cc` 设备对象交给设备注册入口。该设备的容量、读者链表和读写规则只引用本文开头的唯一原文。

本段只是把系统日志通道连到该设备，它本身不是 `/dev/ramlog` 的文件节点，
也不证明内存日志会被持久化或通过无线链路发出。
