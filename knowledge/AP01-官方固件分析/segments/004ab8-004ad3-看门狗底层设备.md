# `0x004ab8..0x004ad3` 看门狗底层设备

返回总账：[`AP01 原厂固件逐字节与逐指令通读总账`](../原厂固件逐字节与逐指令通读总账.md)

芯片设备描述表的唯一定义原文：
[`0x003d04..0x003f83` 芯片设备描述表`](003d04-003f83-芯片设备描述表.md)

## 1. 覆盖结论

本段连续覆盖 28 字节，是 BL616 看门狗底层设备的完整静态对象。它保存七入口操作表、
上次重置计时时刻、60 秒超时值、运行标志、到期处理函数、芯片设备指针和中断号。

| 项目 | 值 |
| --- | --- |
| 文件范围 | `0x004ab8..0x004ad3` |
| 复制后的运行内存范围 | `0x62fc3fa4..0x62fc3fbf` |
| 初始超时 | 60,000 毫秒 |
| 初始状态 | 未启动，无到期处理函数 |
| 运行中断号 | 70 |
| 注册路径 | `/dev/watchdog0` |
| 连续覆盖字节 | 28 |

`0x004ad4..0x004ad7` 是后续待判定零值，看门狗所有底层入口都只访问到本对象
`+0x18`，而 `+0x18` 是一字节中断号与三字节对齐填充。因此本段在 `0x004ad3` 结束，
不提前为后续零值指定对象归属。

## 3. 七入口操作表

| 表内偏移 | 原始值 | 已证实职责 |
| ---: | --- | --- |
| `+0x00` | `0xa012d9a4` | 启动：写入超时值、启用硬件并保存当前计时值 |
| `+0x04` | `0xa012da76` | 停止：关闭硬件并清除运行标志 |
| `+0x08` | `0xa012da9a` | 保持运行：重置硬件计时并更新上次计时值 |
| `+0x0c` | `0xa012bfee` | 查询状态：返回运行标志、当前超时值和剩余时间 |
| `+0x10` | `0xa012dacc` | 设置超时：只接受 1..65,535 毫秒，同时重置硬件计时 |
| `+0x14` | `0xa012db4e` | 设置到期处理：在“到期复位”与“到期调用函数”之间切换 |
| `+0x18` | 空 | 不提供额外设备控制入口 |

七项顺序与原厂采用版本
[`watchdog.h`](https://github.com/apache/nuttx/blob/271f76590f22/include/nuttx/timers/watchdog.h#L113-L180)
的通用底层操作表一致。状态查询函数把本对象 `+0x08` 原样写入“当前超时毫秒数”，
并用当前计时值与 `+0x04` 的差计算剩余时间，因此 60,000 的单位不是推测。

## 4. 芯片连接和注册

`0xa0055c2a..0xa0055c68` 完成芯片侧连接：

1. 按名称 `watchdog` 查找芯片设备描述；
2. 把返回指针写入本对象 `+0x14`；
3. 打开对应芯片时钟通路。

该描述的寄存器起点是 `0x2000a500`，设备表中的外设中断值是 54；本对象实际交给中断登记入口的是 70。
两个值属于不同的编号层，本文分别记录，不把它们混为一个字段。

`0xa0055c6c..0xa0055ca8` 申请并初始化通用上层对象，把本段起点 `0x62fc3fa4`
写入上层对象，然后注册 `/dev/watchdog0`。失败时释放已申请的对象并记录错误。
通用上层的操作分发与原厂采用版本
[`watchdog.c`](https://github.com/apache/nuttx/blob/271f76590f22/drivers/timers/watchdog.c)
闭合。

## 5. 能力边界

本段证明默认 60 秒超时、启停、保持运行、状态查询、超时修改、到期处理切换和设备注册路径。
它不证明上层业务一定会打开或启动看门狗；实际业务调用须等顺序通读到调用方后再入账。
