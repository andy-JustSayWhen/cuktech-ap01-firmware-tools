# `0x004ae4..0x004c43` 蓝牙主机总状态对象

返回总账：[`AP01 原厂固件逐字节与逐指令通读总账`](../原厂固件逐字节与逐指令通读总账.md)

## 1. 覆盖结论

本段连续覆盖 352 字节，是原厂蓝牙主机保存本机控制器状态的完整静态对象。对象从本机身份地址开始，
依次保存建连参数、旧式广播状态、控制器版本和能力、初始化工作项、全局状态位、低功耗控制器状态、
三个发送额度同步量、最后发送的命令、命令发送队列和已登记的控制器驱动。

| 项目 | 值 |
| --- | --- |
| 文件范围 | `0x004ae4..0x004c43` |
| 复制后的运行内存范围 | `0x62fc3fd0..0x62fc412f` |
| 原厂对象名 | `bt_dev` |
| 身份地址容量 | 1 个，每个 7 字节 |
| 静态初始化函数 | `0xa00dd808` |
| 初始可发送控制命令数 | 1 |
| 初始控制器驱动 | 空，登记时写入 |
| 连续覆盖字节 | 352 |

对象内最后一条直接字段引用是运行地址 `0x62fc4128`，即对象 `+0x158` 的控制器驱动地址；
`0x004c44` 对应运行地址 `0x62fc4130`，从四个连续函数地址开始，且已经出现独立的直接引用。
因此本对象在 `0x004c43` 结束，不吞入下一份函数表。

## 3. 对象身份和初始化调用链

原厂指令给出以下闭环：

1. `0xa00d7182` 用身份编号乘 7，再加运行地址 `0x62fc3fd0`，证明对象起点是身份地址数组；
2. `0xa00da9c0` 从对象 `+0x07` 取身份地址数量；
3. `0xa00dd180`、`0xa00dd210`、`0xa00dd2ca` 分别把控制器返回的 8、64、8 字节能力数据写入本对象；
4. `0xa00dd300` 把控制器报告的数据长度写入 `+0x100`，随后以 `+0x104` 初始化对应额度同步量；
5. `0xa00dd808..0xa00dd826` 调用完整蓝牙初始化，再在回调非空时返回初始化结果；
6. `0xa00dc0f4` 读取 `+0x140` 的最后命令地址，`0xa00dcbbc` 等路径把命令放进 `+0x148` 队列；
7. `0xa00d66fc` 从 `+0x158` 取控制器驱动，再调用其发送入口。

这些访问次序与 Bouffalo Lab 官方仓库
[`hci_core.h`](https://github.com/bouffalolab/bouffalo_sdk/blob/master/components/wireless/bluetooth/blestack/src/host/hci_core.h)
中的本机控制器状态职责，以及
[`hci_core.c`](https://github.com/bouffalolab/bouffalo_sdk/blob/master/components/wireless/bluetooth/blestack/src/host/hci_core.c)
中的初始化、命令队列和驱动发送关系一致。对象前半部分的建连和旧式广播布局又与上游
[`Zephyr 2.5 hci_core.h`](https://github.com/zephyrproject-rtos/zephyr/blob/v2.5.0/subsys/bluetooth/host/hci_core.h)
对应。

两份公开源码的系统同步量和工作项大小都与本镜像采用的适配层不同，因此本文只用它们核准职责与顺序；
每个实际偏移、长度和静态值仍以本镜像指令和 352 字节原文为准。

## 4. 三个同步量和命令发送闭环

原厂适配层的同步量初始化入口 `0xa01a94ca` 把上限写到对象内 `+0x10`，再初始化前方
系统同步量；归还入口 `0xa0103ac8` 先比较当前计数和上限，未达到上限才真正归还。
这说明每份 28 字节区域不是普通零填充。

主机到控制器的数据包额度在读取控制器缓冲参数后按报告数量初始化。控制命令额度则在镜像中静态设为
“当前 1、上限 1”，允许发送第一条控制命令。发送线程从 `+0x148` 的队列取命令，取得 `+0x120`
的额度后发送，并把命令地址写到 `+0x140`；命令完成或状态事件到达后，完成路径读取该地址并归还额度。

## 5. 能力边界

本段证明蓝牙主机总状态的完整静态边界、各能力区、初始化工作、数据包和命令额度、命令队列及控制器驱动调用。
它不证明设备业务层启用了哪些服务，也不把全零能力初值当成运行时不支持；这些字段会在初始化读取控制器后覆盖。
`+0x144..+0x147` 和 `+0x15c..+0x15f` 没有足够直接证据，按原始零值保留，不为凑齐公开结构而猜名。
