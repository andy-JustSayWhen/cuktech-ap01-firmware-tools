# `0x004c58..0x004c83` 内存日志句柄、加密锁与时间日志配置

返回总账：[`AP01 原厂固件逐字节与逐指令通读总账`](../原厂固件逐字节与逐指令通读总账.md)

普通互斥量的 16 字节字段和静态初值唯一原文见
[`0x0040a4..0x0040b3` 文件区间锁保护互斥量`](0040a4-0040b3-文件区间锁保护互斥量.md)；
本文只确定两把锁的业务归属，不重复定义其内部字段。

## 1. 覆盖结论

本段连续覆盖 44 字节，依次由五份独立对象组成：

1. 一个待移除和关闭的内存日志文件描述符交接槽；
2. 一把加密引擎复用保护互斥量；
3. 一个全局日志等级阈值；
4. 一个时区秒偏移缓存；
5. 一把摘要引擎复用保护互斥量。

| 项目 | 值 |
| --- | --- |
| 文件范围 | `0x004c58..0x004c83` |
| 复制后的运行内存范围 | `0x62fc4144..0x62fc416f` |
| 对象数 | 5 |
| 连续覆盖字节 | 44 |

`0x004c84` 复制到运行地址 `0x62fc4170`，开始值是函数地址 `0xa01c042c`，
且 `0xa005a68e` 直接把 `0x62fc4170` 作为索引表起点。因此两把互斥量中的后一把在
`0x004c83` 结束，不吞入后方函数表。

## 3. 内存日志文件描述符交接链

`0xa008f3bc` 开始的内存日志工作入口使用运行对象 `0x62fcb1ac`。其对象
`+0xd4` 保存当前内存日志文件描述符，同一函数的日志原文直接包含
`ramlog_fd`、`ramlog exit` 和 `remove ramlog_fd`。

退出或解初始化时，`0xa008f44a..0xa008f478` 与 `0xa008faa4..0xa008fad4` 都执行：

1. 取当前内存日志描述符；
2. 把运行对象 `+0xd4` 置为 `-1`；
3. 把旧描述符写入本段 `0x62fc4144`。

`0xa005eabc..0xa005ead6` 随后读本槽；值大于 0 时，先从事件观察登记表移除它，
再调用文件关闭入口 `0xa0026788`，最后把本槽恢复为 `-1`。因此该槽用于跨处理路径
交接待回收的描述符，不是蓝牙连接句柄。

## 4. 两把硬件引擎锁

### 4.1 加密引擎锁

`0xa0057ccc..0xa0057eaa` 的文件名原文为 `chip/bl616_aes.c`。该入口先核对长度和模式，
准备密钥材料，再于 `0xa0057e00` 取得 `0x62fc4148` 的互斥量；完成引擎调用后，
`0xa0057e8e` 用同一地址释放它。取得失败时不进入硬件处理。

### 4.2 摘要引擎锁

`0xa005767a..0xa0057c62` 的文件名原文为 `chip/bl616_sha.c`。已定位的初始、更新和完成
入口均在进入摘要硬件前把 `0x62fc4160` 交给互斥量取得入口，完成后把同一地址
交给释放入口。固件为不同摘要长度申请 256 或 384 字节上下文，但共用这一把锁。

## 5. 日志等级与时区偏移

### 5.1 全局日志等级阈值

镜像中的大量日志路径先读取 `0x62fc4158`，把它与当前语句的固定等级比较，只有
通过阈值判定才调用 `0xa002dd70` 输出。例如 `0xa005cc70`、`0xa005cd8a` 和
`0xa009ed9e` 分别在不同业务路径中执行同样的全局判定。本段只证明静态阈值初值为 1；
原厂符号名未保留，不猜造具体变量名。

### 5.2 `gmt_offset` 秒偏移缓存

`0xa005cb70..0xa005cbd0` 先读本段 `0x62fc415c`。值非负时直接返回；值为 `-1` 时，
它从 `ot_config` 配置域读取键 `gmt_offset`，读得 4 字节后写入本缓存。取得值为 0 时，
该入口又把 `0x7080`，即 28,800 秒，写入输出和本缓存。`0xa0060ebe` 是直接更新缓存的
另一处写点。

## 6. 能力边界

本段证明了五份对象的静态初值、相互边界和主要读写链。日志阈值和时区偏移的下游使用
范围跨越大量后方函数；本文的地址反查只用于确定数据对象，不将后方函数提前标成已逐指令
通读。
