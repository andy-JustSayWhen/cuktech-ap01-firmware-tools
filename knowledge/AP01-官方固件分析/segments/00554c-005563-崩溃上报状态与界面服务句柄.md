# `0x00554c..0x005563` 崩溃上报状态与界面服务句柄

返回总账：[`AP01 原厂固件逐字节与逐指令通读总账`](../原厂固件逐字节与逐指令通读总账.md)

## 1. 覆盖结论

本段连续覆盖 24 字节，含六个四字节镜像初值。第一项是米家客户端崩溃信息上报的
返回状态锁存值；后五项是界面服务和工厂测试的状态与句柄。它们与后方从 `0x005564`
开始的另一张表有独立访问起点，因此本段在 `0x005563` 结束。

| 文件偏移 | 复制后的运行地址 | 四字节原值 | 已证明作用 |
| --- | --- | ---: | --- |
| `0x00554c` | `0x62fc4a38` | `-12` | `_otc.crash` 分块上报返回状态锁存值 |
| `0x005550` | `0x62fc4a3c` | `255` | 界面米家服务状态字，实际按有符号单字节读取 |
| `0x005554` | `0x62fc4a40` | `-1` | `/dev/gpio12` 工厂测试输出设备句柄 |
| `0x005558` | `0x62fc4a44` | `-1` | `/dev/gpio3` 工厂测试输入设备句柄 |
| `0x00555c` | `0x62fc4a48` | `-1` | `/mq_miio2lvgl` 米家到界面的接收队列句柄 |
| `0x005560` | `0x62fc4a4c` | `-1` | `/mq_lvgl2miio` 界面到米家的发送队列句柄 |

## 2. 崩溃上报状态锁存值

`0x62fc4a38` 的初值是 `-12`。`0xa006dade` 所在处理路径正在报告 `_otc.crash`：

1. `0xa006db0c..0xa006db46` 根据当前分块状态调用 `0xa019454a`，并把返回值写入此地址；
2. 返回值为零时，`0xa006dbca..0xa006dc34` 处理重试次数和下一分块；
3. 返回值非零且不是 `-12` 时，清理当前分块状态并把此地址恢复为 `-12`；
4. 重试超过上限时，`0xa006dc1c..0xa006dc2e` 同样写回 `-12`。

相邻日志原文包含 `_otc.crash failed`、`memory not enough for _otc.crash`和
`no memory for _otc.crash`。因此该值与崩溃上报的分块控制直接闭合，不是通用错误码全局值。

## 3. 界面米家服务状态字

`0x005550..0x005553` 的原始字节为 `ff 00 00 00`。实际代码只访问最低字节
`0x62fc4a3c`：

- `0xa00717b0..0xa00717ba` 在界面米家服务完成产品信息、位置信息和消息队列初始化后将它写为 1；
- `0xa00aa4be..0xa00aa51e` 把它作为有符号单字节读取，值非零时跳过一次
  `wifi_configured` 持久值刷新，然后返回缓存的无线网络已配置标志。

本镜像中的 255 和初始化后的 1 都为非零。当前指令只能证明上述分支事实；没有独立证据证明
255 与 1 分别对应两个不同业务状态，因此不进一步命名它们。

## 4. 工厂测试设备句柄

`0xa0071204..0xa0071294` 检查并打开 `/dev/gpio3`，把句柄写入 `0x62fc4a44`，随后读取引脚类型和
引脚值以决定是否进入工厂测试。`0xa007130e..0xa0071592` 在确认进入测试后检查并打开
`/dev/gpio12`，把句柄写入 `0x62fc4a40`，并通过设备控制请求切换输出值。

`0xa00ad598..0xa00ad6e6` 按工厂测试阶段反复读取 `0x62fc4a40` 并发送请求 `0x2301`，
请求的第三个参数在 0 和 1 之间切换。

## 5. 界面与米家的双向消息队列

| 运行地址 | 创建路径 | 关闭路径 | 数据方向 |
| --- | --- | --- | --- |
| `0x62fc4a4c` | `0xa0070df0..0xa0070e22` 使用名称 `/mq_lvgl2miio` 打开队列 | 当前已读区间未见直接关闭 | 界面发往米家服务 |
| `0x62fc4a48` | `0xa0071818..0xa007183e` 使用名称 `/mq_miio2lvgl` 打开队列 | `0xa00729e8..0xa00729fe` | 米家服务发往界面 |

`0xa00ad784..0xa00ad822` 从 `0x62fc4a4c` 读取句柄并向队列发送数据；
`0xa00aea9a..0xa00aeab6` 从 `0x62fc4a48` 读取句柄并接收最多 257 字节。创建名称、后续读写方向和
关闭路径一起确定了两个句柄的方向。

## 6. 能力边界

本段已对六个四字节镜像值全部归类，并与崩溃分块上报、界面米家服务初始化、工厂测试引脚
和双向消息队列的直接读写路径闭合。状态字 255 与 1 的独立业务含义因无直接比较分支而保留未定。
