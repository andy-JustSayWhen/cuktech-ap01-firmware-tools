# `0x0057dc..0x0057e3` 米家网络状态与天气重试间隔

## 1. 覆盖范围

- 原厂镜像：`ap01-1.0.2_0031.bin`
- 文件偏移：`0x0057dc..0x0057e3`
- 复制后运行地址：`0x62fc4cc8..0x62fc4ccf`
- 长度：8 字节
- 本段原始字节散列：`c9bee1f948c4b7ec7f1eaf0744b6e28888c055afa2f7a53a92e993f87e543baf`
- 运行地址换算：文件偏移加 `0x62fbf4ec`

本段是两个独立对象：前四字节只有首字节保存网络状态，后三字节为零填充；后四字节保存
天气请求重试间隔。两者相邻但没有共同访问入口。

## 3. 米家当前网络状态

`0xa00aa23c..0xa00aa4b2` 的原厂日志函数名是 `miio_network_status_change`，并打印
`network status change from %d to %d`。其输入就是新网络状态，完整变化路径为：

1. 从 `0x62fc4cc8` 读取旧值；新旧相同就直接返回；
2. 按新状态调整网络已配置标志；特定状态变化还触发恢复处理；
3. 按新状态更新计数数组并通知四类运行对象；
4. 在 `0xa00aa364` 把新状态以单字节写回 `0x62fc4cc8`。

后续实际读取点包括：

- `0xa00ad8c0` 在米家定时处理前判断当前网络状态；
- `0xa00b182c` 把它与界面联网标志一起写入日志；
- `0xa00b929a` 在通信收尾时据其是否为 0 选择不同状态值；
- `0xa00bba20` 的十轮一次维护路径仅在该值为 2 时执行一组在线维护。

这些调用证明它是共享网络状态缓存。镜像未保留初值 6 及各数值的枚举符号表，本文不把 6
改写成“离线”“云端在线”或其他文字状态。

## 4. 天气请求重试间隔

天气任务入口 `0xa00b6ca6` 的直接证据为同一函数中的原厂日志：

- `Failed to fetch weather data: %d`
- `Weather data fetched successfully, HTTP status: %d`
- `HTTP request failed with status: %d`
- `Weather data fetch failed, retry in %ld s`

其中 `HTTP（网页请求使用的通信规则）` 只出现在原厂日志原文；本文按其实际控制流判断成功和
失败，不用日志文本替代指令证据。

失败路径 `0xa00b6d0c..0xa00b6d5e`：

1. 读取 `0x62fc4ccc`；
2. 除以 1000 后用于打印下一次重试秒数；
3. 把当前毫秒值乘 2；
4. 若翻倍值超过 `7,200,000` 毫秒，就写成该上限，否则写回翻倍值。

成功路径 `0xa00b6f70..0xa00b6f82` 把同一地址重新写成 `0x7530`，即 30,000 毫秒，再
安排正常的下一次天气任务。调试输出 `g_retry_interval: %d` 也直接读取此地址。

所以原厂退避序列从 30 秒开始，连续失败时依次翻倍，最长 2 小时；任一次成功都会恢复到
30 秒初值。
