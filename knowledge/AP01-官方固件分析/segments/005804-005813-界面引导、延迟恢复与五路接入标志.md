## 3. 一次性旋钮切页提示

`j_sys_timer_update_timer_xcb` 的一条路径在 `0xa00b18de..0xa00b1908` 检查系统的首次
引导状态。状态有效时，它先把 `0x62fc4cf5` 置 1，再更新引导数据。

另一条同名定时路径 `0xa00bb684..0xa00bb708` 只在以下条件同时成立时消费该标志：

1. 当前页面类型为 8；
2. `0x62fc4cf5` 非零；
3. 原厂联网检查入口返回非零。

条件成立后，该路径取得编号 8 的界面对象，把文字更新为原厂中文
“旋转旋钮切换界面”，然后把 `0x62fc4cf5` 清零。所以该字节是待处理的一次性
界面提示，不是旋钮实时键值。

## 4. 屏保的辅助检测门禁

`j_update_screen_close` 和 `j_update_screen_saver` 两条原厂日志都把本字节作为
`adc_asst_flag` 输出。对应指令位于 `0xa00bbea2..0xa00bbf4c`：

- 从 `0x62fc4cf6` 读取单字节值；
- 息屏与屏保分支都要求该值非零才会继续累加计时；
- 当前已读指令范围内没有找到对该字节的动态写入，原厂镜像初值为 1。

本文保留原字段名与读取条件，不根据缩写自行指定它对应哪一种具体硬件检测。

## 5. 延迟恢复标志

`0x62fc4cf7` 与上一段的 `ota_flag` 成对读写：

- `0xa00bbb02..0xa00bbb2e` 在 `ota_flag` 非零且当前界面处于特定状态 3 时，
  将 `0x62fc4cf7` 置 1，同时把 `ota_flag` 清零；
- `0xa00bbd36..0xa00bbd82` 在该标志非零且当前界面已离开状态 3 后，
  取得末尾界面对象并复用原厂切换入口，然后把 `ota_flag` 置 1、本标志清零；
- 界面事件路径 `0xa00bc0c6..0xa00bc0d8` 会读取该标志，非零时跳过后续的
  屏保详情交互处理。

这些指令可以确认它是“进入特定状态时暂存、离开后恢复”的延迟标志。
镜像没有保留该字段的独立符号名，本文不把状态 3 进一步命名为某个具体页面。

## 6. 五路首次接入待处理标志

这五字节与上一段的五路接口数组使用同一个 0 至 4 下标。

`lv_dev_chg_first_and_light_up_screen` 路径的闭环为：

1. `0xa00b9fbc..0xa00b9fca` 发现本路上一次在线状态为零、本次非零；
2. `0xa00b9fd6..0xa00b9fe2` 点亮屏幕，并将 `0x62fc4cf8 + 下标` 置 1；
3. `0xa00ba0aa..0xa00ba172` 只在该字节为 1、全局初始化标志为 1，
   且当前接口记录允许时，进入原厂设备接入弹窗与数据更新分支；
4. 该分支完成后，`0xa00ba172..0xa00ba176` 将对应字节清零。

因此它们是按接口分开的一次性“新接入待处理”标志，不是持续的在线状态副本。
