## 3. 对象来源与字段准备

本段有两个独立来源：队列接收给出一条至少 44 字节的记录指针；`0x62fd8220` 则是描述对象
空闲单向链。取得空闲描述对象后，代码把记录前 40 字节复制到对象 `+0x04`，再单独读取记录
`+0x28` 的编号。编号既被转成待处理位图中的一位，也作为后续发送处理的第二参数。

复制完成后的本段直接写入如下字段：

| 描述对象偏移 | 写入值 |
| --- | --- |
| `+0x28` | 0 |
| `+0x38` | 0 |
| `+0x50` | 0 |
| `+0x54` | 复制所得 `+0x04` 基址再加 140 |
| `+0x58` | 同一基址再加 72 |

后续入口返回后，函数不在本段结束，而是回到 `0xa00056a6` 重新执行状态检查。空闲描述链取空
被原厂视为不可继续的内部错误，而不是普通返回：二进制保留了字符串和位置号 89，并进入
最终断言入口。

## 4. 能力边界

- 已闭合：120 个源字节、36 条指令、队列接收、空闲链取件、取空断言、40 字节复制、五项
  字段写入、八位位图置位、后续处理调用和循环回边。
- 队列记录的原厂结构体名称、编号的正式枚举名、描述对象全部字段名以及后续大型处理入口的
  原厂函数名尚未取得，本文不使用相似源码名称替代。
- 同一函数仍剩 `0x00676a..0x00679b` 的待处理位消费路径未闭合。
