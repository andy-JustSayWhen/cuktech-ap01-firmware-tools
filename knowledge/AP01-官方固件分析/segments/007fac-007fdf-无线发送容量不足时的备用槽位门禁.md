# `0x007fac..0x007fdf` 无线发送容量不足时的备用槽位门禁

返回总账：[`AP01 原厂固件逐字节与逐指令通读总账`](../原厂固件逐字节与逐指令通读总账.md)

本段处理前段主容量不足的情况。只有工作对象 `+0x43` 槽位编号仍小于 `+0x42` 上限、
工作对象 `+0x41` 不等于 `1`，且第二张索引表的容量仍不小于需求值，代码才把源对象与
描述对象指针写入候选对象的编号槽位，递增槽位编号后重新进入容量足够的提交路径。

- 执行地址：`0xa0006fac..0xa0006fdf`
- 长度：52 字节
- 本段原始字节散列：`0977e1135cfb7fdaa6f23f3a23ef4f403f62e103c7a18b7151847c1760b43494`

## 3. 备用槽位条件与写入

启用备用槽位必须同时满足：

1. `工作[+0x43] < 工作[+0x42]`；
2. `工作[+0x41] != 1`；
3. `第二容量值 >= 前段需求值`。

槽位基址为：

`候选对象 + 4 × 工作[+0x43]`

写入：

- `槽位基址 + 0x38 = 源对象指针`；
- `槽位基址 + 0x148 = 描述对象指针`；
- `工作[+0x43]` 字节加一。

任一门禁失败都转到已经闭合的 `0xa0006fa2` 回退路径。

- 第二张索引表、工作状态和槽位字段的正式业务名称尚无原厂定义证据。
