# `0x008090..0x0080d1` 无线发送两种终止状态准备与最终会合

返回总账：[`AP01 原厂固件逐字节与逐指令通读总账`](../原厂固件逐字节与逐指令通读总账.md)

本段闭合大型函数入口和中段保留的两种终止准备路径。第一种把路径标记设为 `0`，第二种从
`0xa00070ce` 把标记设为 `1`，随后共享初始化：描述对象 `+0x28` 字写 `1`、`+0x24`
半字写 `0x0101`。第二种路径还把 `+0x28` 改为 `5`，并可能按描述 `+0x1c/+0x2c`
改成“`+0x2c` 左移四位后合入 `7`”。最后调用 `0xa018a496` 并复用前段现场恢复代码返回。

## 3. 两种终止状态

第一种入口来自大型函数前方多处入口或模式门禁失败：

- `描述[+0x28] = 1`；
- `描述[+0x24] = 0x0101`；
- 调用 `0xa018a496(描述)`。

第二种入口来自入口候选节点判定失败：

- 先执行与第一种相同的共享初始化；
- 默认把 `描述[+0x28]` 改为 `5`；
- 若 `描述[+0x1c] & 3 == 3`，再改为
  `描述[+0x28] = (描述[+0x2c] << 4) | 7`；
- 调用同一函数。

调用后两条路径都跳到 `0xa0007068`，复用已经覆盖的现场恢复与返回序列。

## 4. 大型函数最终闭合

- `0xa0007090` 的直接来源包括入口编号、站点状态及模式门禁失败；`0xa00070ce` 的直接来源
  是入口候选节点判定失败。来源条件唯一原文见各前序分段。
- 下一条顺序指令 `0xa00070d2` 建立新的 `32` 字节栈帧，形成真实下一函数入口。
- 因此执行地址 `0xa0005c2e..0xa00070d1`、文件偏移 `0x006c2e..0x0080d1` 的大型函数
  已全部逐指令覆盖；两种终止路径、主体返回、返回后的所有分支尾和最终现场恢复均已闭合。
- `0xa018a496` 的函数本体尚未顺序到达，具体业务名称保持未定。
