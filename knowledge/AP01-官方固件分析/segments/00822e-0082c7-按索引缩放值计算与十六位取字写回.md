# `0x00822e..0x0082c7` 按索引缩放值计算与十六位取字写回

返回总账：[`AP01 原厂固件逐字节与逐指令通读总账`](../原厂固件逐字节与逐指令通读总账.md)

本函数按输入编号形成 `20 × 编号` 偏移，读取对象内两个半字和一个高半字，结合两个后方
函数的返回值计算无符号商。末尾把商乘 `910000` 后的低 32 位从第 16 位起取字，并把结果
写入 `对象 + 20 × 编号 + 24`。两个被调用函数均在尚未顺序通读的后方地址，本文只记录
已经由本函数直接证明的参数、返回值分支和算术关系，不给它们补业务名称。

## 3. 未识别原始指令的官方编码复核

原反汇编结果只把 `0xdf050577` 打印为原始四字节指令。对照
[`riscv/riscv-p-spec`](https://github.com/riscv/riscv-p-spec) 仓库提交
`cba718ab0cd218a80613405f3276cba5804f8bd4f` 的
`old-doc/P-ext-proposal.adoc` 中 `WEXTI（从寄存器对指定比特开始取一个 32 位字）` 编码：

- 位 `31..25 = 1101111`；
- 位 `24..20 = 10000`，即起始位 `16`；
- 源寄存器和目标寄存器均为 `a0`；
- 低七位操作码为 `1110111`。

四项与 `0xdf050577` 逐位一致。32 位环境下，偶数编号源寄存器 `a0` 与紧随其后的
`a1` 构成低、高寄存器对；本函数已在 `0xa0007296` 把 `a1` 清零。因此本处最终结果为：

`(商 × 910000 的低 32 位) 无符号右移 16 位`。

这也限定了证据边界：前一条普通乘法只保留低 32 位，不能把本处写成“完整 64 位乘积右移
16 位”。

## 4. 已闭合公式与能力边界

令：

- `i = 输入编号`；
- `A = 对象[20 × i + 20]` 的无符号半字；
- `B = 对象[20 × i + 22]` 的无符号半字；
- `H = 对象[244]` 这个字的高 16 位；
- `F = 0xa000761a(对象 + 20 × i + 12)` 的返回值；
- `G = 0xa0163d74(B)` 的返回值。

则第一项附加量 `D` 为：

- `G != 0`：`D = 0`；
- `G == 0` 且 `B[13:11] == 6`：`D = 330000 / H`；
- `G == 0` 且 `B[13:11] != 6`：`D = 218000 / H`。

最终写回：

`对象[20 × i + 24] = (低32位(((A × 1000) / (D + F)) × 910000)) >> 16`。

- 已闭合：154 个源字节、54 条指令、两次直接调用的参数与返回值用途、三路附加量公式、
  官方编码复核、最终写回地址和精确截断顺序。
- 本函数没有在无符号除法前显式检查 `H` 或 `D + F` 是否为零；调用方如何保证输入仍待
  后续调用链证据确认。
- `0xa000761a` 与 `0xa0163d74` 的函数体尚未到达顺序通读端点，本文不定义其业务语义。
- 对象各字段的正式业务名称尚无原厂结构定义证据。
