# `0x00a66e..0x00a6b3` 目标链偏移扣除与缺失节点取得

返回总账：[`AP01 原厂固件逐字节与逐指令通读总账`](../原厂固件逐字节与逐指令通读总账.md)

本段承接目标偏移不在当前节点容量内的路径。它把前段算出的“640 减目标节点 `+6`
半字”低 16 位写入当前目标节点 `+4`，并从剩余目标偏移中扣除。已有下一节点时，先把
下一节点 `+4`、`+8` 清零再推进；没有下一节点时，以入口第六参数调用固定函数取得新
节点并接到当前节点 `+0`。取得失败立即返回 `-12`；成功后推进并重新计算目标容量。
本段也包含整个大型函数共用的现场恢复返回尾。

## 3. 精确推进规则

令当前目标节点为 `D`、剩余目标偏移为 `T`：

`Q = 低16位(640 - 无符号半字(D + 6))`

当上一段的有符号差值门禁决定推进时，本段执行：

- `半字(D + 4) = Q`；
- `T = T - Q`；
- 若 `next = 字(D + 0)` 非零，写 `字(next + 4) = 0`、`字(next + 8) = 0`，再令 `D = next`；
- 若 `next == 0`，调用 `new = 0xa0009dd4(C)`；`new == 0` 时返回 `-12`，否则写 `字(D + 0) = new` 并令 `D = new`；
- 目标节点推进成功后回到 `0xa0009636`，以剩余目标偏移重新判定容量。

## 4. 能力边界

- 已闭合：70 个源字节、29 条指令、目标容量低半字提交、偏移扣除、已有节点清理推进、缺失节点取得、失败返回和共用恢复尾。
- `0xa0009dd4` 的函数本体位于后续尚未顺序覆盖区域；返回值被直接当作目标节点指针使用，可以确认接口结果类型，不能先行命名其内部取得方式。
- 已有下一节点路径清除的是两个完整 32 位字，因此同时覆盖其 `+4..+11` 八个字节；不得简化成只清两个半字。
- 当前大型函数的实际数据复制路径尚待后续闭合；下一顺序文件偏移为 `0x00a6b4`。
