# `0x00aed4..0x00af37` 目标节点裁减与分段长度重写

返回总账：[`AP01 原厂固件逐字节与逐指令通读总账`](../原厂固件逐字节与逐指令通读总账.md)

本段继续执行地址 `0xa0009e8e` 开始的大型分段链调整函数。当前段先配合
后方回跳遍历，把目标节点之后的剩余链断开，并调用已通读的 `0xa00099bc`
将剩余节点逐个转挂。随后将请求量先写入链头 `+8`，再沿现有链把每个节点
`+4` 半字重写为本节点承担量：节点 `+6` 半字与剩余请求量之和不大于
640 时使用剩余请求量的低 16 位，否则使用 `640 - 节点+6半字` 的低 16 位。
如果链先于剩余请求量用完，最后还会从链头 `+8` 中扣除未分配部分。

- 执行地址：`0xa0009ed4..0xa0009f37`

## 3. 精确裁减与重写

令目标节点数为 `T`，请求量为 `R`，当前节点 `+6` 半字为 `O`，本节点
承担量为 `L`：

1. 后方回跳路径把指针推进到第 `T` 个节点，并把该节点作为保留链尾；
2. 清零保留链尾 `+0`，将原第 `T+1` 个节点开始的剩余链交给 `0xa00099bc`；
3. 写 `字(链头+8) = R`，并以 `剩余 = R` 开始重写；
4. 若 `无符号(O + 剩余) <= 640`，则 `L = 低16位(剩余)`；否则
   `L = 低16位(640 - O)`；
5. 写 `半字(当前节点+4) = L`，执行 `剩余 = 低32位(剩余 - L)` 并推进到下一节点；
6. 剩余为零或链已空时，写 `字(链头+8) = 低32位(R - 剩余)`。

## 4. 能力边界

- 已闭合：100 个源字节、32 条指令、目标位置回接、断链、剩余链转挂、链头请求量
  写入、节点承担量公式、链推进、实际总量回写与共同返回。
- 本函数的返回寄存器没有在共同返回前设置成固定结果；可验证的成果是链和字段修改，
  不将返回寄存器当作稳定状态码。
- 节点数不足时的增链和通往当前裁减写入的回跳遍历，从下一字节 `0x00af38`开始。
