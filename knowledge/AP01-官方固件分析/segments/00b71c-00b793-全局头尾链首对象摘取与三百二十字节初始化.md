# `0x00b71c..0x00b793` 全局头尾链首对象摘取与三百二十字节初始化

返回总账：[`AP01 原厂固件逐字节与逐指令通读总账`](../原厂固件逐字节与逐指令通读总账.md)

本段是执行地址 `0xa000a71c` 开始的大型函数第一条对象取得路径。
原厂先在不改写入口第一参数寄存器的情况下调用 `0xa01b0f4e`，再读
全局头尾结构 `0x62fc6050` 的 `+0` 链首。链首为空时转入后方另一条
取得路径；非空时摘下当前首对象。

被摘对象 `+0` 指向空值时，原厂同时清零全局结构 `+0` 和 `+4`；
还有下一对象时，把全局结构 `+0` 改为下一对象，并清零新首对象
`+4`。随后把被摘对象 `+0/+4` 都清零，在不另行准备参数的情况下调用
`0xa003ba8c`，再把该对象整个 320 字节填零。

填零后的固定初始化为：字节 `+31=64`、字节 `+52=1`、字 `+112=0x4000`、
字 `+116=0x4000`；原厂还调用 `0xa019e558(对象+120, 0)`，再写
半字 `+90=536`。本段最后跳到后方共同返回尾，返回尾的指令将在
顺序到达时登记。

## 3. 头对象摘取规则

令全局头尾结构为 `Q=0x62fc6050`、原链首 `N=字(Q+0)`、
下一对象 `P=字(N+0)`：

- `N==0` 时转入后方另一条取得路径；
- `N!=0` 且 `P==0` 时，写 `字(Q+0)=0`、`字(Q+4)=0`；
- `N!=0` 且 `P!=0` 时，写 `字(Q+0)=P`、`字(P+4)=0`；
- 两种摘取都写 `字(N+0)=0`、`字(N+4)=0`。

## 4. 被摘对象初始化

1. 在不另行准备参数的情况下调用 `0xa003ba8c`；
2. 填零 `N+0..N+319`；
3. 写 `字节(N+31)=64`、`字节(N+52)=1`；
4. 写 `字(N+112)=0x4000`、`字(N+116)=0x4000`；
5. 调用 `0xa019e558(N+120, 0)`；
6. 写 `半字(N+90)=536`；
7. 跳到后方共同返回尾。

## 5. 能力边界

- 已闭合：120 个源字节、40 条指令、全局头尾结构、空与非空摘取、双指针清理、
  320 字节填零、五个固定初始化字段和两个后方调用的已准备实参。
- 全局结构 `+4` 在链只有一个对象时与 `+0` 一起清零，这证明它是与链尾
  一起维护的字段；具体业务名称保留未定。
- `0xa01b0f4e`、`0xa003ba8c` 和 `0xa019e558` 本体尚未按顺序覆盖，因此不命名效果。
- 全局链为空时的取得路径、后方共同返回尾和整个大型函数尚未闭合。
- 下一字节 `0x00b794` 开始后方候选链的节点筛选循环。
