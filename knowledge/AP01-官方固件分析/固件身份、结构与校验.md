## 2. 文件结构

| 位置 | 直接证据 | 结论 |
| --- | --- | --- |
| 文件开头 | `BFNP` | AP01 官方固件容器标识 |
| 文件头区域 | `FCFG`、`PCFG` | 存在固件和分区配置记录 |
| `0x1000` | 可解码的 32 位 RISC-V 指令 | 主程序入口位于 4KB 文件头之后 |
| 文件偏移 `0x4d47` | `njcuk.enstor.ap01` | 固件内嵌设备型号 |
| 文件尾 `0x67d400` | 恢复记录标记、文件长度、校验值 | 文件尾包含恢复校验记录 |

当前主程序按“运行地址 = 文件偏移 + `0x9ffff000`”映射。这个换算只对
`1.0.2_0031` 当前分析成立，版本变化后重新求证。

这些字符串证明固件的工程、构建日期和内嵌组件版本标识；它们不等同于实体产品标签。

## 5. 修改时的硬约束

1. 成品总字节数保持 6,804,520，除非新版本容器分析明确证明可变长度。
2. 保留 `BFNP` 文件头、分区配置和文件尾恢复记录格式。
3. 每次修改后重新计算并回写文件尾恢复校验值。
4. 保存全部修改区间；修改区间外必须与原厂基线逐字节一致。
5. 不凭文件名判断版本，必须同时核对型号、字节数和两个文件指纹。
6. 不把当前偏移直接用于其他版本。
