# AP01 离线恢复与救砖证据

返回主文档：[`AP01 官方固件分析`](AP01-官方固件分析.md)

调查日期：2026-07-27

## 1. 调查范围与当前结论

本调查交叉核对了 AP01 `1.0.2_0031` 原厂文件、参考项目真机记录、`MHCWB9B-B`
无线模组认证资料，以及博流 `BL616/BL618` 芯片家族的官方工具和源码。不同证据层级不得
相互替代。

网页深度研究只用于扩大检索范围，不作为事实来源。写入本文的外部结论必须能回到表中的
厂商资料或源码；模型中间结论没有一手来源支持时一律舍弃。

当前可以成立的结论：

1. 原厂 `BFNP` 文件是 AP01 在线更新使用的应用固件容器，不是已经证明包含整片闪存内容的
   离线救砖镜像；
2. 原厂程序包含双槽、更新和恢复代码，但 AP01 的实际分区地址、第二阶段启动程序版本、
   自动回退触发条件和失败次数仍未真机确认；
3. 博流官方工具对 `BL616/BL618` 芯片家族提供串口、调试器、读取、写入和擦除能力；
4. `MHCWB9B-B` 模组资料只确认主要芯片、供电和模组接口类型，没有提供 AP01 主板测试点
   接线；
5. 参考项目已证明一台 AP01 可以通过米家在线更新路径安装第三方固件，但没有完成同机原厂
   回刷，也没有证明设备无法启动或联网时的恢复通道；
6. **未找到 AP01 专属硬件恢复证据**，包括可复查的下载模式进入方法、主板焊盘定义、串口
   接线、调试口接线或外置闪存恢复记录。

所以，现阶段不得把芯片开发板的能力写成 AP01 已具备能力，也不得把原厂 `BFNP` 文件写成
“完整救砖包”。首次实验安装继续受
[`固件制作规范`](../../reference/固件制作规范.md) 的独立恢复门禁阻塞。

## 2. 术语与恢复层级唯一原文

本节是以下术语和层级在本项目中的唯一定义位置，其他文档只引用，不重复定义。

### 2.1 固件与接口术语

- **应用更新包**：由正常运行的 AP01 通过在线更新流程接收和安装的 `BFNP` 文件。
- **全闪存备份**：从同一台设备的实体闪存地址零开始，按已经确认的真实容量逐字节读出的
  完整内容；它应保留启动、分区、应用、资源、校准和设备专属数据，但具体组成仍须由 AP01
  实测分区图确认。
- **Boot ROM（芯片出厂时已经固化、应用损坏后仍会先运行的启动程序）**：芯片上电后最早
  执行且不能被普通刷写覆盖的代码。
- **Boot2（片上启动程序之后继续选择并装载应用的第二阶段启动程序）**：位于可写闪存内，
  写错后可能导致所有应用槽都无法启动。
- **UART（用收发两根信号线传数据的串行接口）**：博流工具支持的一种下载通道。
- **JTAG（调试器直接控制和观察芯片的调试接口）**：需要时钟、模式和数据线的芯片调试
  通道。
- **eFuse（写入后通常不能恢复的一次性芯片配置位）**：可控制安全启动、调试和版本限制；
  本项目禁止写入。
- **FlashCube（博流官方固件读写工具）**：当前官方资料中支持 `BL616/BL618` 读取、写入、
  擦除和一次性配置操作的电脑工具。
- **bouffalo_isp（博流面向 Linux（常见的开源电脑系统）主机的串口烧录程序）**：需要产品自行配置启动与复位
  信号，只接收组合后的完整烧录文件，不提供已经查到的备份读回说明。

### 2.2 恢复层级

| 层级 | 通道 | 是否依赖优化固件正常启动和联网 | AP01 当前状态 |
| --- | --- | --- | --- |
| R0 | 正常运行设备通过米家在线更新回刷匹配原厂应用更新包 | 是 | 路径存在，同机回刷未验证 |
| R1 | 设备自身的双槽自动回退或厂家恢复逻辑 | 不一定 | 代码存在，触发条件未验证 |
| R2 | 进入芯片固化启动程序后通过串口恢复 | 否 | 芯片家族支持，AP01 接口未找到 |
| R3 | 拆机后通过芯片调试接口恢复 | 否 | 芯片家族支持，AP01 接口未找到 |
| R4 | 外置闪存编程器、芯片返修或厂家售后恢复 | 否 | AP01 闪存型号、接线和镜像布局未确认 |

R0 只能处理设备仍能启动、联网并响应更新命令的故障。R2、R3 或 R4 中至少一种必须在专用
测试设备上完成恢复演练，才能满足“独立恢复通道已经实测”的安装门禁。

## 4. 原厂文件能证明和不能证明的恢复事实

### 4.1 已复核

- 文件字节数、两个文件指纹、`BFNP` 文件头和文件尾恢复记录均与
  [`固件身份、结构与校验`](固件身份、结构与校验.md) 一致；
- 文件头安全配置字按官方结构解释时，签名类型和加密类型字段为零，
  `crc_ignore` 与 `hash_ignore` 位为一；
- 文件头自身保存的校验值与重新计算结果一致；
- 文件内未检出博流分区表的 `BFPT` 标记；
- 文件字符串含两个固件槽、当前槽、更新槽、一次性配置设备和启动失败处理相关名称。

文件头字段结构的交叉核对来源为
[官方启动头结构](https://github.com/bouffalolab/bouffalo_sdk/blob/b3c904b47ec0f8487c3b640553cee582b1597925/examples/boot2_isp/port/bl616/bflb_port_boot2.h#L217-L289)。

### 4.2 严格边界

- 文件头字段只能说明该文件怎样声明自身，不能读出 AP01 芯片内的一次性配置；
- 文件字符串只能证明相关代码或名字存在，不能证明真实分区地址和自动回退已经启用；
- 未检出 `BFPT` 标记不能证明设备没有分区表，只能证明当前应用更新包不能作为分区表备份；
- 当前没有证据说明 `BFNP` 文件偏移如何映射到物理闪存，也没有证据说明文件尾恢复记录
  是否会原样写入闪存；
- 当前一手资料没有确认 AP01 或目标模组使用 `GPIO2` 进入下载模式；本次只证实它出现在
  一份芯片家族默认调试映射中，因此不得把它写成 AP01 启动选择脚；
- 量产工具手册中的 `GPIO21`、`GPIO22` 和按键时序属于指定开发板示例，不是 AP01 测试点
  定义；
- 文件尾恢复校验通过只能排除该容器的部分损坏，不能证明新增代码一定可启动；
- 原厂应用更新包不能替代同一设备的全闪存备份。

## 5. 现有制作保护的能力边界

| 保护措施 | 能降低的风险 | 不能证明或防止 |
| --- | --- | --- |
| 固定文件长度和身份指纹 | 错版本、截断文件、误用其他设备固件 | 新增指令语义正确、设备一定启动 |
| 修改前旧字节断言 | 地址漂移、错误版本、同一位置被其他工具改过 | 目标修改本身安全 |
| 修改区间外逐字节一致 | 意外覆盖未申报区域 | 已申报区域不会破坏控制流、内存或时序 |
| 重算文件尾恢复校验 | 容器校验因合法修改而不一致 | 启动程序接受、应用能运行、可离线恢复 |
| 先执行仅下载校验 | 设备仍在线时的传输、下载和文件校验问题 | 切槽后能启动、自动回退会发生；AP01 写入目标未证实时也不能排除它覆盖原有回退槽 |
| 同一冻结成品安装 | 校验后成品被替换或重新构建 | 成品中的逻辑没有缺陷 |
| 不修改启动、联网和更新路径 | 减少直接破坏现有恢复路径的概率 | 新代码崩溃、越界或耗尽资源不会间接破坏这些路径 |
| 固件中存在双槽与恢复代码 | 说明继续调查回退机制有依据 | AP01 已启用自动回退、失败次数和回退条件 |

这些措施是完整性和变更范围门禁，不是“不会变砖”证明。恢复能力必须由独立恢复演练另行
取得。

## 6. 独立恢复通道的验证证据

### 6.1 只读识别

拆机或接线前必须取得单独授权，并在专用测试设备上完成：

1. 拍摄外壳、主板正反面、板号、全部测试点和芯片丝印；
2. 断电后用通断测量确认地线，不按排列或颜色猜测；
3. 设备正常供电时只用高阻测量确认各候选点电压；
4. 用逻辑分析仪被动观察上电和复位波形，不从电脑向未知点送电；
5. 把观测波形与厂商资料交叉核对后，才给测试点命名；
6. 信号电平、启动选择方法和复位方法任一未确认时停止。

### 6.2 备份

只有在接口、真实闪存容量和读取范围已经确认后才允许读取：

1. 第一次完整读取保存为只读文件；
2. 设备重新断电、接线复核后再完整读取一次；
3. 两份文件逐字节一致，且两个文件指纹分别一致；
4. 记录工具版本、接口、电平、闪存身份、容量、读取范围和供电限制；
5. 备份保存在仓库外的两个独立位置，不提交到版本控制。

两次一致读取只证明“可以稳定读回”，仍不证明“写回后可以启动”。

### 6.3 恢复演练

恢复演练必须使用专用测试设备和该设备自己的备份，并另行取得当次写入确认：

1. 先证明 R0 原厂应用更新包回刷可用；
2. 再证明 R2、R3 或 R4 中至少一条通道能在应用不运行时识别芯片；
3. 取得 AP01 真实分区图并区分第二阶段启动程序、两份分区表、应用槽、资源、校准和设备
   专属数据；
4. 优先只恢复已经确认的非当前应用槽，不使用芯片家族示例地址；
5. 写后完整读回比对，再复位启动；
6. 验证原厂页面、联网、米家通信、设备身份和官方更新；
7. 保存从故障状态到原厂状态的完整记录。

在整片布局未确认前，禁止整片擦除、从地址零写入应用更新包、写入其他设备备份或尝试一次性
配置。

## 7. 强制禁止项

以下操作不得用于探索性试错：

- 执行整片擦除；
- 把 `BFNP` 应用更新包写到物理地址零；
- 套用开发板分区地址或示例配置；
- 写入或擦除第二阶段启动程序、分区表、校准区、设备身份区和密钥区；
- 写入一次性配置、防降级版本、安全启动配置或调试密码；
- 未测电平就把电脑串口或调试器连接到未知焊盘；
- 反复短接未知测试点、连续断电重启或重复下发写入命令；
- 用另一台 AP01 的全闪存备份覆盖当前设备。

FlashCube 使用指南同时提供读取、写入、擦除和一次性配置能力。当前 AP01 调查只允许将其
读取能力用于受控验证；界面中出现某个功能不等于该功能已获准执行。
