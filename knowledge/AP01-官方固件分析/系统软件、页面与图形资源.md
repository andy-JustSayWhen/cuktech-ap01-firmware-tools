# AP01 系统软件、页面与图形资源

返回主文档：[`AP01 官方固件分析`](AP01-官方固件分析.md)

## 1. 系统软件

固件中存在以下直接组件证据：

| 组件 | 在设备中的作用 |
| --- | --- |
| NuttX | 任务、设备、文件系统和命令环境 |
| NSH | NuttX 自带的设备命令环境 |
| LVGL | 绘制屏幕页面、控件、动画和图片 |
| libuv | 处理异步任务、定时和网络事件 |
| mbedTLS | 加密、证书与安全网络连接 |
| `miio-client 4.0.4.1` | 米家设备通信 |

固件启动应用记录包括 `lvgl_ui_main`、`mible_mesh_common_bt` 和 `miio_client`，
分别对应图形界面、米家蓝牙相关任务和米家设备通信。

## 2. 文件系统与配置

固件包含只读文件系统、临时文件系统、FAT 文件系统和 LittleFS。直接路径包括：

- `/etc`
- `/data`
- `/resource`
- `/data/sysconfig.bin`
- `/data/wapi.conf`

`/data/sysconfig.bin` 的原厂持久化字段包括：

- `ShowType`
- `TimeShowType`
- `ScreenSave`
- `ScreenOff`
- `ScreenBackLight`
- 配置校验值

固件含 `SysSettingsInit`、`SysSettingsWrite`、`sysconfig.bin Reset` 和
`FactoryRestore` 相关代码。由此确认原厂设置会写入设备闪存，恢复出厂设置会重置系统设置。

当前字段中没有一级页面显隐配置。

### 4.1 原厂界面生成方式

本节是原厂界面生成方式的唯一说明，其他文档只引用本节。

原厂界面采用控件与图片资源混合生成：

1. 时钟、功率、天气、日历、设置和虚拟形象分别有页面创建入口，由窗口管理代码加入一级
   页面并切换；
2. 菜单和详情页在设备运行时创建页面、文字、列表、滚轮、开关、复选框等独立元素，设置
   文字、尺寸、位置和事件处理；系统设置列表的创建循环、实际项目数读取、按序号取得列表
   元素和选择切换也都发生在设备运行时；
3. 静态图和动图作为独立图片元素载入。天气图标、数字、功率仪表等可作为页面局部素材，
   虚拟形象、操作引导和屏幕保护等页面可以使用完整画面的图片或动图；
4. 实时数值、文字、当前选择和开关状态由设备代码更新，不需要为每次变化重新生成一张
   完整页面图片。

因此，原厂菜单不是把一张固定底图与所有实时文字预先合成为完整画面后再显示；也不是全部
由设备即时绘制而不使用图片。每一页具体使用多少独立元素、局部图片或完整画面资源，仍需
按页面继续反汇编或在真机运行时核对，当前静态证据不能替代逐页源码。

AGENTS 看板采用的服务端成品画面方案只见
[`AP01 1.0.2_0031 优化固件 DESIGN` 第 7.2 节](../../reference/DESIGN/AP01-1.0.2_0031-opt.bin.md#72-成品画面)，
不得用该方案反推原厂页面实现。

## 5. 图形资源统计

对完整固件逐字节扫描并实际解码：

| 格式 | 扫描结果 |
| --- | --- |
| PNG | 200 个文件头，其中 199 个可完整解码，1 个是程序数据中的偶合字节 |
| GIF89a | 10 个可完整解码 |
| JPEG（常见照片格式） | 未找到可解码资源 |

199 张 PNG 中，195 张带有可识别的 LVGL 资源描述，声明数据总量为 639,058 字节；
另外 4 张是连续存放的可解码资源。图片包括品牌标志、二维码、天气图标、数字、功率仪表、
操作引导和完整页面。

## 6. 对第三方画面的直接约束

1. AP01 设备画面必须按 320×240 制作。
2. 原厂软件直接具备 PNG 和 GIF 解码能力。
3. 参考项目当前真机加载链路只验证了 GIF89a、320×240、至少两帧。
4. 参考项目的 256KB 是当前网络接收和三个临时内存槽的实现限制，不是原厂解码器上限。
5. 采用 PNG 静态资源、不同动图体积或新的内存布局前，必须完成设备端加载实现与真机验证。

案例证据：[`2026-07-25 全量静态分析记录`](cases/2026-07-25-1.0.2_0031全量静态分析.md)
