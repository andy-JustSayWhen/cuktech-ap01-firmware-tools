# AP01 通信、存储、更新与恢复

## 1. 无线与云端通信

固件直接包含：

- Wi-Fi 客户端、WPA（无线网络接入保护规则）和 Wi-Fi 6 相关代码；
- BLE 配网、GATT（低功耗蓝牙交换数据的规则）、快速配对和米家蓝牙网关任务；
- 米家设备通信客户端；
- 天气服务安全网络请求；
- 在线更新命令、状态和进度处理。

固件明确记录接入点模式未包含，因此当前原厂程序按 Wi-Fi 客户端方式接入现有无线网络，不负责创建供电脑连接的无线热点。

天气服务地址为：

- `https://iot.cuktech.net/api/weather2?`
- `https://iot.cuktech.net/api/weather?`

请求参数包含令牌和设备网络地址。知识文档只记录字段存在，不记录任何真实设备值。

## 2. 米家通信和在线更新

固件包含：

- `miIO.ota`
- `miIO.ota_install`
- 下载、校验、安装、状态和进度处理；
- 小米在线服务主机记录；
- 安装完成后的重启流程；
- 降级检查。

原厂标准在线更新路径含禁止降级的判断。第三方工具不能把“云端接受命令”当成“设备已经完成安装”，必须继续验证下载、安装、重启、运行时间和重新上线。

### 2.1 `miIO.ota` 端到端行为（2026-08-19 实测）

静态字符串证据（官方固件 `1.0.2_0031` 二进制直接提取）：

| 文件偏移 | 字符串 | 说明 |
| --- | --- | --- |
| `0x1c5544` 附近 | `app_url`、`app_hostip_list`、`app_hostip`、`cert_verify`、`verify`、`optional`、`signed_file`、`original_length`、`partial_enable`、`app_force` | `miIO.ota` 参数解析区完整键名列表；没有 `install`、`proc`、`mode` 键，这三个键被设备忽略 |
| `0x1c5680` 附近 | `[%s] %s: auto enable: %d, force enable: %d`、`[%s] %s: busy`、`[%s] %s: downgrade disabled, ota error...`、`downgrade error` | 设备端存在强制开关、忙检查和降级检查 |
| `0x52a200` 附近 | `[%s] %s: downgrade_config = %d`、`[%s] %s: downgrade params error` | 降级开关是配置项 |
| `0x52a26d` 附近 | `ota.downgrade`、`ota_install`、`miIO.ota_install` | 设备注册的另外两个更新相关方法名 |

分层拒绝行为（按请求经过顺序）：

1. **云端桶白名单**（`home/rpc` 转发层，同步返回）：`app_url` 路径第一段（桶名）不在白名单时，返回 `{"code": -1, "message": "ota bucket not permit"}`，请求不到达设备。实测 `app-user-music`（`home/genpresignedurl` 的默认桶）被拒；`miio_fw`（官方固件桶，见 `home/latest_version` 返回的 URL）通过。局域网 `http://` URL 同样被此层拒绝。
2. **设备端协议限制**（设备收到命令后）：`app_url` 为 `http://` 时设备返回 `error.code=-30000 "sys undefined error."`，不发起连接——OTA 下载强制 HTTPS。
3. **设备端证书校验**（TLS 握手阶段）：自签证书默认被拒，`ota_error` 记录 `TLS Open Failed, -0x2700, <host>`（mbedTLS 的 `X509_CERT_VERIFY_FAILED`）。 `miIO.ota` 带 `"cert_verify": "optional"` 参数后，设备接受自签证书并完成下载。
4. **同版本重刷**：`app_url` 指向官方同版本固件时不带 `app_force` 也能被接受并完成安装（实测官方 `1.0.2_0031` 重刷官方 `1.0.2_0031` 成功），说明降级检查不拦截相同版本。向同版本第三方固件推送时带 `app_force: 1` 可用。

成功推送第三方固件的完整参数组合（实测 2026-08-19）：

| 参数 | 值 | 作用 |
| --- | --- | --- |
| `app_url` | `https://<本机局域网 IPv4>/miio_fw/<固件文件名>` | 路径第一段 `miio_fw` 通过云端桶白名单；HTTPS 满足设备协议要求；本机 443 端口用自签证书（CN 可任意）提供固件文件 |
| `cert_verify` | `"optional"` | 跳过设备端证书链校验，接受自签证书 |
| `app_force` | `1` | 强制刷入（同版本重刷场景） |
| `file_md5`、`signed_file`、`original_length` | 固件 MD5、`false`、文件字节数 | 设备端下载校验 |
| `app_hostip` / `app_hostip_list` | 实测被设备忽略 | 设备仍直连 `app_url` 的 host；不可用于引流 |

设备收满 `Content-Length` 字节数后立即断开连接，服务端在写缓冲残余数据时会看到 `SSLEOFError`，这不代表下载失败；成功与否以 `ota_error` 无新记录、设备重启（`miIO.info` 的 `life` 重新计数）和 `miIO.get_ota_state` 回到 `idle`/`progress=101` 判断。

## 3. 本地存储

固件包含串行闪存、分区管理和闪存块设备。确认的用途包括：

- `/data`：系统设置和联网配置；
- `/resource`：图形资源；
- `/etc`：只读系统内容；
- `/dev/fw1`、`/dev/fw2`：两个固件槽；
- `/dev/reserve`：保留区；
- `/dev/ota`：在线更新设备接口。

系统属性包含：

- `ro.boot.current_slot`
- `ro.boot.update_slot`

这证明程序区分当前运行槽与待更新槽。

## 4. 更新与恢复机制

固件直接包含：

- 两个固件槽的读取和写入接口；
- 更新槽选择；
- 自动恢复代码；
- 恢复版本、恢复次数和恢复校验；
- 文件尾恢复记录；
- 下载文件校验和安装状态。

严格结论如下：

1. 固件代码中存在双槽更新和恢复机制。
2. 文件尾恢复记录的长度与校验值已离线复算一致。
3. 参考项目已完成第三方固件安装验证。
4. 本项目尚未完成指定设备的官方固件回退实测。
5. 在第 4 项完成前，发布文案只能写“具备官方固件安装路径”，不能写“一键回退已经可靠”。

## 6. 刷机验收证据链

正式安装必须按以下证据链验收：

```mermaid
flowchart LR
    A["官方来源与文件指纹一致"] --> B["修改范围与恢复校验通过"]
    B --> C["同一固件仅下载校验通过"]
    C --> D["用户本次确认安装"]
    D --> E["下载完成并进入安装"]
    E --> F["设备重启，运行时间重新计数"]
    F --> G["设备重新上线"]
```

任何一项缺失都不能宣布刷机成功。

## 7. 天气任务首次取数条件

原厂首次取数调用链如下：

| 位置 | 直接行为 |
| --- | --- |
| `0xa00b13fe` | 取消 `0x62fca9a8` 上的原任务，再以 `2000` 毫秒调用首次调度入口 |
| `0xa01aa812` | 把回调 `0xa00b6ca6` 和延时写入原厂定时任务 |
| `0xa00b6ca6` | 执行天气取数，成功或失败后经 `0xa009b3b6` 再次预约自身 |

天气任务在 `0xa00b6dd4` 调用 `0xa00acbea` 取得九位数字形式的位置编号。成功返回 `1` 时继续组装请求；失败返回 `0` 时进入城市后备分支。后备分支必须同时满足：运行时间超过 `100000` 毫秒，并且 `0x62fca650 + 68` 或 `0x62fca650 + 132` 至少一个文本字段非空。条件不满足时，本轮不创建网络请求，只按原厂失败间隔再次预约。

因此，替换网络执行点不会自动绕过首次取数的位置前置条件。复用原厂天气任务时，只能在 `0xa00b6dd4` 替换位置取得函数；原厂定时任务、网络状态、调用时机和失败重试必须保留。
