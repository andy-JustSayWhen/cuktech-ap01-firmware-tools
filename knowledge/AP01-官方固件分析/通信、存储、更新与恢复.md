# AP01 通信、存储、更新与恢复

返回主文档：[`AP01 官方固件分析`](AP01-官方固件分析.md)

## 1. 无线与云端通信

固件直接包含：

- Wi-Fi 客户端、WPA（无线网络接入保护规则）和 Wi-Fi 6 相关代码；
- BLE 配网、GATT（低功耗蓝牙交换数据的规则）、快速配对和米家蓝牙网关任务；
- 米家设备通信客户端；
- 天气服务安全网络请求；
- 在线更新命令、状态和进度处理。

固件明确记录接入点模式未包含，因此当前原厂程序按 Wi-Fi 客户端方式接入现有无线网络，
不负责创建供电脑连接的无线热点。

天气服务地址为：

- `https://iot.cuktech.net/api/weather2?`
- `https://iot.cuktech.net/api/weather?`

请求参数包含令牌和设备网络地址。知识文档只记录字段存在，不记录任何真实设备值。

## 2. 米家通信和在线更新

固件包含：

- `miIO.ota`
- `miIO.ota_install`
- 下载、校验、安装、状态和进度处理；
- 小米在线服务主机记录；
- 安装完成后的重启流程；
- 降级检查。

原厂标准在线更新路径含禁止降级的判断。第三方工具不能把“云端接受命令”当成“设备已经完成
安装”，必须继续验证下载、安装、重启、运行时间和重新上线。

## 3. 本地存储

固件包含串行闪存、分区管理和闪存块设备。确认的用途包括：

- `/data`：系统设置和联网配置；
- `/resource`：图形资源；
- `/etc`：只读系统内容；
- `/dev/fw1`、`/dev/fw2`：两个固件槽；
- `/dev/reserve`：保留区；
- `/dev/ota`：在线更新设备接口。

系统属性包含：

- `ro.boot.current_slot`
- `ro.boot.update_slot`

这证明程序区分当前运行槽与待更新槽。

## 4. 更新与恢复机制

固件直接包含：

- 两个固件槽的读取和写入接口；
- 更新槽选择；
- 自动恢复代码；
- 恢复版本、恢复次数和恢复校验；
- 文件尾恢复记录；
- 下载文件校验和安装状态。

严格结论如下：

1. 固件代码中存在双槽更新和恢复机制。
2. 文件尾恢复记录的长度与校验值已离线复算一致。
3. 参考项目已完成第三方固件安装验证。
4. 本项目尚未完成指定设备的官方固件回退实测。
5. 在第 4 项完成前，发布文案只能写“具备官方固件安装路径”，不能写“一键回退已经可靠”。

## 5. 当前未发现的传输路径

在 `1.0.2_0031` 原厂固件中：

- 未发现通过 BLE 传输第三方固件或实时页面的实现；
- 未发现供普通用户从 AP01 屏幕外露接口直接刷机的实现；
- 未发现参考项目 `HTTP 8765` 实时画面服务的原厂实现。

`HTTP 8765` 实时画面获取属于参考项目加入的第三方功能，不得写成原厂通信能力。

## 6. 刷机验收证据链

正式安装必须按以下证据链验收：

```mermaid
flowchart LR
    A["官方来源与文件指纹一致"] --> B["修改范围与恢复校验通过"]
    B --> C["同一成品仅下载校验通过"]
    C --> D["用户本次确认安装"]
    D --> E["下载完成并进入安装"]
    E --> F["设备重启，运行时间重新计数"]
    F --> G["设备重新上线"]
    G --> H["米家、原厂页面、新功能逐项验收"]
```

任何一项缺失都不能宣布刷机成功。
