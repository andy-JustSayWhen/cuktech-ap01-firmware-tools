# 刷机失败案例及解决办法

本文记录已经用真机复现并解决的刷机失败；每个案例写清症状、原因、处理方法和完成依据。刷机时先按 [`如何刷机`](../SOP/如何刷机.md) 执行，安装命令和参数以 [`AP01 刷机安装`](../reference/DESIGN/AP01刷机安装.md) 为准。

## 案例：设备立即拒绝网络升级，返回 `code=-1`

### 症状

项目刷机命令 `firmware-install`（项目内负责上传、回读和下发安装的命令）在固件回读后立即报：

```text
AP01 未接受 OTA：code=-1
```

`OTA`（设备通过网络接收固件更新的方式）未开始下载，设备状态仍是 `idle`（空闲），运行时间没有重新计数。

### 原因

未提供 `--ota-url` 的旧上传方式会把文件放到小米云不允许用于更新的下载位置。云端在转发 `miIO.ota`（让设备开始网络升级的指令）前检查下载地址的第一段路径，因此直接返回 `code=-1`，请求没有到达 AP01。

### 处理方法

1. 停止本次失败安装；保留安装记录，不重复下发。
2. 确认目标固件、设备状态和唯一 AP01 均未变化。
3. 在刷机电脑的局域网地址上启动临时加密固件服务：

   ```powershell
   .venv\Scripts\python.exe tools\ota_https_serve.py --firmware "<固件路径>"
   ```

4. 用路径首段为 `miio_fw`（云端允许转发的固件下载路径）的地址安装，并允许设备使用临时证书：

   ```powershell
   .venv\Scripts\python.exe app\ap01_firmware.py firmware-install `
     --firmware "<固件路径>" `
     --env-file env\mi-cloud.env `
     --ota-url "https://<本机局域网IPv4>/miio_fw/<固件文件名>" `
     --self-signed-ota
   ```

5. 命令先从该地址完整回读固件并逐字节核对；核对通过后才会下发一次安装。
6. 等待设备完成下载、安装、重启和重新上线；完成后停止临时固件服务。

实际设备地址和服务端地址仅保存在 `env/` 的本机配置中，不写入文档、代码或提交记录。

### 本次完成依据（2026-08-20）

- 原厂 `ap01-1.0.2_0031.bin` 与小米云当前版本和文件指纹一致。
- AP01 已请求 `env/` 本机配置中声明的固件服务地址，服务完整发送 6,804,520 字节。
- 设备状态依次显示下载进度 17%、38%，随后回到空闲。
- 运行时间从 5,676 秒重新计数为 17 秒，证明设备已经重启；之后查询不到新的升级错误。

### 完成标准

只有同时看到固件地址完整回读一致、设备实际请求固件、下载或安装状态、运行时间重新计数、重新上线和无新升级错误，才算解决本案例。还应按 SOP 完成原厂页面和米家通信的肉眼验收。
