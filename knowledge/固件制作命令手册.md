# 固件制作命令手册

本文是 [`如何制作固件`](../SOP/如何制作固件.md) 的技术细节部分，收集制作固件各阶段的具体命令、参数、产物位置和常见错误。流程规则、通过标准和停止条件见 SOP 和 [`固件制作规范`](固件制作规范.md)，本文不重复规定。命令或参数变更时，必须同步更新本文。制作环境的镜像结构、版本固定和命令转交机制见 [`固件制作 Docker 环境`](../reference/DESIGN/固件制作Docker环境.md)。

## 1. 命令总览

全部构建命令都在 Docker 内执行：入口脚本 + 空格 + 完整命令。

| 阶段 | 子命令 | 输入 | 产物 |
| --- | --- | --- | --- |
| 环境检查 | 无参数运行入口脚本 | — | 工具版本核对结果 |
| 官方固件查询/下载 | `official-firmware-info` / `official-firmware-download` | `env/mi-cloud.env` | `artifacts/firmware/original/ap01-1.0.2_0031.bin` |
| 设置阶段固件 | `firmware-input-prepare` → `settings-wrap-approved-plan` → `settings-build` | 官方原版固件 | `artifacts/firmware/ap01-1.0.2_0031-opt-setting.bin` |
| 公开固件 | `agents-release-build` | 设置阶段固件 | `artifacts/firmware/ap01-1.0.2_0031-opt.bin` |
| 个人固件 | `ap01-opt-personalize.ps1` / `ap01-opt-personalize.sh` | 设置阶段固件 + `env/agents-dashboard.env` | `artifacts/build/personalized/fast-<时间>/ap01-1.0.2_0031-opt-personalized.bin` |
| 交互模拟 | 快速个人化脚本自动执行；其他构建使用 `agents-interaction-simulate` | 构建清单 | 同目录 `.interaction-report.json` |

官方固件查询和下载的流程规则见 [`SOP/如何查询和下载AP01的最新官方固件.md`](../SOP/如何查询和下载AP01的最新官方固件.md)。

## 2. 环境准备

Docker Desktop 的检查、自动启动、自动安装和向用户求助的条件，唯一规定见 [`如何制作固件` 第 2.1 节](../SOP/如何制作固件.md#21-制作环境缺失或不可用)。环境就绪后，Windows：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/ap01-tools.ps1
```

macOS：

```bash
tools/ap01-tools.sh
```

命令会制作或复用本地镜像 `cuktech-ap01-build-tools:1.0`，并核对全部固定工具版本（Gifsicle、FFmpeg、RISC-V GCC、Binutils、Pillow、Requests）。版本任一不符时以非零码退出，此时不得继续构建，先按 [`requirements.md`](../reference/requirements.md) 核对工具版本。制作镜像需要联网下载，下载缓慢（低于 1MB/s）或失败时按 AGENTS.md 网络规则配置 Clash Verge 代理（默认端口 7897），不得黑盒死扛。

## 3. 设置阶段固件

三步命令依次执行。官方原版的固定值（字节数 6,804,520、MD5、SHA-256）以 [`固件制作规范` 第 4 节](固件制作规范.md#4-制作前先核对官方原版固件)为准。

第 1 步，生成只读工作副本（构建器拒绝直接使用原文件，必须先做只读副本）。Windows：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/ap01-tools.ps1 `
  python app/ap01_firmware.py firmware-input-prepare `
  --source artifacts/firmware/original/ap01-1.0.2_0031.bin `
  --target-dir artifacts/build/settings-stage/work `
  --expected-size 6804520 `
  --expected-sha256 8a721fc8ef25458d415b2460e4a251e0503a82f7743fdff85b12612190e5c1cb `
  --expected-md5 469a7329d496f81ae8625c4d76ccf56d
```

第 2 步，生成已批准修改清单：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/ap01-tools.ps1 `
  python app/ap01_firmware.py settings-wrap-approved-plan `
  --input artifacts/build/settings-stage/work/ap01-1.0.2_0031.bin `
  --output artifacts/build/settings-stage/work/settings-menu-wrap-approved.json
```

第 3 步，构建（`--cloud-checked-at` 填当次查询时间，格式 `2026-08-20T16:00:00+08:00`；`--cloud-version`、`--cloud-md5` 用 `official-firmware-info` 的当次查询结果，当前为 `1.0.2_0031` 和 `469a7329d496f81ae8625c4d76ccf56d`）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/ap01-tools.ps1 `
  python app/ap01_firmware.py settings-build `
  --input artifacts/build/settings-stage/work/ap01-1.0.2_0031.bin `
  --plan artifacts/build/settings-stage/work/settings-menu-wrap-approved.json `
  --output artifacts/firmware/ap01-1.0.2_0031-opt-setting.bin `
  --manifest artifacts/build/settings-stage-manifest.json `
  --cloud-version 1.0.2_0031 `
  --cloud-md5 469a7329d496f81ae8625c4d76ccf56d `
  --cloud-checked-at 2026-08-20T16:00:00+08:00
```

macOS 把入口换成 `tools/ap01-tools.sh`、续行符换成 `\`，参数不变。

### 3.1 修改补丁清单后要同步什么

`features/settings_menu_wrap/patch_plan.py` 的 `PATCHES` 数量或区间变化时，同一次变更必须完成：

1. `features/settings_menu_wrap/approval_record.json`：更新 `patch_count`、 `approval_limit` 并重算 `scope_sha256`（用 core 审批模块按新 `PATCHES` 重新计算）；
2. `features/settings_menu_wrap/test_patch_plan.py`：更新偏移、区间数量断言；
3. `features/settings_menu_wrap/settings_menu_wrap_patch.ld`：删除或新增对应段定义和 `ASSERT`；
4. `knowledge/AP01-官方固件分析/原厂各页面物理旋钮交互实现.md` 第 8 节的区间表。

## 5. 个人固件

先按 `env/agents-dashboard.env.example` 创建 `env/agents-dashboard.env` 并填写真实服务地址，然后执行快速个人化。脚本使用带时间的独立目录，避免覆盖历史产物。Windows：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/ap01-opt-personalize.ps1
```

macOS：

```bash
tools/ap01-opt-personalize.sh
```

脚本只有在当前代码提交、设置阶段固件 SHA-256、制作镜像标识均与本机完整测试记录一致时才复用测试结果；否则会先运行全部项目测试。无论是否复用，脚本都会制作新个人固件、生成构建清单并执行深度 8 交互模拟。地址配置项含义和数量限制的唯一原文见 [`ap01-1.0.2_0031-opt.bin 技术实现` 9.3 节](../reference/DESIGN/ap01-1.0.2_0031-opt.bin技术实现/ap01-1.0.2_0031-opt.bin技术实现.md#93-地址配置与两种固件)。 `env/agents-dashboard.env` 含本机地址，不得提交入库。

## 6. 交互模拟

快速个人化脚本已自动执行交互模拟，并把报告写在个人固件同目录。其他构建路径对每个最终产物执行以下命令（`--manifest` 用该产物的构建清单，报告放在固件同目录）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/ap01-tools.ps1 `
  python app/ap01_firmware.py agents-interaction-simulate `
  --manifest "<构建清单路径>" `
  --report "<构建清单同目录>/ap01-1.0.2_0031-opt-personalized.interaction-report.json" `
  --depth 8
```

通过标准：报告 `summary.passed` 为 `true` 且 `summary.failure_count` 为 0。报告是刷机前的必查文件，缺失或不通过的固件不得刷入。

macOS 使用同一参数，把入口改为 `tools/ap01-tools.sh`、续行符改为 `\`。

## 7. 常见错误

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `FirmwareValidationError`：原厂固件必须先设为只读 | 直接把原厂文件传给构建器 | 先执行第 3 节第 1 步，用只读副本构建 |
| 构建失败提示目标文件已存在 | 输出路径已有同名固件 | 按固件制作规范第 6 节先改名归档旧产物并更新引用，再构建 |
| `ModuleNotFoundError` 找不到项目模块 | 临时脚本没有把项目根加入模块搜索路径 | 脚本开头 `sys.path.insert(0, <项目根>)` |
| PowerShell 报解析错误 | 多行提交信息用了 bash 的 heredoc 语法 | `git commit` 用多个 `-m` 参数 |
| 工具版本核对失败 | 本地镜像工具与固定版本不一致 | 按 [`requirements.md`](../reference/requirements.md) 核对，重建镜像 |
| 工具启动时报“没有执行权限”或返回 `126` | 镜像内复制的固件编译器没有执行权限 | 先检查 `tools/docker/Dockerfile` 是否为 `toolchain/bin/` 和 `toolchain/libexec/` 中的程序设置了执行权限；修复后重建镜像。不要先更换 Windows、macOS 或 Docker 版本。 |
| 构建成功但修改区间与清单不一致 | 补丁清单改了但审批记录或链接脚本没同步 | 按第 3.1 节四项全部同步后重跑测试 |
