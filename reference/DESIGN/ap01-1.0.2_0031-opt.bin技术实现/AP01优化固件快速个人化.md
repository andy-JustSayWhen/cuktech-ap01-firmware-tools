# AP01 优化固件快速个人化

## 1. 对应需求

本文实现 [`BRIEF-OPT-004`](../../BRIEF/ap01-1.0.2_0031-opt.bin.md#brief-opt-004-个人地址制作) 和 [`SPEC-TOOLS-005`](../../SPEC/ap01-1.0.2_0031-opt.bin.md#spec-tools-005-优化固件快速个人化)。仅适用于 `ap01-1.0.2_0031-opt` 重新写入看板服务地址，不改变任何固件功能。

## 2. 文件与职责

| 路径 | 职责 |
| --- | --- |
| `tools/ap01-opt-personalize.ps1` | Windows 快速制作入口；检查可复用的完整测试记录，制作新个人固件并生成交互模拟报告。 |
| `tools/ap01-opt-personalize.sh` | macOS 快速制作入口；执行与 Windows 脚本相同的检查、制作和模拟。 |
| `artifacts/build/personalized/.opt-fast-test-cache.json` | 本机测试记录；保存代码提交、阶段输入指纹和制作镜像标识，不提交。 |
| `env/agents-dashboard.env` | 本机服务地址和端口，不提交；字段含义见最终版技术实现第 9.3 节。 |

## 3. 适用范围与测试记录

两个脚本固定使用已验收的设置菜单阶段输入，输出到带时间的独立目录，不覆盖任何已有固件。它先比较当前代码提交、阶段输入 SHA-256（长文件指纹）和制作镜像标识；三项均与本机测试记录一致时，复用该次完整测试结果。缺少记录、任一项不同、制作代码存在未提交改动或传入 `-RunFullTests` 时，脚本在制作前运行全部项目测试，并用通过结果更新记录。

无论是否复用测试记录，脚本都必须执行：

1. 容器内工具版本检查；
2. 读取本机地址配置并制作新的个人固件与构建清单；
3. 核对输出文件、清单允许安装状态和地址数量；
4. 对最终清单进行深度 8 连续交互模拟，要求零失败。

脚本输出只包含文件路径、文件指纹、是否执行完整测试和模拟结果；地址只留在 `env/` 与个人固件中。

## 4. 制作镜像

两个脚本优先使用本机已有的 `cuktech-ap01-build-tools:1.0` 镜像，并在每次容器调用时执行其工具版本检查。镜像不存在时调用 [`ap01-tools.ps1`](../../../tools/ap01-tools.ps1) 制作镜像后继续。镜像工具内容改变时，完整测试记录中的镜像标识不再匹配，下一次快速制作会重新测试。

## 5. 完成标准

脚本正常结束时必须同时有一份新的个人固件、新构建清单和新交互模拟报告；清单允许一次测试安装，模拟零失败。服务检查、唯一设备检查、上传后回读和安装仍按 [`ap01-1.0.2_0031-opt刷机流程`](../../../SOP/ap01-1.0.2_0031-opt刷机流程.md) 后续章节执行。
