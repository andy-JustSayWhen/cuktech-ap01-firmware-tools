# 酷态科 10 号电能基站 AP01 第三方固件制作与刷机工具

本文档记录产品目标、最小可用版本范围和验收边界。

本项目采用 FCMA（按用户功能组织代码的模块化架构），详细规则见
[`Architecture.md`](Architecture.md)。写代码前必须先阅读架构原文。

项目实施顺序单独维护在 [`Plan.md`](Plan.md)，不在本文定义。

## 1. 产品目标

为酷态科 10 号电能基站 AP01 屏幕制作优化固件，并提供普通用户也能使用的
Windows 和 macOS 通用刷机工具。

项目不仅供个人使用，还要能够安全分享给其他用户。使用者不需要理解命令行、
固件结构或小米云接口，通过 Chrome（谷歌浏览器）打开 WebUI（浏览器中的操作界面）
即可完成设备识别、检查、刷机和结果验证。

项目不得泄露 Codex 卡密、Codex 登录态、米家登录态、AP01 设备信息、米家账号信息、
用户提示词、任务内容和本机文件路径等敏感内容。

项目依赖统一记录在根目录 [`Depends.md`](../../Depends.md)，增加、删除或替换依赖时
必须同步维护。

## 2. MVP

### 2.1 完成标准

本项目的 MVP（最小可用版本）是：

1. 每次制作前从小米云查询 AP01 官方最新固件信息；
2. 当前目标基线为官方固件 `ap01-1.0.2_0031.bin`；
3. 制作并离线验证优化固件 `ap01-1.0.2_0031-opt.bin`；
4. 在指定测试设备上完成仅下载校验、正式刷机、功能验收和官方固件回退实测；
5. 沉淀可复查的固件制作规范和刷机工作流；
6. 固化为 Windows 和 macOS 通用的 AP01 WebUI 刷机工具。

如果小米云返回的最新版本不是 `1.0.2_0031`，立即停止复用现有偏移和成品，重新通读、
定位并验证新版本固件。不得只修改文件名后继续制作。

## 3. 优化固件功能

### 3.1 支持隐藏原厂一级页面

在系统设置菜单新增“开关一级页面”，用户可以通过复选操作决定是否显示日历、天气、
萌宠等原厂内容页。

本 brief 只声明“用户可以选择隐藏哪些原厂一级页面”这一产品目标。具体产品规则由用户
确认后写入对应 PRD（产品需求文档），实现和验收分别写入 Design（交互与视觉设计文档）
和 SPEC（技术实现合同）。

### 3.2 新增 AGENTS 看板一级页面

新增名为“AGENTS 看板”的一级页面，展示和刷新 Codex 使用信息。

服务端取得 Codex 数据并生成设备画面。AP01 每 5 分钟主动取得一次最新画面到
RAM（断电后会清空的临时内存）并显示。

服务端支持：

- Windows 电脑；
- macOS 电脑；
- Linux NAS（运行 Linux 的网络存储设备）；
- Linux 云服务器。

服务端在系统启动或用户登录后自动运行。固件内支持按顺序配置多个服务端地址：

1. 优先请求上次成功的服务端；
2. 请求失败时自动尝试下一个服务端；
3. 取得合法的新画面后才替换当前画面；
4. 所有服务端均不可达时继续显示最后一次成功画面，屏幕不显示报错。

#### 3.2.1 Codex 数据来源

数据分成两类取得：

1. **官方账号数据**
   - 复用本机已经登录的 Codex 官方应用或命令行工具；
   - 通过 Codex 自带的后台服务读取额度窗口、已用百分比、重置时间和每日消耗；
   - 主数据项包括 `account/rateLimits/read` 和 `account/usage/read` 返回的结果；
   - 主动重置次数及明细使用当前登录态读取 ChatGPT 官方额度接口；
   - 不要求用户再次输入 Codex 账号或密码。
2. **本地任务统计**
   - 增量读取 Codex 本地会话记录；
   - 从每次任务的累计用量中计算新增输入、输出和缓存命中；
   - 汇总请求数、今日消耗、近 30 天消耗、最长任务时长、活动洞察和常用插件；
   - 费用没有官方账单值时只能按明确的模型价格表计算，并在产品中写成“估算成本”。

任何上游没有提供、也无法从本地记录可靠计算的字段都显示“暂无数据”，不得编造。

#### 3.2.2 刷新、最后数据与访问控制

- 数据读取和画面生成周期固定为 5 分钟；
- 每次刷新只有在数据读取、画面生成和文件校验全部成功后，才覆盖上一次成功结果；
- 断网、Codex 暂时不可用或服务端请求失败时，继续使用最后一次成功结果；
- 最后一次成功结果保存在服务端本地，服务端重启后仍然可用；
- AP01 只取得最终画面，不取得 Codex 登录凭据、米家凭据或本地会话原文；
- 服务端对外只提供画面和不含敏感信息的运行状态，不提供原始账号数据；
- 局域网或云端画面地址必须带随机访问标识，避免同一网络中的其他人直接猜到地址；
- 云服务器方案启用前必须验证设备支持的安全连接方式；未验证前默认使用家庭局域网服务；
- 日志不得记录访问令牌、Cookie（网站保持登录用的凭据）、账号编号、设备编号、
  用户提示词或本机文件路径。

#### 3.2.3 设备画面约束

- AP01 固件的实际页面画布为 320×240；
- 设计图只用于参考信息层级、布局、配色和数字表现；
- 最终画面只显示本 brief 明确列出的数据，不照搬设计图中的其他数据；
- 可以先制作高分辨率设计底图，但送入 AP01 的最终画面必须是 320×240；
- 官方 `1.0.2_0031` 固件直接包含 PNG（静态图片格式）和 GIF（动图格式）解析器，
  并内置 199 张可解码 PNG 与 10 个可解码 GIF；
- 当前参考项目已经真机验证的实时画面方案为 GIF89a、320×240、至少两帧、单文件
  不超过 256KB，并使用三个临时内存槽轮换；
- 256KB 是当前第三方实时画面加载实现的限制，不是 AP01 原厂图片解析能力的全局上限；
- 改用 PNG、扩大文件体积或改变内存布局前，必须完成设备端实现和真机稳定性验证；
- 画面生成失败、文件损坏、尺寸不符或体积超限时，不得替换最后一次成功画面。

效果图由 Codex 调用图片生成能力制作。效果图审阅通过后，只删除实时变化的数据文字，
保留标题和视觉底图，由服务端把实时文字、圆环、进度条和曲线合成到最终画面。

#### 3.2.4 一级页面：概览

概览只显示三个区块：

- 圆环：本周剩余额度；
- 卡片：今日消耗、近 30 天消耗；
- 曲线：近 7 天消耗。

#### 3.2.5 二级页面

二级页面共三个：

1. **周剩余额度详情**
   - 本周剩余：进度条和百分比；
   - 下次重置：倒计时和具体时间；
   - 可用主动重置次数；
   - 每次主动重置记录：状态、发放时间、到期时间和到期倒计时。
2. **今日消耗详情**
   - 总消耗 Token（模型处理文字时计算用量的单位）；
   - 请求数；
   - 估算成本；
   - 输入、输出和缓存命中。
3. **近 30 天消耗详情**
   - 近 30 天累计消耗；
   - 最长任务时长；
   - 活动洞察；
   - 常用插件。

#### 3.2.6 物理旋钮交互

原厂动作、系统事件和功能映射见
[`AP01-物理旋钮原厂功能映射表.md`](../../knowledge/AP01-物理旋钮交互设计/AP01-物理旋钮原厂功能映射表.md)。

- AGENTS 看板一级页面：按下后松开，进入二级页面；
- 第一次进入二级页面：默认显示“周剩余额度详情”；
- 二级页面：左右旋转，在三个详情页之间循环切换；
- 二级页面：按下后松开，返回 AGENTS 看板一级页面；
- 熄屏状态下的第一次旋转或按下遵循原厂唤醒逻辑，不额外执行页面操作；
- 连续旋转时每个有效旋钮格只切换一个页面，不跳页；
- 页面重建后立即重新挂载最后一次成功画面，不短暂回到错误页面。

### 3.3 优化系统设置页的旋钮交互

系统设置菜单中的选择项首尾相连：

- 向左旋转到顶部后继续左旋，跳到最后一个菜单项，并继续向上选择；
- 向右旋转到底部后继续右旋，跳到第一个菜单项，并继续向下选择；
- 每个有效旋钮格只移动一个菜单项；
- 循环选择不得改变按下确认、返回和数值调整等原厂功能。

## 4. WebUI 刷机工具

### 4.1 支持环境

- MVP 浏览器：Chrome；
- 操作系统：Windows、macOS；
- 服务端代码同时为 Linux 部署保留兼容能力；
- 普通用户不需要安装开发工具或手动运行命令。

### 4.2 设备连接和发现

参考项目已验证的连接方式如下，本项目优先复用并改造成 WebUI 流程：

1. 用户通过二维码登录米家；
2. 工具从小米云设备列表中查找型号为 `njcuk.enstor.ap01` 的在线设备；
3. 用小米云信息确认设备型号、固件版本、在线状态和局域网地址；
4. 使用局域网 MiIO（小米设备通信协议）UDP 54321 做只读可达性检查；
5. 固件上传使用小米 FDS（云端临时存放固件的文件服务）或已经签名的官方分发地址；
6. AP01 通过小米云 `miIO.ota` 接收仅下载或安装指令；
7. 优化固件中的第三方加载功能让 AP01 主动通过局域网 HTTP 8765 端口取得日常画面。

MVP 不把 USB（常见的数据线接口）、蓝牙、充电底座触点或串口作为连接和刷机方式。

### 4.3 一键刷机流程

“一键”表示用户完成设备选择并确认风险后，只点击一次“开始刷机”，后续流程由工具自动完成，
不表示跳过安全检查。

工具必须依次自动执行：

1. 唯一识别目标 AP01；
2. 查询官方固件和目标设备版本；
3. 检查供电、联网、在线状态和局域网可达性；
4. 取得并保存匹配版本的原厂固件；
5. 校验原厂固件来源、文件头、字节数和官方文件指纹；
6. 制作优化固件并生成构建清单；
7. 完成离线结构、校验值、修改范围和自动测试验证；
8. 上传同一个已验证成品；
9. 让 AP01 仅下载并校验，不安装；
10. 向用户展示目标设备、版本、文件指纹、修改范围、检查结果和回退方案；
11. 用户本次确认后下发安装；
12. 展示下载、安装、重启和重新上线进度；
13. 自动执行安装后验收。

任何一步失败都停止后续操作，并给出用户能看懂的原因和下一步建议。

## 5. 固件制作、刷机与恢复要求

固件制作规范沉淀到 `knowledge/固件制作规范/`。开始实现时先复制并改造参考项目中的
`agent-docs/firmware-safety.md`，不能在运行时继续依赖将被删除的参考项目。

### 5.1 制作前

- 唯一确认设备型号、当前固件版本和在线状态；
- 从小米云读取官方最新固件信息；
- 保存未经修改的匹配版本官方固件；
- 记录官方来源、版本、字节数、MD5（快速核对文件是否相同的指纹）和
  SHA-256（更严格核对文件是否相同的指纹）；
- 原厂固件和构建产物放在不会提交到代码仓库的目录；
- 不修改启动引导程序、分区表、恢复区、联网初始化和官方更新链路。

### 5.2 离线校验

- 文件头必须为目标 AP01 使用的 `BFNP`；
- 文件字节数必须与目标版本预期一致；
- 回读尾部长度和恢复校验值；
- 记录所有修改区间，修改区间外不得出现意外差异；
- 检查载荷边界、资源边界、跳转地址和调用约定；
- 运行自动测试；
- 为每个成品生成不可混淆的文件名和构建清单；
- 仅下载验证和正式安装必须使用同一个已经校验的成品文件。

### 5.3 安装验证

安装前必须先完成“仅下载校验”。正式安装必须经过本次即时确认。

安装成功至少需要同时证明：

- AP01 接受安装指令；
- 下载进度完成；
- 设备进入安装阶段；
- 设备发生重启；
- 运行时间重新计数；
- 设备重新上线；
- 米家通信正常；
- 原厂基础页面正常；
- 页面开关、AGENTS 看板和旋钮循环功能全部通过；
- 官方更新能力仍可用。

只看到屏幕亮起、进度字段变化或设备短暂离线，不能判定刷机成功。

### 5.4 回退与失败恢复

- 发布前必须在指定测试设备上完成一次官方原厂固件回退实测；
- 回退前同样先执行原厂固件仅下载校验，再经过即时确认安装；
- 回退成功必须证明设备重启、重新上线、原厂页面恢复、米家通信和官方更新能力正常；
- 未完成上述实测前，只能写“具备原厂固件安装能力”，不能写“一键回退已经可靠”；
- 官方固件包含两个固件槽、当前槽与更新槽、自动恢复和恢复校验代码；这些代码不能替代
  指定设备上的官方固件回退实测；
- 未在当前固件中发现按键触发的离线免拆机恢复流程；
- 设备无法联网时停止重复刷机和反复断电，保存最后状态与日志，再评估厂家恢复或硬件恢复；
- 拆机、短接、连接调试器或直接写存储芯片属于新的高风险操作，必须另行确认。

## 6. 验收标准

| 验收对象 | 通过条件 |
| --- | --- |
| 官方固件 | 来源、版本、文件头、字节数和文件指纹全部一致 |
| 优化固件 | 修改范围明确，结构与校验全部通过，自动测试通过 |
| 仅下载验证 | AP01 下载并校验同一个成品，不安装、不切换启动状态 |
| 正式安装 | 接受、下载、安装、重启、运行时间重置和重新上线证据完整 |
| 页面开关 | 用户选择隐藏的原厂一级页面不再进入一级导航 |
| AGENTS 看板 | 四个页面字段与 brief 一致，不增加设计图中的其他数据 |
| 数据刷新 | 每 5 分钟成功刷新；失败时保持最后成功画面且屏幕不报错 |
| 旋钮交互 | 一级进入、二级循环、按下返回、设置菜单首尾循环全部通过 |
| 服务端 | macOS、Windows 自动启动和持续运行通过；Linux 部署方案可用 |
| 真机取图 | AP01 实际请求画面成功，不能只验证电脑本地能打开 |
| 原厂回退 | 指定测试设备完成原厂固件安装、重启、重新上线和原厂功能验收 |
| 普通用户流程 | 用户仅使用 Chrome 和图形界面即可完成设备识别、确认、刷机与结果查看 |
| 隐私 | 成品、图片、日志和仓库中均无凭据、设备身份、账号身份或任务原文 |
