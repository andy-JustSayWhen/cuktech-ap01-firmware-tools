# AGENTS 看板跨电脑数据获取方法

本文只规定把 AGENTS 看板数据服务切换到另一台电脑时的操作方法。四类数据的技术定义、
安全边界和固件取包合同只见
[`AP01 优化固件 DESIGN`](../../DESIGN/AP01-1.0.2_0031-opt.bin.md) 第 7.4、7.4.5、8.2 和 9 节；
本文不重复定义。

## 1. 当前能力边界

当前成品一次只从一个固定局域网地址取包。运行服务的电脑通过 `--codex-home` 指向本机的
Codex 数据根目录：额度、重置卡和个人统计使用该目录中的当前登录状态向官方接口查询；今日
本地会话读取该目录中的 `sessions/` 与 `archived_sessions/`。

因此，不同电脑上的数据关系固定如下：

| 数据 | 切到另一台电脑后的来源 | 当前能否跨电脑合并 |
| --- | --- | --- |
| 本周额度、重置卡、个人统计 | 目标电脑当前登录账号对应的官方结果 | 不需要由设备合并 |
| 今日用量、模型费用 | 目标电脑本地保存的会话记录 | 不能；当前只统计服务电脑可读到的本地记录 |

同一账号在两台电脑登录，不代表任一台电脑天然拥有另一台电脑的本地会话记录。当前实现也不
复制登录文件、会话原文或设备共享配置。

## 2. 换机步骤

### 2.1 准备目标电脑

目标电脑必须具备：

- 当前项目代码；
- Python 3.9 或更高版本；
- `env/fonts/` 中所需字体；
- 目标用户自己的有效 Codex 登录状态和本地会话目录；
- 与 AP01 同一局域网，且允许访问服务端口 `18765`。

不要从原电脑复制 `auth.json`、会话原文或设备共享配置。目标电脑应使用自己的正常登录状态，
并把实际数据根目录作为启动参数。

### 2.2 启动目标服务

```shell
cd /Users/mac/Desktop/cuktech-ap01-firmware-tools

python3 -m features.agents_dashboard.bridge \
  --bind 0.0.0.0 \
  --port 18765 \
  --interval 300 \
  --codex-home /Users/mac/.codex \
  --cache-directory env/agents-dashboard-cache \
  --output artifacts/agents-dashboard \
  --font-directory env/fonts
```

路径必须按目标电脑的实际位置填写。首次生成失败时，只有磁盘上已有一份通过完整检查的旧包，
服务才允许继续提供旧结果。

### 2.3 验证目标电脑确实取得自己的数据

```shell
curl --fail --silent --show-error http://127.0.0.1:18765/health
curl --fail --silent --show-error http://目标电脑局域网地址:18765/health
curl --fail --silent --show-error \
  --output /tmp/ap01-agents-current.apag \
  http://目标电脑局域网地址:18765/a
```

继续条件：

1. 健康结果中 `ok` 为 `true`、`degraded` 为 `false`、`error` 为 `null`；
2. `quota`、`reset_cards`、`profile`、`local_sessions` 四项均为 `true`；
3. `/a` 返回的完整包通过 DESIGN 第 8.1 节检查；
4. AP01 发起后台刷新后，请求次数增加，最后设备请求时间更新。

如果只有 `local_sessions` 为 `false`，先核对 `--codex-home` 是否指向目标用户真实数据目录；
不能用另一台电脑的缓存冒充目标电脑数据。

### 2.4 判断是否需要重新制作固件

- 目标电脑能够实际取得当前固件固定的局域网地址：停止原服务，确认目标电脑已占用该地址后，
  按第 2.2 至 2.3 节验证；固件地址没有变化时不修改固件。
- 目标电脑使用不同局域网地址：先修改对应 DESIGN 中的固定地址和验证方案，再构建、模拟、
  上传回读并安装新固件；只启动另一台电脑的服务不会改变 AP01 的取包目标。

换机完成后再为目标系统建立开机常驻任务。当前只有 home02-macmini 的 macOS 常驻任务经过
实测；Windows、Linux 电脑和 Linux 网络存储服务器的常驻方式尚未实现与验收。

## 3. 多台电脑汇总的判定

当前服务不能把多台电脑的今日本地会话合并为一个数字。如果目标是“无论在哪台电脑使用，
AP01 都显示所有电脑合计”，必须先新增一项 DESIGN：各电脑只上报安全聚合结果，由一个固定
服务端去重、合并并生成四页包；AP01 仍只访问该固定服务端。该功能实现前，不得把单机结果
写成跨电脑总量。
