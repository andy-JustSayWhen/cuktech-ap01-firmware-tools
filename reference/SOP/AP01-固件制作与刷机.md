# AP01 固件制作与刷机操作规范

本文档记录执行步骤、停止条件和验收证据。开发需求见
[`brief.md`](../brief.md)，技术合同见 [`SPEC.md`](../SPEC.md)。所有操作必须先满足
[`固件制作规范`](../固件制作规范.md)。恢复层级、首次安装前自救验证和设备离线后的操作见
[`AP01-分级恢复与救砖.md`](AP01-分级恢复与救砖.md)。

## 0. 小米授权实现来源与执行门禁

本项目的小米二维码授权唯一参考实现为用户远端仓库
[`andy-JustSayWhen/cuktech-screen-controller`](https://github.com/andy-JustSayWhen/cuktech-screen-controller)
中的 `mi_login.py`。本地工作目录固定为 `/Users/mac/Desktop/cuktech-screen-controller`。
每次执行登录或刷机前，必须查询该远端仓库 `main` 分支的实时版本并同步本地；本地保存的远端
跟踪记录不能代替实时查询。2026-07-31 核对并同步的版本为提交号
`334ae8da576522624f72508fa6b5ee6c314eec61`，二维码登录由其中提交号
`05a7da7` 引入。

`mi_login.py` 的二维码协议核心来源于
[`PiotrMachowski/Xiaomi-cloud-tokens-extractor`](https://github.com/PiotrMachowski/Xiaomi-cloud-tokens-extractor)
的提交号 `c4db715dace9806e905153c2977608873e8ab7c9`。该来源采用
MIT（允许复用，但必须保留作者和许可文本的开源许可证）。直接复用范围是二维码申请、轮询、
登录结果解析及小米家庭应用请求标识；用户远端仓库增加了二维码文件原子写入与仅限本人读取、
登录态写入被忽略的 `.env`、AP01 型号与唯一性校验、版本和在线状态校验以及自动测试。完整
许可文本保存在参考项目的 `THIRD_PARTY_NOTICES.md`。

后续执行必须遵守：

1. 不打开小米之家或米家应用代替该流程，不自行猜测或改写授权地址；
2. 先运行参考项目的 `test_mi_login.py` 和 `test_ap01_install_firmware.py`，全部通过后才能
   生成二维码；
3. 直连失败时复用用户当前选中的网络配置及其 7897 端口；未经用户明确要求，不切换配置文件；
4. 二维码只在用户已经准备扫码时生成；超时后不得把失败会话写成已授权；
5. 登录成功后只从被版本控制忽略、权限为 `0600` 的 `.env` 读取登录态，不打印、不复制到
   本项目，不写入日志或知识文档；
6. 每次刷机前重新确认账号中恰好一台目标型号为 `njcuk.enstor.ap01` 的在线设备，再继续执行
   本文后续门禁。

## 1. 制作前

1. 唯一确认目标设备型号、当前固件版本和在线状态；
2. 从小米云重新查询官方最新固件；
3. 下载匹配版本的原厂固件；
4. 核对官方来源、文件头、字节数和文件指纹；
5. 保存未经修改的原厂文件；
6. 固件和构建产物只保存到仓库忽略目录；
7. 官方版本与当前知识基线不一致时停止制作，重新通读固件。

## 2. 离线制作与校验

1. 从已经校验的原厂文件制作优化固件；
2. 保持目标版本要求的文件头和总字节数；
3. 记录全部修改区间；
4. 检查修改区间外没有意外差异；
5. 检查载荷边界、资源边界、跳转地址和调用约定；
6. 重新计算并核对文件尾恢复校验值；
7. 运行自动测试；
8. 生成不可混淆的成品文件名和构建记录。

当前原厂基线检查入口：

```bash
python3 -m app.ap01_firmware inspect \
  --input /仓库外只读目录/ap01-1.0.2_0031.bin \
  --report artifacts/build/baseline-inspection.json \
  --cloud-version 1.0.2_0031 \
  --cloud-md5 469a7329d496f81ae8625c4d76ccf56d \
  --cloud-checked-at <本次小米云查询时间>
```

该入口只生成基线检查报告。没有已批准且具备直接证据的修改清单时，不生成优化固件。

当前版本系统设置菜单首尾循环的待批准清单入口：

```bash
python3 -m app.ap01_firmware settings-wrap-plan \
  --input /仓库外只读目录/ap01-1.0.2_0031.bin \
  --output artifacts/build/settings-menu-wrap-direct-position-draft.json
```

该入口逐项核对真实原厂旧字节，并用 `requirements.md` 固定的工具版本复现替换字节。输出
状态固定为等待用户批准，不能直接用于离线制作。批准范围只见
[`2026-07-27 系统设置菜单首尾循环静态定位`](../../knowledge/AP01-官方固件分析/cases/2026-07-27-系统设置菜单首尾循环静态定位.md)。

用户已经明确批准该记录中的 3 个精确区间后，使用下列入口重新读取真实原厂基线并生成批准
范围绑定清单：

```bash
python3 -m app.ap01_firmware settings-wrap-approved-plan \
  --input /仓库外只读目录/ap01-1.0.2_0031.bin \
  --output artifacts/build/settings-menu-wrap-direct-position-approved.json
```

该入口不接收批准开关。只有版本控制内的批准记录与重新生成的目标、证据、3 个修改区间、
全部修改前后字节、代码间隙和日志保持范围完全一致时，才输出允许离线构建的清单。

本次重新查询小米云并确认版本与原厂文件校验值一致后，使用下列入口离线制作：

```bash
python3 -m app.ap01_firmware build \
  --input /仓库外只读目录/ap01-1.0.2_0031.bin \
  --plan artifacts/build/settings-menu-wrap-direct-position-approved.json \
  --output artifacts/firmware/opt-setting.bin \
  --manifest artifacts/build/opt-setting-manifest.json \
  --cloud-version <本次查询版本> \
  --cloud-md5 <本次查询文件校验值> \
  --cloud-checked-at <本次查询时间>
```

该入口当前只制作 [`SPEC-FIRMWARE-004`](../SPEC.md#spec-settings-stage) 规定的设置菜单
阶段成品。制作入口要求制作代码已经提交，并把成品和构建清单冻结为只读。离线制作完成不
代表允许进入仅下载或安装阶段。

## 3. 仅下载校验

本节只适用于实验成品。匹配原厂包的 R0 验证见
[`AP01-分级恢复与救砖.md`](AP01-分级恢复与救砖.md) 第 3.2 节。

恢复类条件无法取得时，只能按
[`固件制作规范`](../固件制作规范.md) 第 7.1 节记录绑定唯一设备、唯一成品和一次动作的逐次
风险授权；本流程不重复定义可跳过范围。

1. 在专用测试设备上完成同机原厂 R0 回刷；
2. 完成至少一条不依赖应用启动和联网的恢复演练；
3. 取得 AP01 当前槽、更新槽和本次写入目标的直接证据；
4. 上传已经完成离线校验的冻结成品；
5. 把上传对象完整下载回来，与冻结成品逐字节比较；
6. 取得本次仅下载动作的即时确认；
7. 让 AP01 下载并校验，不安装、不切换启动槽；
8. 保存设备接受指令、下载进度、写入目标和校验结果；
9. 正式安装继续使用同一个成品文件。

仅下载校验失败时停止，不下发安装。

构建清单关闭普通安装权限的实验候选，不得进入自动或普通用户刷机流程。只有
[`固件制作规范`](../固件制作规范.md) 第 7.1 节允许的专用测试设备单次实验，才能在绑定唯一
设备、唯一成品指纹和一次动作后人工执行本节；该授权不修改冻结构建清单，也不解除发布门禁。

## 4. 正式安装

正式安装前向用户展示目标设备、版本、文件指纹、修改范围、检查结果和恢复材料，并取得
本次安装确认。

安装后依次保存下列证据：

1. 设备接受安装指令；
2. 下载完成；
3. 设备进入安装；
4. 设备重启；
5. 运行时间重新计数；
6. 设备重新上线；
7. 米家通信正常；
8. 原厂基础页面正常；
9. `brief.md` 中的优化功能逐项通过；
10. 官方更新能力正常。

证据不完整时不宣布安装成功。

## 5. 官方固件回退

1. 使用与目标设备匹配且已经校验的官方固件；
2. 先完成官方固件仅下载校验；
3. 取得本次回退确认；
4. 下发安装；
5. 验证设备重启、重新上线、原厂页面、米家通信和官方更新能力。

本项目在指定设备上完成以上全流程前，不得写“一键回退已经可靠”。

设备无法启动或联网时，不继续执行本节，转入
[`AP01-分级恢复与救砖.md`](AP01-分级恢复与救砖.md)。

## 6. 失败停止条件

出现下列任一情况立即停止后续操作：

- 设备型号不能唯一确认；
- 官方版本、字节数或文件指纹不一致；
- 修改区间外出现差异；
- 恢复校验不一致；
- 供电或联网不稳定；
- 仅下载校验失败；
- 设备安装后没有重新上线；
- 原厂基础功能异常。

设备无法联网时停止重复刷机和反复断电，保存最后状态与日志。拆机、短接、连接调试器或
直接写存储芯片需要新的明确授权，并且必须遵守
[`AP01-分级恢复与救砖.md`](AP01-分级恢复与救砖.md) 的证据门禁。
