# AP01 固件制作与刷机操作规范

本文档记录执行步骤、停止条件和验收证据。开发需求见
[`brief.md`](../brief.md)，技术合同见 [`SPEC.md`](../SPEC.md)。所有操作必须先满足
[`固件制作规范`](../固件制作规范.md)。恢复层级、首次安装前自救验证和设备离线后的操作见
[`AP01-分级恢复与救砖.md`](AP01-分级恢复与救砖.md)。

## 1. 制作前

1. 唯一确认目标设备型号、当前固件版本和在线状态；
2. 从小米云重新查询官方最新固件；
3. 下载匹配版本的原厂固件；
4. 核对官方来源、文件头、字节数和文件指纹；
5. 保存未经修改的原厂文件；
6. 固件和构建产物只保存到仓库忽略目录；
7. 官方版本与当前知识基线不一致时停止制作，重新通读固件。

## 2. 离线制作与校验

1. 从已经校验的原厂文件制作优化固件；
2. 保持目标版本要求的文件头和总字节数；
3. 记录全部修改区间；
4. 检查修改区间外没有意外差异；
5. 检查载荷边界、资源边界、跳转地址和调用约定；
6. 重新计算并核对文件尾恢复校验值；
7. 运行自动测试；
8. 生成不可混淆的成品文件名和构建记录。

当前原厂基线检查入口：

```bash
python3 -m app.ap01_firmware inspect \
  --input /仓库外只读目录/ap01-1.0.2_0031.bin \
  --report artifacts/build/baseline-inspection.json \
  --cloud-version 1.0.2_0031 \
  --cloud-md5 469a7329d496f81ae8625c4d76ccf56d \
  --cloud-checked-at <本次小米云查询时间>
```

该入口只生成基线检查报告。没有已批准且具备直接证据的修改清单时，不生成优化固件。

当前版本系统设置菜单首尾循环的待批准清单入口：

```bash
python3 -m app.ap01_firmware settings-wrap-plan \
  --input /仓库外只读目录/ap01-1.0.2_0031.bin \
  --output artifacts/build/settings-menu-wrap-draft.json
```

该入口逐项核对真实原厂旧字节，并用 `requirements.md` 固定的工具版本复现替换字节。输出
状态固定为等待用户批准，不能直接用于离线制作。批准范围只见
[`2026-07-27 系统设置菜单首尾循环静态定位`](../../knowledge/AP01-官方固件分析/cases/2026-07-27-系统设置菜单首尾循环静态定位.md)。

用户已经明确批准该记录中的 3 个精确区间后，使用下列入口重新读取真实原厂基线并生成批准
范围绑定清单：

```bash
python3 -m app.ap01_firmware settings-wrap-approved-plan \
  --input /仓库外只读目录/ap01-1.0.2_0031.bin \
  --output artifacts/build/settings-menu-wrap-approved.json
```

该入口不接收批准开关。只有版本控制内的批准记录与重新生成的目标、证据、3 个修改区间、
全部修改前后字节、代码间隙和日志保持范围完全一致时，才输出允许离线构建的清单。

本次重新查询小米云并确认版本与原厂文件校验值一致后，使用下列入口离线制作：

```bash
python3 -m app.ap01_firmware build \
  --input /仓库外只读目录/ap01-1.0.2_0031.bin \
  --plan artifacts/build/settings-menu-wrap-approved.json \
  --output artifacts/firmware/opt-setting.bin \
  --manifest artifacts/build/opt-setting-manifest.json \
  --cloud-version <本次查询版本> \
  --cloud-md5 <本次查询文件校验值> \
  --cloud-checked-at <本次查询时间>
```

该入口当前只制作 [`SPEC.md` 第 1.1 节](../SPEC.md#11-设置菜单阶段固件)规定的设置菜单
阶段成品。制作入口要求制作代码已经提交，并把成品和构建清单冻结为只读。离线制作完成不
代表允许进入仅下载或安装阶段。

## 3. 仅下载校验

本节只适用于实验成品。匹配原厂包的 R0 验证见
[`AP01-分级恢复与救砖.md`](AP01-分级恢复与救砖.md) 第 3.2 节。

1. 在专用测试设备上完成同机原厂 R0 回刷；
2. 完成至少一条不依赖应用启动和联网的恢复演练；
3. 取得 AP01 当前槽、更新槽和本次写入目标的直接证据；
4. 上传已经完成离线校验的冻结成品；
5. 把上传对象完整下载回来，与冻结成品逐字节比较；
6. 取得本次仅下载动作的即时确认；
7. 让 AP01 下载并校验，不安装、不切换启动槽；
8. 保存设备接受指令、下载进度、写入目标和校验结果；
9. 正式安装继续使用同一个成品文件。

仅下载校验失败时停止，不下发安装。

## 4. 正式安装

正式安装前向用户展示目标设备、版本、文件指纹、修改范围、检查结果和恢复材料，并取得
本次安装确认。

安装后依次保存下列证据：

1. 设备接受安装指令；
2. 下载完成；
3. 设备进入安装；
4. 设备重启；
5. 运行时间重新计数；
6. 设备重新上线；
7. 米家通信正常；
8. 原厂基础页面正常；
9. `brief.md` 中的优化功能逐项通过；
10. 官方更新能力正常。

证据不完整时不宣布安装成功。

## 5. 官方固件回退

1. 使用与目标设备匹配且已经校验的官方固件；
2. 先完成官方固件仅下载校验；
3. 取得本次回退确认；
4. 下发安装；
5. 验证设备重启、重新上线、原厂页面、米家通信和官方更新能力。

本项目在指定设备上完成以上全流程前，不得写“一键回退已经可靠”。

设备无法启动或联网时，不继续执行本节，转入
[`AP01-分级恢复与救砖.md`](AP01-分级恢复与救砖.md)。

## 6. 失败停止条件

出现下列任一情况立即停止后续操作：

- 设备型号不能唯一确认；
- 官方版本、字节数或文件指纹不一致；
- 修改区间外出现差异；
- 恢复校验不一致；
- 供电或联网不稳定；
- 仅下载校验失败；
- 设备安装后没有重新上线；
- 原厂基础功能异常。

设备无法联网时停止重复刷机和反复断电，保存最后状态与日志。拆机、短接、连接调试器或
直接写存储芯片需要新的明确授权，并且必须遵守
[`AP01-分级恢复与救砖.md`](AP01-分级恢复与救砖.md) 的证据门禁。
