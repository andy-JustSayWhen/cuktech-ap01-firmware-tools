### 1.1 设置菜单阶段固件

`opt-setting.bin` 是完整优化版之前的独立阶段成品。它唯一新增的用户功能是优化系统设置
一级列表的旋钮交互，支持首尾循环；不得包含 AGENTS 看板、一级页面开关、七页导航、持久化、
后台刷新、参考项目实时画面加载器或二级菜单首尾循环。

本项目中“首尾循环”的唯一功能定义是：系统设置一级列表的有效设置项按顺序首尾相接。焦点
位于第一项时继续向左旋转一格，直接选择最后一项；焦点位于最后一项时继续向右旋转一格，
直接选择第一项。选中状态、选中样式和列表可视位置必须在这一次旋转中同时到达目标端，不能
要求用户再旋转一次才看见新焦点；继续沿同一方向旋转时，从目标端按正常相邻顺序继续选择。
一级列表内部的相邻选择保持原厂表现，二级菜单到达边界后仍停止，不参与首尾循环。

该阶段成品必须保持第 1 节的型号、版本、总字节数、文件头和文件尾恢复记录格式。允许修改的
程序区间只见
[`2026-07-27 系统设置菜单首尾循环静态定位`](../knowledge/AP01-官方固件分析/cases/2026-07-27-系统设置菜单首尾循环静态定位.md)。
生成成功只表示离线成品成立，不表示允许仅下载或安装。

每个有效旋转格必须在同一次事件处理中同步完成选中状态、选中样式和列表可视位置更新。首尾
循环后的目标项必须立即可见，不得等到后续旋转才移动列表或显示视觉焦点。首尾循环只允许
直接切换到目标端的列表位置，不播放跨越中间条目的滚动过渡；内部相邻条目继续保持原厂表现。
同一个物理旋转格内尚未完成的相位变化或机械抖动不得产生相反方向的页面移动。用户主动快速
反转方向时，可以丢弃尚未完成的中间相位，但下一格完整旋转必须按新方向正常响应。

为满足上述功能而复用的底层旋钮方向过滤会作用于所有页面，其技术影响范围只见
[`DESIGN`](DESIGN/AP01-1.0.2_0031-opt.bin.md) 第 6.1 节；它不构成其他页面的新增用户功能。

## 2. 页面与资源事实

- 原厂一级页面为时钟、功率、天气、日历、设置和虚拟形象；
- 原厂窗口管理支持添加窗口、读取窗口数和按序号切换窗口；
- 原厂设置保存于 `/data/sysconfig.bin`；
- 原厂设置字段中没有一级页面显隐配置；
- 固件页面画布为 320×240；
- 固件包含 PNG（静态图片格式）和 GIF（动图格式）解析能力；
- 当前参考项目完成真机验证的实时画面是 GIF89a、320×240、至少两帧、最大 256KB；
- 256KB 是当前第三方实时加载功能的限制，不是原厂图片解析器的全局限制。

新增 AGENTS 看板不得改变日历、天气等原厂页面进入详情和返回一级页面的既有交互。原厂页面
进入详情后，按下并松开旋钮必须仍能按原厂行为返回对应一级页面。

### 2.1 一级页面开关

系统设置一级列表在“返回”之前新增“开关一级页面”。按下并松开旋钮进入开关页；开关页按
时钟、功率、天气、日历、萌宠、AGENTS 看板、返回的固定顺序显示。

左右旋转在七项之间首尾循环。焦点位于前六项时，按下并松开旋钮切换对应复选状态；焦点位于
“返回”时，按下并松开旋钮返回系统设置一级列表，并保持焦点位于“开关一级页面”。

六个开关只控制一级页面导航是否经过对应页面，不删除原厂页面对象。设置页始终显示，不能
关闭。首次没有有效保存记录时，时钟、功率和 AGENTS 看板开启，天气、日历和萌宠关闭。
修改成功后立即影响一级页面导航，设备正常重启后继续使用最后一次成功保存的状态。

当前页被关闭时，不在当前画面立即跳走；下一次左右旋转时从当前页开始寻找该方向上的第一个
启用页面。保存失败时，复选状态和一级页面导航均保持修改前的状态。

## 3. 当前复用的设备通信路径

参考项目已经验证以下路径：

1. 通过米家二维码登录取得用户授权；
2. 从小米云设备列表识别型号为 `njcuk.enstor.ap01` 的设备；
3. 通过小米云取得设备版本、在线状态和局域网地址；
4. 通过米家设备通信检查局域网可达性；
5. 上传已经校验的固件文件；
6. 通过小米云在线更新指令让设备下载或安装；
7. 优化固件通过局域网画面服务取得实时画面。

原厂 `1.0.2_0031` 固件中没有第三方局域网画面服务；该能力由优化固件加入。

### 4.1 看板数值显示合同

本节是 AGENTS 看板数值显示规则的唯一原文，其他文档只引用本节。

所有看板数据最终显示为整数，显示字符串不得包含小数点。计数保持整数；百分比、金额和
原始数据中的小数值按四舍五入得到显示整数。

Token 消耗按原始整数自动选择单位：

| 原始值范围 | 数值部分 | 单位部分 | 最大常规显示 |
| --- | --- | --- | --- |
| 小于 1 万 | 原始整数，千位使用分隔符 | `Token` | `9,999 Token` |
| 1 万至小于 1 亿 | 除以 1 万后四舍五入 | `万 Token` | `9,999 万 Token` |
| 1 亿至小于 1,000 亿 | 除以 1 亿后四舍五入 | `亿 Token` | `1,000 亿 Token` |

四舍五入结果达到下一单位门槛时，必须改用下一单位重新格式化，不能显示五位数值。数值与
单位使用两个独立位置；数值位置按最多四位数字预留并对齐，千位分隔符不计入数字位数。

示例：

| 原始数据 | 显示结果 |
| ---: | --- |
| `5,353` | `5,353 Token` |
| `9,000` | `9,000 Token` |
| `164,000` | `16 万 Token` |
| `1,557,279` | `156 万 Token` |
| `1,388,000` | `139 万 Token` |
| `500,000,000` | `5 亿 Token` |
| `1,000,000,000` | `10 亿 Token` |
| `2,000,000,000` | `20 亿 Token` |
| `18,280,000,000` | `183 亿 Token` |

圆环只用于有明确总量且能换算为百分比的数据。概览页只有本周剩余额度使用圆环；今日消耗
和近 30 天消耗是绝对 Token 数值，只使用普通数值和单位。

### 4.2 看板字段口径

本周剩余额度使用当前 Codex 账号中窗口时长为 10,080 分钟的一周额度窗口。显示值为
`100 - 已用百分比`；下次重置使用同一额度窗口的重置时间。重置卡数量和每张卡的获得时间、
失效时间只使用官方重置卡明细；没有返回时显示“无法获取”，不能把额度窗口、账户积分或
空数组当作重置卡。

今日消耗只汇总北京时间当日的正增量：

- 总消耗等于新增输入、输出与缓存命中 Token 之和，也等于原始输入与输出之和；
- 原始输入、输出和缓存命中分别取同名累计计数的相邻非负增量；
- 新增输入等于原始输入减去缓存命中，结果不得小于零；
- 请求数等于当日产生正 Token 增量的模型请求次数；
- 缓存命中率等于缓存命中除以原始输入，按第 4.1 节显示整数百分比；原始输入为零时显示
  `0%`；
- 今日页显示“API 成本”和整数美元；费用必须按
  [`Codex 模型 API 计费表`](Codex-模型API计费表.md) 对当天每次模型请求分别计算后求和；
- 当天任一正 Token 用量无法确定模型、必要 Token 字段或单价时，API 成本显示“无法获取”，
  不能把已知部分的小计当作当天总计。

近 30 天累计消耗和近 7 天曲线使用 Codex 个人统计中的每日用量。窗口固定为北京时间今天
及此前 29 个自然日；官方结果中缺少的日期按零处理，不混入本地会话估算值。

活动洞察使用 Codex 个人统计中的原始聚合字段：

| 字段 | 统计口径 |
| --- | --- |
| 快速模式 | 官方返回的快速模式使用百分比 |
| 最常用的推理强度 | 官方返回的最常用推理强度及其百分比 |
| 已探索的技能 | 官方返回的不同技能数量 |
| 使用的技能总数 | 官方返回的技能使用总次数 |
| 任务总数 | 官方返回的任务总数 |
| 最长任务 | 官方返回的最长单次任务时长 |

常用插件使用 Codex 个人统计中的调用排行，只保留类型明确为插件的项目，按官方返回顺序最多
显示五项；不足五项时不虚构补齐。

采集器只保存额度窗口、重置卡时间、每日 Token、活动洞察、插件排行，以及按模型汇总的
请求数、原始输入、新增输入、缓存命中、缓存写入、输出、推理输出、长上下文请求数和 API
成本状态等安全聚合结果。生成的缓存、数据文件和图片不得包含提示词、回复正文、登录信息、
账号标识、设备信息或本机绝对路径。

## 5. 刷新合同

- 刷新周期为 5 分钟；
- 新数据和新画面全部生成成功后才替换最后一次成功结果；
- 刷新失败时继续提供最后一次成功结果；
- 服务端重启后继续提供重启前最后一次成功结果；
- AP01 请求失败时继续显示设备内最后一次成功画面。

## 6. 版本维护
