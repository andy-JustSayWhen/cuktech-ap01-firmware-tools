## 2. 页面与资源事实

- 原厂一级页面为时钟、功率、天气、日历、设置和虚拟形象；
- 原厂窗口管理支持添加窗口、读取窗口数和按序号切换窗口；
- 原厂设置保存于 `/data/sysconfig.bin`；
- 原厂设置字段中没有一级页面显隐配置；
- 固件页面画布为 320×240；
- 固件包含 PNG（静态图片格式）和 GIF（动图格式）解析能力；
- 当前参考项目完成真机验证的实时画面是 GIF89a、320×240、至少两帧、最大 256KB；
- 256KB 是当前第三方实时加载功能的限制，不是原厂图片解析器的全局限制。

## 3. 当前复用的设备通信路径

参考项目已经验证以下路径：

1. 通过米家二维码登录取得用户授权；
2. 从小米云设备列表识别型号为 `njcuk.enstor.ap01` 的设备；
3. 通过小米云取得设备版本、在线状态和局域网地址；
4. 通过米家设备通信检查局域网可达性；
5. 上传已经校验的固件文件；
6. 通过小米云在线更新指令让设备下载或安装；
7. 优化固件通过局域网画面服务取得实时画面。

原厂 `1.0.2_0031` 固件中没有第三方局域网画面服务；该能力由优化固件加入。

## 4. Codex 数据实现边界

- 服务端从当前用户已经登录的 Codex 环境读取 Brief 中要求的数据；
- 本地任务记录只用于计算汇总值；
- AP01 只取得最终显示数据或最终画面；
- AP01 不取得 Codex 登录信息、米家登录信息和本地任务原文；
- 上游没有提供、且无法从本地记录准确计算的字段不生成数值。

具体数据接口、字段换算和价格来源在对应功能开发前补充，并以自动测试固定。

### 4.1 看板数值显示合同

本节是 AGENTS 看板数值显示规则的唯一原文，其他文档只引用本节。

所有看板数据最终显示为整数，显示字符串不得包含小数点。计数保持整数；百分比、金额和
原始数据中的小数值按四舍五入得到显示整数。

Token 消耗按原始整数自动选择单位：

| 原始值范围 | 数值部分 | 单位部分 | 最大常规显示 |
| --- | --- | --- | --- |
| 小于 1 万 | 原始整数，千位使用分隔符 | `Token` | `9,999 Token` |
| 1 万至小于 1 亿 | 除以 1 万后四舍五入 | `万 Token` | `9,999 万 Token` |
| 1 亿至小于 1,000 亿 | 除以 1 亿后四舍五入 | `亿 Token` | `1,000 亿 Token` |

四舍五入结果达到下一单位门槛时，必须改用下一单位重新格式化，不能显示五位数值。数值与
单位使用两个独立位置；数值位置按最多四位数字预留并对齐，千位分隔符不计入数字位数。

示例：

| 原始数据 | 显示结果 |
| ---: | --- |
| `5,353` | `5,353 Token` |
| `9,000` | `9,000 Token` |
| `164,000` | `16 万 Token` |
| `1,557,279` | `156 万 Token` |
| `1,388,000` | `139 万 Token` |
| `500,000,000` | `5 亿 Token` |
| `1,000,000,000` | `10 亿 Token` |
| `2,000,000,000` | `20 亿 Token` |
| `18,280,000,000` | `183 亿 Token` |

圆环只用于有明确总量且能换算为百分比的数据。概览页只有本周剩余额度使用圆环；今日消耗
和近 30 天消耗是绝对 Token 数值，只使用普通数值和单位。

### 4.2 看板字段口径

本周剩余额度使用当前 Codex 账号一周额度窗口的已用百分比换算，显示值为
`100 - 已用百分比`；下次重置使用同一额度窗口的重置时间。上游没有返回重置卡数量和
重置卡明细时，这些位置显示“无法获取”，不能把额度窗口、账户积分或空数组当作重置卡。

今日消耗只汇总北京时间当日的本地会话增量：

- 总消耗等于输入与输出 Token 之和；
- 输入、输出和缓存命中分别取同名累计计数的相邻非负增量；
- 请求数等于当日产生正 Token 增量的模型请求次数；
- 缓存命中率等于缓存命中除以输入，按第 4.1 节显示整数百分比；输入为零时显示 `0%`；
- 上游没有提供可核验价格时，总成本显示“无法获取”，不能按未知模型价格推算。

近 30 天累计消耗和近 7 天曲线优先使用官方每日用量。官方数据只统计到较早日期时，在
官方统计截止日之后追加本地会话增量；同一个自然日不能同时加入官方值和本地值。

近 30 天活动洞察使用以下固定口径：

| 字段 | 统计口径 |
| --- | --- |
| 快速模式 | 明确记录为快速服务档位的设置次数，占全部明确服务档位设置次数的整数百分比 |
| 最常用的推理强度 | 任务上下文中出现次数最多的推理强度，以及它占全部已记录推理强度的整数百分比 |
| 已探索的技能 | 30 天内明确读取过说明文件的不同技能数量 |
| 使用的技能总数 | 30 天内技能说明文件的读取总次数 |
| 任务总数 | 30 天内出现过记录的不同本地任务数量 |
| 最长任务 | 单个任务在 30 天窗口内第一条与最后一条记录之间的最长时长 |

常用插件按本地记录中可明确识别的插件包或工具服务分组，按调用次数从高到低最多显示五项。
没有明确来源的通用命令不计入插件；不足五项时不虚构补齐。

本地统计只读取时间、累计 Token、服务档位、推理强度、技能说明文件路径、工具名称和任务
内部标识。生成的数据文件和图片不得包含提示词、回复正文、登录信息、设备信息或本机绝对
路径。

## 5. 刷新合同

- 刷新周期为 5 分钟；
- 新数据和新画面全部生成成功后才替换最后一次成功结果；
- 刷新失败时继续提供最后一次成功结果；
- 服务端重启后继续提供重启前最后一次成功结果；
- AP01 请求失败时继续显示设备内最后一次成功画面。

## 6. 版本维护

- 本文只记录已经进入实现或已经取得直接证据的技术合同；
- 开发需求变化先修改 `brief.md`；
- 交互与视觉变化写入独立 Design（交互与视觉设计文档）；
- 操作步骤和故障停止条件写入 `SOP/`；
- 固件证据变化先更新 `knowledge/`，再同步本文。
