## 查询和下载官方固件

### SPEC-SOURCE-001 官方原始固件获取

官方原始固件必须从本项目命令查询和下载。没有可用登录态时，本项目必须生成项目内二维码，由执行任务的 AI 展示给用户；用户用拥有目标 AP01 的米家账号扫码确认后，本项目自动取得登录态、确认账号内存在 AP01，并保存到项目内的忽略文件。用户不得手工提取或填写登录令牌，流程不得读取项目目录外的凭据文件或米家应用数据。

查询命令只读取小米云当前 AP01 官方固件信息，不打印下载地址、登录凭据或用户设备信息。下载命令必须使用云端本次返回的版本生成文件名，以云端本次返回的 MD5 核对下载内容，并记录实际文件字节数和 SHA-256；不得把版本、MD5、SHA-256 或文件字节数固定为某个历史版本。下载内容与云端 MD5 不一致时必须停止，已保存的官方原始固件必须保持只读。

动态下载的新版本只是官方原件。它通过下载核对不代表已经成为固件制作基线；只有另行完成结构分析并更新固定基线文档和代码后，才能用于制作或刷入。

## 刷机安装

### SPEC-INSTALL-001 按来源执行安装和验收

README 表格标为“官方”的固件，或用户明确说明来自官方的固件，在目标账号仅有一台空闲 AP01 时直接执行官方刷机流程。README 表格标为“第三方”的固件，或用户明确说明来自第三方的固件，只能在找到对应专用刷机流程后执行。两类安装都必须记录设备接受安装、下载或安装阶段、重启、重新上线、空闲状态和用户屏幕验收；任一环节失败时停止重复下发。

## 跨固件制作环境

### SPEC-TOOLS-001 同一套制作工具

Windows 与 macOS 使用项目提供的同一个 Docker 镜像制作固件。镜像必须包含依赖清单固定的 Gifsicle、FFmpeg、RISC-V GCC、RISC-V Binutils、Python、Pillow 和 Requests；不得根据宿主系统改用其他版本。

### SPEC-TOOLS-002 一条入口命令

项目必须分别提供 Windows 与 macOS 可直接调用的入口。入口负责制作或复用镜像、挂载当前项目、转交用户命令，不要求用户逐项安装镜像内工具。

### SPEC-TOOLS-003 启动检查

镜像制作完成后必须运行版本检查。任一固定工具缺失或版本不匹配时，镜像制作失败，不得用于固件制作。

### SPEC-TOOLS-004 文件归属

源代码、输入固件、配置和构建输出保存在宿主项目目录；镜像只提供运行环境。用户退出后不依赖容器内临时文件保存构建结果。

## 跨固件服务部署

### SPEC-TOOLS-006 看板服务一键部署

1. 刷机流程只要求在执行刷机的当前电脑部署看板服务；已写入地址表的其他电脑可在需要时自行部署，不作为刷机成功的条件。
2. 项目必须提供 Windows 与 macOS 的一键部署程序。程序把运行所需代码、字体、输出目录和缓存目录写入仓库外的独立部署目录，注册当前用户登录后自动启动，并立即执行本机健康检查。
3. 一键部署程序不得复制 Codex 登录状态、固件地址、设备信息或仓库临时结果；部署后服务的工作目录不得指向项目仓库。
4. 使用方式、默认目录、前提、完成检查和故障处理只在 `SOP/如何部署服务端.md` 规定；刷机 SOP 与优化固件专用流程只声明并链接该文档。
