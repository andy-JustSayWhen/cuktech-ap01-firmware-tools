## 1. 用户目标

AP01 用户可以查看今天的 Codex 总消耗、请求数量、成本以及输入、输出和缓存命中。

## 2. 前端入口与显示

- 用户在 AGENTS 详情区域切换到“今日消耗详情”时显示本 Feature；
- 页面只显示：
  - 总消耗 Token；
  - 请求数；
  - 总成本；
  - 输入；
  - 输出；
  - 缓存命中；
- 页面不显示 Brief 没有要求的模型排行、账户名称或其他提供商数据；
- 总消耗使用完整数值或经 design 统一确定的紧凑显示，不得改变实际含义。

## 3. 用户操作与结果

- 用户向右旋转时，由应用入口显示“查看近 30 天消耗详情”；
- 用户向左旋转时，由应用入口显示“查看周剩余额度详情”；
- 用户按下并松开旋钮时，由应用入口返回 AGENTS 看板概览；
- 本 Feature 不直接控制其他详情页。

## 4. 服务端与设备端表现

- 六个字段来自同一个公共今日消耗结果；
- 输入、输出和缓存命中不得使用互相不一致的统计窗口；
- 总成本没有准确来源时显示“无法获取”，不得自行推算价格；
- 服务端生成完整页面后才替换最后一次成功页面；
- 刷新失败时继续显示最后一次成功页面；
- 设备端只取得汇总结果或最终画面，不取得任务原文。

## 5. 独立状态与公开结果

本 Feature 独立拥有当前今日消耗详情画面和最后一次成功画面。公开输入是公共今日消耗数据
结果，公开结果是一份完整的今日消耗详情画面及其是否可用。

## 6. 公共能力依赖

- 今日消耗公共数据读取与统一能力；
- Token、次数和成本格式能力；
- 画面合成与格式校验能力；
- 最后成功结果保存能力；
- 应用入口导航能力。

## 7. 禁止依赖

- 不调用概览、周额度或近 30 天消耗 Feature；
- 不读取其他 Feature 的内部状态；
- 不自行定义与概览不同的“今日”统计范围；
- 不根据参考图增加“创建”等 Brief 未点名字段；
- 不把无法取得的成本显示为零。

## 8. 异常表现

| 场景 | 用户可见结果 |
| --- | --- |
| 单个统计字段无法取得 | 对应字段显示“无法获取” |
| 总成本没有准确来源 | 总成本显示“无法获取” |
| 本轮刷新失败 | 保留最后一次成功页面 |
| 尚无成功结果 | 完整显示字段名称，值为“无法获取” |

## 9. 静态验收

- 页面只出现 Brief 指定的六类数据；
- 六类数据使用统一统计窗口；
- 缺失值不伪造成零；
- 不包含任务原文或本机路径；
- 刷新失败不清空最后成功结果；
- 没有对其他 Feature 的直接调用。

## 10. 真机验收

1. 进入本页面，核对六类数据与服务端同一时刻结果一致；
2. 验证大数值在 320×240 画面中完整可读；
3. 让成本或其他单字段无法取得，确认只影响对应字段；
4. 中断刷新，确认保留最后成功页面；
5. 左右旋转和按压，确认应用入口按公共导航合同组合页面。
