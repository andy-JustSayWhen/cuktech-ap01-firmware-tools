## 1. 用户目标

AP01 用户可以在一个一级页面中快速查看 Codex 本周剩余额度、今日消耗、近 30 天消耗和
近 7 天消耗趋势。

## 2. 前端入口与显示

- 一级页面名称为“AGENTS 看板”；
- 该页面作为独立一级页面参与设备一级页面轮换；
- 页面固定包含三个信息区块：
  - 圆环：本周剩余额度；
  - 卡片：今日消耗和近 30 天消耗；
  - 曲线：近 7 天消耗；
- 画布为 320×240；
- 视觉底图与实时数据文字合成后的最终画面才发送给 AP01；
- 不显示 Brief 没有点名的账户、模型、任务或统计字段。

## 3. 用户操作与结果

1. 用户在一级页面轮换中进入“AGENTS 看板”；
2. 用户无需再次操作即可看到最近一次成功生成的完整概览；
3. 数据成功刷新后，下一份完整画面替换上一份成功画面；
4. 用户按下并松开旋钮时，由应用入口进入周剩余额度详情；
5. 页面处于熄屏状态时，首次旋钮操作只执行原厂唤醒，不误进入详情。

## 4. 服务端与设备端表现

- 服务端使用公共数据结果生成完整概览画面；
- AP01 按公共刷新合同取得最终画面；
- AP01 只在新画面完整取得并确认可用后替换当前画面；
- 请求或刷新失败时继续显示最后一次成功画面；
- 没有任何成功画面时，完整显示三个区块，并把无法取得的值显示为“无法获取”；
- 设备端不取得 Codex 登录信息、本地任务原文或本机路径。

## 5. 独立状态与公开结果

本 Feature 独立拥有：

- 当前概览显示画面；
- 当前概览画面对应的数据生成时间；
- 当前是否存在成功画面。

公开输入是公共 Codex 数据结果。公开结果是一份完整的 320×240 概览画面及其是否可用。

## 6. 公共能力依赖

- Codex 公共数据读取与字段统一能力；
- 画面合成与格式校验能力；
- 最后成功结果保存能力；
- AP01 获取画面能力；
- 一级页面承载和应用入口导航能力。

## 7. 禁止依赖

- 不调用三个详情 Feature；
- 不读取详情 Feature 的内部画面或状态；
- 不自行计算与详情不同的同名数据；
- 不负责选择下一个详情 Feature；
- 不因参考图出现额外字段而扩充页面。

## 8. 异常表现

| 场景 | 用户可见结果 |
| --- | --- |
| 单个字段无法取得 | 对应位置显示“无法获取”，其他区块正常显示 |
| 本轮刷新失败 | 继续显示最后一次成功概览 |
| 服务端不可达 | 设备继续显示最后一次成功概览 |
| 设备没有成功画面 | 显示完整结构，缺失值显示“无法获取” |
| 画面格式或尺寸不合格 | 不替换当前成功画面 |

设备屏幕不显示网络错误、程序异常、登录信息或本机路径。

## 9. 静态验收

- 页面名称准确；
- 只包含圆环、两个卡片和近 7 天曲线；
- 同名数据来自公共数据结果；
- 画面尺寸固定为 320×240；
- 缺失字段使用“无法获取”；
- 刷新失败不会清空最后成功画面；
- 没有对详情 Feature 的直接调用。

## 10. 真机验收

1. 通过旋钮进入 AGENTS 看板一级页面；
2. 核对四类摘要与服务端同一时刻的公共数据结果一致；
3. 等待一次成功刷新，确认完整画面更新；
4. 中断服务端，确认设备继续显示最后成功画面且屏幕不报错；
5. 恢复服务端，确认后续完整画面可以更新；
6. 熄屏后操作旋钮，确认首次操作只唤醒；
7. 按下并松开旋钮，确认进入周剩余额度详情；
8. 验证原厂其他一级页面继续正常工作。
