## 1. 用户目标

AP01 用户可以在系统设置中选择是否让时钟、功率、天气、日历和虚拟形象五个原厂一级页面
参与一级页面轮换，以减少不需要的页面。

Brief 使用“日历、天气、萌宠等原厂一级页面”描述范围；结合当前官方固件已经确认的原厂
一级页面，本 Feature 管理除设置以外的五个原厂一级页面。设置页面必须保留，AGENTS 看板
不是原厂页面，不属于本 Feature 的复选范围。

## 2. 前端入口与显示

- 系统设置菜单新增“开关一级页面”设置项；
- 进入后显示“时钟”“功率”“天气”“日历”“虚拟形象”五个复选项；
- 每个复选项必须同时显示页面名称和当前是否参与一级页面轮换；
- 默认五个复选项全部开启，首次安装后保持原厂页面可见；
- 用户完成复选操作后，界面必须显示保存后的状态；
- 本 Feature 不显示固件地址、内部页面序号或配置文件路径。

## 3. 用户操作与结果

1. 用户进入“开关一级页面”；
2. 用户选择一个页面并切换复选状态；
3. 设置立即成为后续一级页面轮换规则；
4. 用户离开设置页后，旋转一级页面时只经过开启的候选页面；
5. 被关闭的页面不再出现在一级页面轮换中；
6. 重新开启后，该页面恢复参与轮换；
7. 设备重启后继续使用最后一次成功保存的复选状态。

设置页面本身始终可以进入，不能被本 Feature 隐藏。

## 4. 设备端表现

- 设备保存五个候选页面各自的开启或关闭状态；
- 保存必须整体成功后才替换最后一次成功配置；
- 页面轮换读取同一份成功配置；
- 关闭页面只影响一级页面轮换，不删除原厂页面资源；
- 本 Feature 失败时不得破坏时钟、功率、设置、AGENTS 看板及原厂基础功能；
- 配置读取失败时使用五个候选页面全部开启的安全默认值；
- 配置保存失败时继续使用最后一次成功配置，并在设置界面恢复显示实际生效状态。

## 5. 独立状态与公开结果

本 Feature 独立拥有：

- 时钟是否参与轮换；
- 功率是否参与轮换；
- 天气是否参与轮换；
- 日历是否参与轮换；
- 虚拟形象是否参与轮换；
- 最近一次成功保存结果。

公开输入是用户提交的五个复选状态。公开结果是完整的页面显隐配置和保存是否成功。

## 6. 公共能力依赖

- 原厂系统设置页面承载能力；
- 旋钮输入和复选控件能力；
- 设置持久化能力；
- 一级页面列表组合能力。

这些能力不包含“开关原厂一级页面”的业务规则，不建立为本 Feature 的子功能。

## 7. 禁止依赖

- 不调用 AGENTS 看板的任何 Feature；
- 不调用“循环选择设置项”Feature；
- 不读取其他 Feature 的内部状态；
- 不把关闭页面实现为删除资源、覆盖页面或破坏原厂页面创建逻辑；
- 不把设置或 AGENTS 看板加入原厂页面复选范围。

## 8. 异常表现

| 场景 | 用户可见结果 |
| --- | --- |
| 配置首次读取失败 | 五个候选页面均显示为开启 |
| 单次保存失败 | 保留上次成功状态，不显示未生效的选择 |
| 某候选页面资源异常 | 不允许因此隐藏或破坏其他一级页面 |
| 设备重启 | 恢复最后一次成功配置 |

## 9. 静态验收

- 设置菜单存在且名称为“开关一级页面”；
- 只出现时钟、功率、天气、日历、虚拟形象五个复选项；
- 默认状态为五个复选项全部开启；
- 保存结构包含五个独立状态；
- 页面轮换逻辑只跳过被关闭的候选页面；
- 配置失败路径会回到最后成功配置或安全默认值；
- 没有对其他 Feature 的直接调用。

## 10. 真机验收

1. 首次安装后确认五个原厂候选页面均参与轮换；
2. 分别关闭五个候选页面，确认每次只影响对应页面；
3. 同时关闭五个候选页面，确认设置和 AGENTS 看板仍可正常轮换；
4. 分别重新开启五个页面，确认恢复正常；
5. 重启设备，确认复选状态保持；
6. 验证原厂页面内容、米家通信和官方更新能力没有异常。

完成上述真机证据前，验证状态保持“未实现”或按实际证据更新，不得直接写成真机通过。
