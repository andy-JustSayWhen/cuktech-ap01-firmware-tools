## 跨固件需求

### BRIEF-SOURCE-001 查询和下载官方固件

用户能查询当前官方 AP01 固件；需要下载时，项目自动使用当前账号的登录态或扫码登录，核对下载文件后保存为只读原件。查询或下载官方原件不等同于把它确认为可制作或可刷入的基座。

### BRIEF-TOOLS-001 固件制作工具随项目提供

Windows 与 macOS 用户安装 Docker 后，应能使用项目固定的同一套固件制作工具，不需要分别寻找、安装或升级 Gifsicle、FFmpeg、RISC-V GCC、RISC-V Binutils 和 Python 程序库。项目应提供统一入口，检查工具版本后才允许执行制作命令。

### BRIEF-TOOLS-003 看板服务独立部署

刷入优化固件时，只部署执行刷机的当前电脑。其他已写入固件地址表的电脑不属于本次刷机的必做步骤；项目分别提供 Windows 与 macOS 的一键部署程序，用户在需要提供备用服务的那台电脑上执行即可。

### BRIEF-INSTALL-001 官方固件直接安装

README 表格标为“官方”的固件，或用户明确说明来自官方的固件，都直接向设备下发安装；不限定具体版本或文件名，也不进行本机临时服务回读。设备仍从本机临时服务下载固件，安装、重启和屏幕验收必须保留。

### BRIEF-INSTALL-002 第三方固件按专用流程安装

README 表格标为“第三方”的固件，或用户明确说明来自第三方的固件，只能在存在对应专用刷机流程时安装。安装前必须完成该流程规定的文件核对、服务检查和设备状态检查；安装、重启、重新上线和屏幕验收必须保留。
