# AP01 固件制作规范

## 1. 文档地位

本文是本项目制作、修改、校验、安装、回退和发布 AP01 固件时必须持续维护的总门禁。
具体产品表现由 SPEC 系列文档规定，具体实现由 DESIGN 系列文档规定，实际操作步骤见
[`SOP/AP01-固件制作与刷机.md`](SOP/AP01-固件制作与刷机.md) 和
[`SOP/AP01-分级恢复与救砖.md`](SOP/AP01-分级恢复与救砖.md)。

本文是安全规则唯一原文。`brief.md` 中约定的
[`firmware-safety.md`](firmware-safety.md) 只作为兼容入口指向本文，不另行定义规则。

固件身份、结构和校验术语的原文见
[`AP01 固件身份、结构与校验`](../knowledge/AP01-官方固件分析/固件身份、结构与校验.md)，

## 2. 安全结论

“优化固件可以安装”和“设备变砖后可以恢复”是两项不同结论。

当前证据只证明：

1. 官方 `1.0.2_0031` 固件身份、容器结构和文件尾恢复校验已经静态复核；
2. 参考项目曾在同型号、同版本设备上完成第三方固件在线安装；
3. 固件中存在双槽、更新和恢复代码；
4. 原厂 `BFNP` 文件是应用更新包，不是已经证明可整片写回的全闪存备份；
5. 本项目尚未完成指定设备从优化固件回刷原厂固件的真机验证；
6. 尚无已经验证的厂家恢复模式、外露刷机接口或拆机硬件恢复通道。

因此，在补齐第 5、6 项之前：

- 不得承诺“绝不变砖”；
- 不得把云端原厂固件安装路径描述成离线救砖能力；
- 不得向日常使用设备安装实验固件；
- 可以继续静态分析、离线制作和自动测试；
- 实验成品的真机仅下载和正式安装都必须停止。

首次实验安装只有在至少一种不依赖优化固件正常启动、联网和米家通信的恢复通道已经实测
通过后才允许进行。原厂固件在线回刷还必须在同一台测试设备上完成全流程实测，才能作为
发布回退方案。

“仅下载”不是只读操作。AP01 实际写入目标槽尚未证明，不能排除实验成品覆盖原有回退槽。
因此，只有匹配原厂包可用于恢复基线验证；实验成品仅下载必须排在独立恢复演练之后。

## 4. 原厂基线门禁

开始制作前必须取得并固定一份未经修改的原厂固件。当前唯一允许进入分析阶段的基线为：

| 项目 | 固定值 |
| --- | --- |
| 设备型号 | `njcuk.enstor.ap01` |
| 固件版本 | `1.0.2_0031` |
| 文件字节数 | 6,804,520 |
| MD5 | `469a7329d496f81ae8625c4d76ccf56d` |
| SHA-256 | `8a721fc8ef25458d415b2460e4a251e0503a82f7743fdff85b12612190e5c1cb` |
| 文件头 | `BFNP` |
| 文件尾恢复校验值 | `0x7ffd605b` |

执行规则：

1. 每次制作前重新查询小米云当前版本；
2. 版本、字节数或文件指纹任一不一致，立即停止并重新分析；
3. 原厂文件只保存在仓库忽略目录或仓库外受控目录；
4. 原厂文件、优化固件、提取资源和带设备配置的成品不得提交；
5. 构建工具只读原厂文件，不允许原地修改；
6. 独立功能阶段每次从原厂基线重新开始；组合成品可以从已经真机验收并由 DESIGN 固定完整
   文件指纹的阶段成品开始，但必须同时复核原厂基线、阶段成品身份和两者间全部批准差异。

### 4.1 已验收阶段成品门禁

阶段成品只有同时满足以下条件，才能成为组合成品的制作输入：

1. 对应功能已经完成真机验收；
2. DESIGN 已固定文件名、字节数、两个完整文件指纹和文件尾恢复校验值；
3. 构建器逐字节比较原厂基线与阶段成品；
4. 所有差异只落在原批准修改区间和文件尾恢复校验值；
5. 阶段成品以只读方式打开，不允许原地修改；
6. 任一后续修改仍需单独具备地址、原字节、替换字节和边界证据。

### 4.2 原厂应用更新包的恢复边界

匹配的原厂 `BFNP` 文件必须为 R0 回刷准备，但不得称为“完整救砖包”。在 AP01 真实闪存
容量、分区图和读取通道没有确认前：

1. 不得把该文件写到物理地址零；
2. 不得用该文件执行整片写入或整片擦除；
3. 不得声称它能重建第二阶段启动程序、分区表、校准区或设备专属数据；
4. 不得用其他设备的全闪存备份替代当前设备自己的备份。

全闪存备份必须由同一测试设备经已确认的只读通道取得两次一致结果，并保存在仓库外两个
独立位置。两次读取一致仍不能替代恢复写入和重新启动演练。

## 5. 修改门禁

### 5.1 每一处修改都要有证据

每个修改区间必须记录：

- 对应目标功能；
- 文件偏移和长度；
- 修改前预期字节；
- 修改后字节的来源；
- 对应运行地址；
- 所属程序、资源或数据区域；
- 边界和对齐检查；
- 复查方法；
- 失败时的原厂行为。

实际字节与预期字节不一致时，构建必须失败，禁止模糊匹配或继续写入。

### 5.2 默认禁止修改的区域

没有新的明确授权和已经验证的独立恢复通道时，禁止修改：

- 启动引导程序；
- 分区表和恢复记录格式；
- 当前槽与更新槽选择逻辑；
- 无线网络初始化；
- 米家通信；
- 官方在线更新和安装链路；
- 看门狗和启动早期初始化；
- 厂家恢复代码；
- 物理闪存中的第二阶段启动程序、分区表、校准区、设备身份区和密钥区；
- 一次性配置、防降级版本、安全启动配置和调试密码。

文件尾恢复校验值必须按原格式重新计算，但不得改变恢复记录的结构、位置和总文件长度。

整片擦除、使用芯片家族示例地址写入、把应用更新包写到地址零，以及在未知焊盘上试错短接，
均不属于允许的恢复探索方法。

### 5.3 最小变化

1. 每个可测试阶段只引入一个能够独立验收的变化；
2. 优先调用原厂逻辑，不复制原厂已有能力；
3. 自定义逻辑失败时必须返回原厂安全行为；
4. 新功能不得占用未经证明为空闲的程序、堆、栈、资源或持久化空间；
5. 新旧功能共用的数据结构必须有边界检查；
6. 任何未确认的地址、调用约定、文件路径、容量或时序都属于阻塞项，不得用猜测补齐。

### 5.4 启动路径变更门禁

只要修改会在用户界面创建期间执行，即使功能位于设置页，也按启动路径变更处理。

1. 修改原厂创建循环数量前，必须证明循环依赖的指针表、局部数组、对象数量、状态编号和
   后续遍历都能容纳新增项目；
2. 复用原厂创建入口前，必须证明每个参数的实际类型和间接层级，不能只根据寄存器位置推断；
3. 上述任一边界没有直接证据时，不得增加原厂创建循环次数，应改用界面完成启动后再创建的
   独立覆盖页；
4. 首次真机必须拆成“原路径空挂接”和“单一新增行为”两个成品，前一个成品确认能够进入
   一级页面后，才允许安装后一个成品；
5. 自动测试、修改区间一致和文件尾校验不能替代启动验收；安装后必须在限定时间内证明已经
   离开开机动画并进入一级页面；
6. 卡在开机动画时立即停止继续叠加修改，优先通过仍可用的更新通道回刷上一份已验收成品；
7. 发生启动回归的成品必须在固件清单和当前门禁中标为禁止安装，根因得到直接证据且新成品
   重新完成分阶段验收前不得解除；
8. 在一级窗口中插入新对象时，必须保持原厂内部对象的既有序号，或逐一证明所有读取该序号
   的原厂路径已经同步调整；真机回归必须覆盖每个原厂详情页的进入和返回、每个一级页面的
   确认操作，以及所有菜单“返回”操作；任一确认操作误入其他流程或触发重启时立即禁止该
   成品再次安装。

## 6. 构建产物与记录

每次构建必须生成独立成品和一份不可后补的构建清单。构建清单至少记录：

- 构建时间和工具版本；
- 工具代码版本；
- 原厂输入文件的两个文件指纹；
- 成品文件名、字节数和两个文件指纹；
- 全部修改区间；
- 载荷、资源和持久化数据的大小；
- 文件头、型号、版本、文件尾长度和恢复校验结果；
- 自动测试结果；
- 修改区间外逐字节一致的结果；
- 是否允许进入仅下载、安装和发布阶段。

成品一旦通过离线验证即设为只读。上传、仅下载校验、正式安装和回退验证必须使用同一份
逐字节相同的文件；中途重新构建后，全部校验从头开始。

## 7. 分阶段门禁

| 阶段 | 进入条件 | 退出证据 |
| --- | --- | --- |
| 静态分析 | 原厂基线全部匹配 | 地址、调用、空间和原厂行为有直接证据 |
| 离线构建 | 修改清单已审批 | 构建清单完整，修改区间外逐字节一致 |
| 自动验证 | 成品已冻结 | 容器、代码、资源、状态和失败路径测试通过 |
| 恢复门禁 | 专用测试设备的原厂 R0 回刷已通过 | 至少一条 R2、R3 或 R4 恢复演练通过 |
| 实验成品仅下载校验 | 恢复门禁已通过，且 AP01 写入目标槽已有直接证据 | 设备下载并校验完成，未切换启动槽 |
| 首次实验安装 | 实验成品仅下载校验已通过 | 安装、重启、重新上线和全部基础能力通过 |
| 原厂回刷验证 | 已保存匹配原厂文件 | 同一设备回刷、重启、上线和原厂能力通过 |
| 发布 | 优化固件安装与原厂回刷均通过 | 发布清单、限制和恢复步骤完整 |

任一阶段的通过结果不能替代后续阶段。

### 7.1 专用测试设备的逐次风险授权

当 AP01 专属接口客观上无法取得时，专用测试设备的单次实验安装允许由用户逐次明确授权跳过
以下恢复类条件：

1. 当前槽、更新槽与实际写入目标证据；
2. 两份逐字节一致的同机全闪存备份；
3. 同机原厂固件回刷验证；
4. 不依赖设备正常启动和联网的独立恢复验证。

跳过只对授权中指定的唯一设备、唯一成品指纹和一次安装动作有效，不得转用于发布、批量安装
或“不变砖、可刷回原厂”的结论。原厂基线、修改前旧字节、修改范围、固件长度、文件头、
型号、文件尾恢复校验、上传对象完整回读、稳定供电和安装后重新上线不得跳过。

资源上限和存储行为允许在上述单次实验中逐步补测；未取得的项目必须在构建清单中保持
“待真机测量”，不得伪造成已验证结果。

## 8. 安装与回退保护

正式安装前必须即时展示并确认：

- 唯一目标设备；
- 当前版本和目标成品；
- 原厂与成品文件指纹；
- 修改范围；
- 已通过的检查；
- 尚存风险；
- 独立恢复通道；
- 原厂回刷材料和命令。

安装期间保持稳定供电、联网和设备身份，不并行下发其他命令。状态未知、短暂离线或超时
时先查询状态，不盲目重复安装。

安装成功必须同时证明：设备接受更新、下载完成、进入安装、发生重启、运行时间重新计数、
重新上线、原厂页面正常、米家通信正常、官方更新能力正常、目标功能通过。

原厂回刷成功必须在同一台设备上证明：官方成品仅下载校验通过、安装完成、设备重启、
重新上线、原厂页面恢复、米家通信正常、官方更新能力正常。

### 8.1 首次安装前的自救能力验证

具体步骤只见
[`SOP/AP01-分级恢复与救砖.md`](SOP/AP01-分级恢复与救砖.md)。门禁至少要求：

1. 使用专用测试设备，不使用日常使用设备；
2. 在原厂状态先完成同机 R0 回刷；
3. 拍摄并记录主板、板号、芯片丝印和测试点；
4. 只通过断电通断测量、正常供电高阻测量和被动波形观察识别接口；
5. 确认真实闪存身份、容量和读取范围；
6. 取得两份逐字节一致的同机全闪存备份；
7. 在应用不能运行的条件下完成至少一条独立恢复通道演练；
8. 恢复后验收设备身份、原厂页面、联网、米家通信和官方更新。

任一项依赖猜测、芯片开发板地址或另一台设备备份时，门禁判定失败。

### 8.2 完整性检查不能替代恢复验证

固定长度、旧字节断言、修改区间外一致、文件尾恢复校验、仅下载校验和冻结同一成品，分别
降低误用、误写、意外改动、容器损坏和成品替换风险。它们不能证明新代码一定能启动、自动
回退一定触发或离线恢复一定可用。各项保护的完整能力边界只见
[`AP01 离线恢复与救砖证据`](../knowledge/AP01-官方固件分析/离线恢复与救砖证据.md)
第 5 节。

## 9. 强制停止条件

出现以下任一情况立即停止后续高风险动作：

- 设备、版本、官方来源或文件指纹不能唯一确认；
- 原厂固件进入版本控制；
- 修改范围超出清单；
- 修改前字节与预期不一致；
- 文件长度、文件头、型号、恢复记录或校验不一致；
- 新功能可能影响启动、联网或更新，且没有第 7.1 节所述的本次逐次风险授权；
- 把原厂应用更新包当作全闪存备份或使用未经确认的物理地址；
- 要求整片擦除、写入一次性配置或套用开发板接线；
- 拆机后无法确认地线、信号电平、主控、闪存容量或读取范围；
- 两次全闪存读取不一致；

- 安装后未在限定时间内离开开机动画，或联网服务仍工作但用户界面没有完成启动；
- 要求跳过第 7.1 节明确保留的不可跳过检查。

## 10. 持续维护触发条件

- 官方固件版本或结构变化；
- 新增修改区间、载荷区、资源区或持久化数据；
- 制作、上传、安装或回退工具变化；
- 新增或失效恢复通道；
- AP01 主板、接口、闪存、分区或一次性配置取得新证据；
- 芯片厂商工具、文档或固定证据版本变化；
- 真机安装、失败或回退取得新证据；
- 安全门禁、停止条件或发布范围变化。
